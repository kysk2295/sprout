## 2. 언제 보이나 — **결정: A안** (2026-10-04)
- **A안 [틱틱]**: 로그아웃 상태면 앱을 열자마자 로그인 화면이 창 전체를 덮는다. 로그인해야 쓸 수 있다.
- **B안 [sprout]**: 로그인 없이도 로컬로 다 쓸 수 있고(로컬 퍼스트), 레일 아래 아바타·설정의 계정 화면·동기화 버튼에서 로그인을 연다. 로그인하면 이 기기 데이터가 계정으로 올라간다.
- 두 안 모두 로그인 화면 자체(§3~§5)는 같다.
- A안 세부: 첫 실행(로그아웃)에도 로컬 첫 실행 데이터(기본함·예시)는 만들어 두고, **새로 가입하면 그 데이터가 새 계정의 시작 데이터로 올라간다**. 기존 계정으로 로그인하면 지우고 서버 데이터를 내려받는다. 웹 미리보기(`npm run web`)에는 서버가 없어 로그인 화면을 띄우지 않는다.

### 3.1 구글·애플로 계속하기 — **v1.1 초안** (2026-10-06) [틱틱 배치 / 계정 규칙은 sprout]
**배치 [틱틱 웹]:** 주 버튼 아래 구분선(1px, 위 6) → **"Google로 계속하기"** → **"Apple로 계속하기"**(카드 폭 290, 높이 38, 모서리 10, 테두리 `color.login.input-border`, 바탕 카드색, 글자 14 500, 간격 14). 로그인·가입 화면 둘 다 같은 버튼(소셜은 가입과 로그인이 한 흐름). 가입 화면은 그 아래 약관 문구.
- 표시 [각 회사 지침]: 구글 = 4색 "G" 원본 모양 18px(색·모양 바꾸지 않음, 구글 로그인 브랜딩 지침), 애플 = 애플 로고 18px 글자색 단색(Sign in with Apple HIG — 흰 테두리/검정 스타일, 문구 "Apple로 계속하기"). 두 버튼은 같은 크기·같은 무게. 틱틱 로고·그림은 쓰지 않는다.
- 문구: 틱틱 웹은 "Apple로 계속하세요"지만 애플 지침의 한국어 문구 **"Apple로 계속하기"**를 쓴다 [sprout].

**흐름 [sprout — 보안 설계]**
- **구글**: 메인 프로세스가 시스템 브라우저로 구글 동의 화면을 연다(앱 안 웹뷰 금지 — 구글이 막는다). 설치형 앱 흐름 + **PKCE(S256)** + 루프백 `http://127.0.0.1:<임의 포트>/auth/google` + `state` + `nonce`, 범위 `openid email profile`만. 받은 코드를 구글에서 ID 토큰으로 바꿔 **sprout API `POST /auth/google {id_token, nonce}`** 로 보낸다. 서버가 구글 공개키로 서명·발급자·aud(우리 클라이언트 id)·만료·`email_verified`·nonce를 확인하고 이메일 로그인과 같은 토큰을 준다. 클라이언트 id는 캘린더 연동(16)과 같은 것(`GOOGLE_CLIENT_ID`)이지만 **로그인과 캘린더 권한은 따로 묻는다**(로그인만 하는 사람에게 일정 권한을 묻지 않는다).
- **애플**: 웹 흐름(`response_type=code id_token`, `response_mode=form_post`, 범위 `name email`). form_post는 https 주소가 필요해서 돌아오는 주소 = **API `https://macmini.tail425c97.ts.net/auth/apple/callback`**. API는 받은 토큰을 **state별로 메모리에 5분·한 번만** 맡기고, 브라우저에는 "sprout로 돌아가 주세요" 페이지 + `sprout://auth/apple?state=…`(토큰 없음)로 앱을 깨운다. 앱은 `POST /auth/apple {state, nonce}`로 가져간다(딥 링크가 오면 바로, 아니면 2초마다 — 개발 실행처럼 `sprout://`가 등록 안 돼도 끝난다). 애플에는 **nonce의 SHA-256만** 보내므로, 원래 nonce를 가진 이 앱만 교환할 수 있다(state가 새어도 소용없음). 서버에 `.p8` 키가 있으면 인가 코드를 애플에 한 번 더 확인한다.
- 토큰·코드는 화면(렌더러)에 넘기지 않는다. 구글·애플 토큰은 저장하지 않는다(로그인에 한 번 쓰고 버림). 이후는 sprout 리프레시 토큰(§8)만.

**계정 규칙 [sprout]** (서버 전용 표 `user_identities(provider, subject → user_id, email)`)
1. 같은 (공급자, subject)로 로그인한 적이 있으면 → 그 계정(이메일이 바뀌어도 같은 계정).
2. 처음이면, 공급자가 **확인한(email_verified) 이메일**과 같은 sprout 계정이 있으면 → **그 계정에 연결**(이메일·비밀번호로 가입했던 사람이 나중에 구글로 들어와도 같은 데이터). 확인 안 된 이메일이면 연결·생성 둘 다 거절.
3. 없으면 새 계정(비밀번호 없음). → 새 계정 = 첫 실행 안내(18).
- **애플 이메일 가리기**(`…@privaterelay.appleid.com`): 그 주소로 새 계정이 된다(실제 이메일 계정과 자동으로 합쳐지지 않음). 합치기는 **§3.1.1 "설정 › 계정 › 로그인 방법"**에서 로그인한 채로 애플을 연결한다.
- 이메일·비밀번호 계정은 나중에 소셜을 더할 수 있다(2번 규칙으로 자동). 소셜로만 가입한 계정에 비밀번호를 더하는 것은 비밀번호 재설정 메일이 생기면 [다음].
- 틱틱은 계정을 합치지 않는다(research 27) — 2번 연결 규칙은 sprout가 정한 것.
- ⚠ **남은 위험 — 공개 출시 전 필수**: 이메일 인증이 아직 없어서, 남이 내 이메일로 **먼저 비밀번호 가입**해 두면 내가 구글로 들어올 때 그 계정에 연결된다(계정 선점). 이메일 인증을 넣을 때 "인증 안 된 비밀번호 계정에 소셜을 연결하면 비밀번호를 지우고 기존 세션을 끊는다"로 바꾼다.

### 3.1.1 로그인 방법 연결 — **v1.3 초안** (2026-10-06) [틱틱 배치 / 규칙은 sprout]
- **왜**: 이메일·비밀번호로 쓰던 계정(예: `qa-ui@sprout.test`)에 **이메일이 다른** 구글 계정을 붙여, 다음부터 "Google로 계속하기"로 **이 계정**에 들어오게 한다. §3.1의 2번 규칙(같은 이메일 자동 연결)으로는 이메일이 다르면 새 계정이 생긴다.
- **틱틱 기준**: 설정 › 계정에 로그인 방법 줄 "Google — Link" · "Apple — Link"(research 27 "Apple ID 연결": 기존 계정에 Apple ID를 연결해 다음부터 Apple로 로그인). 연결 뒤에는 연결된 계정과 해제 버튼.
- **배치**: 설정 › 계정 탭, 아바타·이메일·로그아웃 아래, 계정 삭제(§7.1) 위. 작은 제목 **"로그인 방법"** + 설정 카드(`settings-card`) 한 장, 줄 높이 42(`settings-row`).

| 경우 | 문구 |
|---|---|
| 그 구글 계정이 이미 다른 sprout 계정에 붙어 있음 | "이미 다른 sprout 계정에 연결된 구글 계정이에요"(애플: "…애플 계정이에요") — 빼앗지 않는다. 그 계정에서 먼저 해제해야 한다 |
| 이 계정에 다른 구글 계정이 이미 붙어 있음 | "이미 다른 구글 계정이 연결돼 있어요. 먼저 연결을 해제해 주세요" — 공급자마다 하나(틱틱처럼) |
| 마지막 로그인 방법 해제 | "로그인할 방법이 하나도 남지 않아 연결을 해제할 수 없어요. 다른 로그인 방법을 먼저 연결해 주세요" |
| 로그인 만료(401) | "로그인이 만료됐어요. 다시 로그인한 뒤 시도하세요" |
| 시도 과다(429) | 서버 문구 그대로(§4) |
| 설정 안 됨·토큰 검증 실패·서버 끊김·5분 초과 | §3.1과 같은 문구 |

**흐름·서버 [sprout]**
- 앱: §3.1과 같은 브라우저 흐름(구글 PKCE 루프백 / 애플 form_post + 맡김 칸)으로 ID 토큰을 받되, **로그인하지 않고** 지금 세션의 접근 토큰(Bearer)으로 연결 경로에 보낸다. 로컬 데이터·동기화는 그대로. 로그인 안 한 상태면 브라우저를 열지 않는다.
- `POST /auth/link/google` (Bearer) `{id_token, nonce}` — `/auth/google`과 같은 검증(서명·iss·aud·만료·nonce). 연결에는 `email_verified`를 따지지 않는다(이미 이 계정에 로그인한 사람이 구글 계정 소유를 증명). 이메일이 달라도 된다.
- `POST /auth/link/apple` (Bearer) `{state, nonce}` — `/auth/apple`과 같은 맡김 칸·검증. 아직 안 왔으면 202.
- 규칙: (공급자, subject)가 **다른 계정**에 있으면 409 · **이 계정**에 있으면 200 그대로(`linked:false`) · 이 계정에 같은 공급자의 다른 식별자가 있으면 409 · 아니면 `user_identities`에 넣는다(동시에 남이 먼저 넣으면 409). 응답 `{linked, identities:[{provider, email(가림)}]}`.
- `DELETE /auth/link/google` · `/auth/link/apple` (Bearer) — 사용자 행을 잠근 트랜잭션에서 확인: 비밀번호가 없고 다른 공급자도 없으면 409. 없는 연결을 떼면 200 그대로.
- `GET /auth/me`에 `identities:[{provider, email}]` 추가(이메일은 앞 2자 + `***` + 도메인). 기존 `providers`(문자열 목록)는 계정 삭제 화면용으로 그대로.
- 시도 제한: 소셜 로그인과 같은 IP 칸(15분 30회) + 사용자 칸(같은 한도), 실패(4xx)만 센다.
- 연결 뒤 "Google로 계속하기" → §3.1 1번 규칙(식별자)으로 이 계정. 해제한 뒤에는 그 구글 계정이 1번에 걸리지 않으므로, 확인된 이메일이 다른 계정과 같지 않으면 새 계정이 된다.
- 알려진 한계: 연결은 다시 확인(비밀번호·방금 로그인)을 묻지 않는다(틱틱과 같음). 접근 토큰을 훔친 사람이 자기 구글을 붙일 수 있는 위험 → 이메일 인증을 넣을 때 함께 검토 [다음].

**로그아웃**: §7 그대로(소셜 계정도 같다). 구글·애플 쪽 세션은 건드리지 않는다(브라우저의 구글 로그인은 그대로). 다음 로그인 때 구글은 계정 고르기 화면(`prompt=select_account`)이 떠서 다른 계정을 고를 수 있다.

### 7.1 계정 삭제 — **v1.2 초안** (2026-10-06) [틱틱 위치 / 확인 흐름은 sprout]
- 틱틱 기준: 설정 › 계정 맨 아래 빨간 "Delete Account"([research 24](../ticktick-research/24-mobile-ui.md) §설정, 도움말 FAQ). 데스크톱 틱틱 웹도 같은 자리.
- **레이아웃**: 계정 탭(§7) 로그아웃 버튼 아래 가운데 빨간 글자 버튼 "계정 삭제"(`--color-danger`, 호버 배경). 누르면 **같은 자리에 카드**(설정 카드 배경·모서리, 안쪽 16)로 펼쳐진다 — 대화상자 아님.
- **카드 구성**
  | 요소 | 내용 |
  |---|---|
  | 제목(빨강) | "계정을 삭제할까요?" |
  | 설명 | "모든 할 일·일기·수집함·캐릭터와 성장 기록이 서버와 모든 기기에서 지워져요. **되돌릴 수 없어요.**" |
  | 본인 확인 | 비밀번호가 있는 계정 → "비밀번호" 칸(자동 포커스). 구글·애플로만 가입한 계정 → 버튼 "Google로 방금 다시 로그인"(Apple·"Google 또는 Apple"도 같은 꼴) → 성공하면 "다시 로그인했어요. 10분 안에 삭제하세요." |
  | 확인 단어 | `확인하려면 "삭제"를 입력하세요` 칸(앞뒤 공백 무시, 정확히 "삭제") |
  | 오류 | 카드 안 빨간 한 줄 |
  | 버튼 | 오른쪽 [취소] [계정 삭제](빨강 채움). 확인 단어 + (비밀번호 입력 \| 방금 다시 로그인)일 때만 활성 |
- **상태**: 펼친 직후 "확인하는 중…"(로그인 방법을 서버에 물음) · 진행 중 입력·버튼 잠금 · 취소하면 접히고 입력 지움.
- **오류 문구 [임시]**: 비밀번호 틀림 → "비밀번호가 맞지 않아요" · 재확인 만료 → "보안을 위해 Google로 다시 로그인한 뒤 10분 안에 삭제해 주세요" · 시도 과다 → 서버 문구("계정 삭제 확인 시도가 너무 많아요. N분 뒤…") · 토큰 만료 → "로그인이 만료됐어요. 다시 로그인한 뒤 시도하세요" · 연결 실패 → "서버에 연결할 수 없어요. 잠시 뒤 다시 시도하세요" · 다른 구글 계정으로 다시 로그인 → "로그인을 확인하지 못했어요. 다시 시도하세요. 삭제할 계정과 같은 계정으로 로그인하세요."
- **성공**: 메인 프로세스가 로그아웃과 같은 정리(로컬 DB 비움·틱틱 연결·캘린더 연결·위젯 비움·설정 창 닫기·시드) → 로그인 화면 + 토스트 "계정을 삭제했어요"(2.5초).
- **다시 로그인(소셜)** [sprout 보안 설계]: 버튼이 §3.1과 같은 브라우저 흐름을 연다. 이때 메인 프로세스는 **같은 계정인지만 확인하고 토큰만 바꾼다**(로컬 데이터·동기화 그대로). 다른 계정이면 그 세션을 버리고 실패(다른 구글 계정이 처음이면 빈 sprout 계정이 하나 생길 수 있다 — 알려진 한계). 브라우저 흐름 자체는 §3.1처럼 5분 제한.
- **서버** `DELETE /auth/account` (Bearer, 본문 `{password?}`):
  - 비밀번호 계정 → 비밀번호 확인(틀리면 403 `invalid password`).
  - 구글·애플로만 가입한 계정 → 접근 토큰의 `auth_time`이 **10분 안**이어야 한다(403 `reauth required`). `auth_time`은 비밀번호·구글·애플로 **막 로그인할 때만** 넣고, 리프레시로 받은 토큰에는 없다.
  - 한 트랜잭션으로 `ai_usage` 삭제 + `users` 삭제 → 동기화 테이블 23개·세션·소셜 식별자는 `ON DELETE CASCADE`. PowerSync가 지워진 행을 다른 기기에 내려보내고, 세션이 없어져 다른 기기는 다음 리프레시에서 401 → 로그인 화면(그 기기가 꺼져 있어 삭제를 못 받았다면 로컬 사본은 다음 로그인 때 지워진다 — 지금 401 처리는 로그인 정보만 지움, [다음] 로컬도 비우기). 다른 기기가 남은 접근 토큰(최대 1시간)으로 올리면 외래 키 오류 → 401.
  - 로그에는 "계정 1건 삭제"만(이메일·id 없음).
- 구글·애플 쪽 연결 해제(애플 토큰 폐기)는 [다음] — 지금은 sprout 쪽 식별자만 지운다. 백업(`pg_dump`, 14일 보관)에는 보관 기간 동안 남는다(개인정보 처리방침에 적는다).
- 모바일도 같은 서버 경로를 쓴다 — 설정 › 계정, 소셜 전용 계정의 "Google로 방금 다시 로그인"까지 [20 §9](20-mobile-overview.md)(확정 v1.2, 2026-10-05).

### 8.1 계정을 만들면 기본함도 만든다 [sprout 규칙 — 2026-10-05 사용자 결정 "기본함은 있어야지. 이걸 디폴트로 해줘"]
- **계정을 만드는 모든 길**(이메일 가입 `POST /auth/signup`, 구글·애플 첫 로그인 `POST /auth/google`·`/auth/apple`의 새 계정)은 사용자 행과 기본함 행(`lists`: id `inbox-<userId>`, name "기본함", kind `inbox`, sort_order 0, show_in_smart `all`)을 **한 SQL 문(CTE)**으로 만든다 — 하나만 생기는 일이 없다(`server/api/src/defaultInbox.ts`). 기존 계정에 구글·애플을 연결할 때는 만들지 않는다.
- 로그인·리프레시로 토큰을 줄 때마다 기본함이 하나도 없으면 같은 id로 채운다(예전 계정 자가 치유, 이미 있으면 아무것도 안 함). 배포 때 `server/db/migrations/20261009-default-inbox.sql`로 기존 계정을 한 번에 채운다(다시 돌려도 안전).
- 첫 로그인 규칙(§8 표 "첫 로그인")과 맞춤: `has_data`는 **자동 기본함 하나만 있는 계정을 "데이터 없음"**으로 본다(리스트가 그것뿐이고 할 일·노트·일정이 없음). 그래서 로그인 전 쓰던 기기는 그대로 로컬 데이터를 올리고, 올리기 전에 로컬 기본함(무작위 id)을 `inbox-<userId>`로 옮긴다(할 일·섹션의 list_id도 같이) → 기본함은 하나. 휴대폰 새 계정은 처음부터 `inbox-<userId>`로 만든다.
- 앱 안전망과 둘 이상일 때의 규칙은 [02 §14.1](02-task-list.md).
