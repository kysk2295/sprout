## 2. 언제 보이나 — **결정: A안** (2026-10-04)
- **A안 [틱틱]**: 로그아웃 상태면 앱을 열자마자 로그인 화면이 창 전체를 덮는다. 로그인해야 쓸 수 있다.
- **B안 [sprout]**: 로그인 없이도 로컬로 다 쓸 수 있고(로컬 퍼스트), 레일 아래 아바타·설정의 계정 화면·동기화 버튼에서 로그인을 연다. 로그인하면 이 기기 데이터가 계정으로 올라간다.
- 두 안 모두 로그인 화면 자체(§3~§5)는 같다.
- A안 세부: 첫 실행(로그아웃)에도 로컬 첫 실행 데이터(기본함·예시)는 만들어 두고, **새로 가입하면 그 데이터가 새 계정의 시작 데이터로 올라간다**. 기존 계정으로 로그인하면 지우고 서버 데이터를 내려받는다. 웹 미리보기(`npm run web`)에는 서버가 없어 로그인 화면을 띄우지 않는다.

### 3.1 구글·애플로 계속하기 — **v1.1 초안** (2026-10-06) [틱틱 배치 / 계정 규칙은 sprout]
**배치 [틱틱 웹]:** 주 버튼 아래 구분선(1px, 위 6) → **"Google로 계속하기"** → **"Apple로 계속하기"**(카드 폭 290, 높이 38, 모서리 10, 테두리 `color.login.input-border`, 바탕 카드색, 글자 14 500, 간격 14). 로그인·가입 화면 둘 다 같은 버튼(소셜은 가입과 로그인이 한 흐름). 가입 화면은 그 아래 약관 문구.
- 표시 [각 회사 지침]: 구글 = 4색 "G" 원본 모양 18px(색·모양 바꾸지 않음, 구글 로그인 브랜딩 지침), 애플 = 애플 로고 18px 글자색 단색(Sign in with Apple HIG — 흰 테두리/검정 스타일, 문구 "Apple로 계속하기"). 두 버튼은 같은 크기·같은 무게. 틱틱 로고·그림은 쓰지 않는다.
- 문구: 틱틱 웹은 "Apple로 계속하세요"지만 애플 지침의 한국어 문구 **"Apple로 계속하기"**를 쓴다 [sprout].

| 소셜로 가입한 이메일로 이메일 가입 | "이미 가입된 이메일이에요"(§4 그대로) |

**흐름 [sprout — 보안 설계]**
- **구글**: 메인 프로세스가 시스템 브라우저로 구글 동의 화면을 연다(앱 안 웹뷰 금지 — 구글이 막는다). 설치형 앱 흐름 + **PKCE(S256)** + 루프백 `http://127.0.0.1:<임의 포트>/auth/google` + `state` + `nonce`, 범위 `openid email profile`만. 받은 코드를 구글에서 ID 토큰으로 바꿔 **sprout API `POST /auth/google {id_token, nonce}`** 로 보낸다. 서버가 구글 공개키로 서명·발급자·aud(우리 클라이언트 id)·만료·`email_verified`·nonce를 확인하고 이메일 로그인과 같은 토큰을 준다. 클라이언트 id는 캘린더 연동(16)과 같은 것(`GOOGLE_CLIENT_ID`)이지만 **로그인과 캘린더 권한은 따로 묻는다**(로그인만 하는 사람에게 일정 권한을 묻지 않는다).
- **애플**: 웹 흐름(`response_type=code id_token`, `response_mode=form_post`, 범위 `name email`). form_post는 https 주소가 필요해서 돌아오는 주소 = **API `https://macmini.tail425c97.ts.net/auth/apple/callback`**. API는 받은 토큰을 **state별로 메모리에 5분·한 번만** 맡기고, 브라우저에는 "sprout로 돌아가 주세요" 페이지 + `sprout://auth/apple?state=…`(토큰 없음)로 앱을 깨운다. 앱은 `POST /auth/apple {state, nonce}`로 가져간다(딥 링크가 오면 바로, 아니면 2초마다 — 개발 실행처럼 `sprout://`가 등록 안 돼도 끝난다). 애플에는 **nonce의 SHA-256만** 보내므로, 원래 nonce를 가진 이 앱만 교환할 수 있다(state가 새어도 소용없음). 서버에 `.p8` 키가 있으면 인가 코드를 애플에 한 번 더 확인한다.
- 토큰·코드는 화면(렌더러)에 넘기지 않는다. 구글·애플 토큰은 저장하지 않는다(로그인에 한 번 쓰고 버림). 이후는 sprout 리프레시 토큰(§8)만.

**계정 규칙 [sprout]** (서버 전용 표 `user_identities(provider, subject → user_id, email)`)
1. 같은 (공급자, subject)로 로그인한 적이 있으면 → 그 계정(이메일이 바뀌어도 같은 계정).
2. 처음이면, 공급자가 **확인한(email_verified) 이메일**과 같은 sprout 계정이 있으면 → **그 계정에 연결**(이메일·비밀번호로 가입했던 사람이 나중에 구글로 들어와도 같은 데이터). 확인 안 된 이메일이면 연결·생성 둘 다 거절.
3. 없으면 새 계정(비밀번호 없음). → 새 계정 = 첫 실행 안내(18).
- **애플 이메일 가리기**(`…@privaterelay.appleid.com`): 그 주소로 새 계정이 된다(실제 이메일 계정과 자동으로 합쳐지지 않음). 합치기는 [다음] "설정 › 계정 › 로그인 방법"에서 로그인한 채로 다른 방식 추가.
- 이메일·비밀번호 계정은 나중에 소셜을 더할 수 있다(2번 규칙으로 자동). 소셜로만 가입한 계정에 비밀번호를 더하는 것은 비밀번호 재설정 메일이 생기면 [다음].
- 틱틱은 계정을 합치지 않는다(research 27) — 2번 연결 규칙은 sprout가 정한 것.
- ⚠ **남은 위험 — 공개 출시 전 필수**: 이메일 인증이 아직 없어서, 남이 내 이메일로 **먼저 비밀번호 가입**해 두면 내가 구글로 들어올 때 그 계정에 연결된다(계정 선점). 이메일 인증을 넣을 때 "인증 안 된 비밀번호 계정에 소셜을 연결하면 비밀번호를 지우고 기존 세션을 끊는다"로 바꾼다.

**로그아웃**: §7 그대로(소셜 계정도 같다). 구글·애플 쪽 세션은 건드리지 않는다(브라우저의 구글 로그인은 그대로). 다음 로그인 때 구글은 계정 고르기 화면(`prompt=select_account`)이 떠서 다른 계정을 고를 수 있다.

| 가입·로그인 | API `POST /auth/signup` · `/auth/login` · `/auth/google` · `/auth/apple`(§3.1) → 토큰(+`created`: 새 계정). 메인 프로세스가 키체인 암호화로 `userData/auth.bin`에 저장 |
| 첫 로그인 | `GET /auth/me`의 `has_data`: 없음 → 로컬 모든 테이블 `owner_id`를 내 id로 바꿔 올림 / 있음 → 로컬 비우고 내려받음(로그인 전 이 기기에서 만든 것은 사라진다 — 확인 대화상자 필요 [임시]) |
| 동기화 상태 | PowerSync `currentStatus` → IPC `auth:state` |
| 로그아웃 | `POST /auth/logout`, 로컬 DB 비움 |
- 비밀번호 규칙: 틱틱과 같이 **6-64자** (지금 서버는 8자 이상 → 6-64로 맞춘다).
