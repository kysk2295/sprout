## 1. 규칙
### 1.1 대상 [sprout]
열려 있는(`status = 0`, `deleted_at IS NULL`) 할 일 중 **마감 날짜가 오늘보다 14일 넘게 지난 것**:
- `datePart(due_at) < 오늘 − 14일` (오늘 2026-10-09 → 마감 09-24 이전이면 대상, 09-25는 아직). 19와 같이 날짜만 본다 — `due_at`은 떠 있는 시각(floating)이라 시각 있는 일도 그날 날짜로 센다.
- **오늘 = 사용자 시간대의 날짜.** 시간대 = 이 설정 행에 저장된 시간대(설정을 바꾼 기기의 시간대) → 없으면 가장 최근에 보인 휴대폰의 푸시 등록 시간대(`device_tokens.timezone`) → 없으면 `Asia/Seoul`.

### 1.2 빼는 것
| 경우 | 처리 | 까닭 |
|---|---|---|
| 마감 없음 | 대상 아님 | 만료가 없다 |
| 완료·하지 않음(`status` 1·2) | 대상 아님 | 열린 일만 |
| **반복 할 일**(`repeat_rule` 있음) | 대상 아님 — 계열을 지우지 않는다 | 반복은 지금처럼 완료·미루기로 다음 회차로 넘어간다 |
| **상단 고정**(`pinned_at` 있음) | 대상 아님 | 사용자가 일부러 붙잡아 둔 일 |
| **보관한 리스트**의 할 일 | 대상 아님 | 19 만료 판정과 같음(보관 = 이미 정리됨) |
| **진행 중인 프로젝트**의 할 일 | 대상 아님 | 프로젝트 태그(`tags.kind = 'project'`, 받아들인 `task_tags`)가 붙어 있고 그 프로젝트의 마감(⚑ 핵심 날짜 할 일 — 없으면 구성원 중 가장 늦은 마감)이 오늘 이후면 |
| 한 번 자동 정리했다가 사용자가 되살린 일 | **같은 마감 날짜인 동안** 다시 옮기지 않는다 | 되돌리기·복원이 다음 날 또 지워지지 않게. 마감 날짜를 바꾸면 그 날짜로 다시 센다 |
| 외부 캘린더 일정(`events`, 구글·Apple 양방향) | 건드리지 않는다 | 할 일(`tasks`)만 옮긴다. 일정은 할 일과 다른 표이고, 외부 캘린더의 일정은 지우지 않는다 |

### 1.3 하위 할 일 [sprout] — "부모와 함께, 하나라도 지켜야 하면 통째로 건너뜀"
- 대상 부모는 **열린 하위 할 일과 함께** 휴지통으로(02 삭제와 같음). 완료·하지 않음인 하위는 그대로 둔다(완료 기록·통계를 바꾸지 않으려고).
- 열린 하위 중 하나라도 **지켜야 하는 것**이 있으면 부모도 옮기지 않는다: 반복·고정·진행 중인 프로젝트, 또는 **마감이 아직 2주 안 지난**(오늘 이후 포함) 하위. 마감 없는 하위는 부모를 따라간다.
- 부모가 대상이 아니거나 위 규칙으로 건너뛰어도, 스스로 대상인 하위는 그 하위만 옮긴다(하위 하나 삭제와 같음). 고르기는 위쪽 부모부터 — 부모가 옮겨지면 하위는 따라가고 따로 세지 않는다.

### 1.4 동작
- 휴지통으로 = 손으로 지운 것과 같다: `tasks.deleted_at = 지금`, `modified_at = 지금`. **복원은 휴지통에서 그대로**(02·21). 휴지통 자체의 보관 기간은 지금 규칙 그대로(이 기능은 영구 삭제하지 않는다).
- **XP·성장**: 완료가 아니므로 XP를 주지도 빼지도 않는다(`xp_events` 그대로). 완료·하지 않음 행을 건드리지 않으므로 완료 수·주간 통계도 줄지 않는다.
- 19 자동 규칙 "만료 30일 지나면 날짜 빼기"(기본 꺼짐)와 같이 켜면 14일이 먼저라 이 기능이 먼저 옮긴다. 정리 도우미(19 §3)는 남은(제외된) 만료를 그대로 다룬다.

## 2. 어디서 도나 — 서버 하루 한 번 [sprout]
- **서버 API 프로세스의 작업**(`server/api/src/autoTrash.ts`, 10분마다 확인 [임시]): 사용자마다 그 시간대의 날짜가 바뀐 뒤 처음 돌 때 한 번(`auto_trash_state.last_day`). 앱을 아무것도 안 켜도 되고, 모든 기기에 같은 결과.
- 서버는 Postgres의 동기화 열(`tasks.deleted_at`·`modified_at`)에 바로 쓴다 → PowerSync가 논리 복제로 모든 기기에 내려보낸다. 기기의 나중 수정은 열 단위 PATCH라 `deleted_at`을 덮지 않는다.
- 여러 api 프로세스가 떠도 한 번만: advisory lock(푸시 스케줄러와 다른 키). 한 사용자 처리는 한 트랜잭션(옮기기 + 묶음 행 + 기록).
- 로그인하지 않은 로컬 전용 데스크톱은 서버에 데이터가 없어 대상이 아니다.

## 3. 알림 — 다음에 앱을 열 때 한 번
- 서버가 옮길 때마다 **묶음 행**을 하나 만든다: `view_settings` `view_key = 'autoTrash:batch'`, id `atb-<uuid>`, `options_json = {"at","day","ids","count","seen":false,"undone":false}`. 동기화 표라 마이그레이션 없이 모든 기기에 온다.
- 앱(데스크톱·휴대폰)은 `seen = false`이고 되돌리지 않은 묶음이 있으면 토스트를 한 번 띄우고 곧바로 `seen = true`로 바꾼다(다른 기기에서도 다시 안 뜸). 묶음이 여러 개 쌓였으면 합쳐서 한 번.
  - 문구: `만료된 지 2주 지난 할 일 N개를 휴지통으로 옮겼어요` · [보기](휴지통을 연다) · [되돌리기](⟲)
  - 데스크톱: 아래 가운데 토스트(02 §12), 8초 [임시]. ⌘Z도 되돌리기. 휴대폰: 탭 알약 위 토스트(21 §3), 6초 [임시], [보기] + [되돌리기] 두 버튼.
- **되돌리기 = 그 묶음만**: 묶음의 id 중 아직 그 묶음 시각(`deleted_at = at`)으로 휴지통에 있는 것만 `deleted_at = NULL`. 그 사이 손으로 복원했거나 다시 지운 일은 건드리지 않는다. 묶음 행은 `undone = true`.
- 묶음 행은 30일 뒤 서버가 지운다 [임시].

## 4. 설정 — 설정 › 할 일 › "만료 2주 지난 할 일 자동 정리" (계정 동기화)
- 데스크톱: 설정 › 할 일 카드(19 §3.4의 칸들 위) 스위치 + 설명 `매일 한 번, 만료된 지 14일이 지난 할 일을 휴지통으로 옮겨요. 반복·고정·진행 중인 프로젝트는 빼요.` + `마지막 자동 정리` 줄(날짜·개수 · [되돌리기], 30일 안).
- 휴대폰: 설정 › **할 일**(새 칸) → 같은 스위치 + 같은 설명 + 마지막 자동 정리 [되돌리기].
- 저장: `view_settings` id `autotrash-<사용자 id>`(기기 두 대가 따로 만들어도 한 행), `view_key = 'autoTrash'`, `options_json = {"on": true|false, "tz": "<IANA>"}`. **행이 없으면 켬**. 스위치를 바꾼 기기의 시간대를 `tz`로 같이 저장한다.
