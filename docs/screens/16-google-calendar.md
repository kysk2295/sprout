## 0-2. v2 결정 — 양방향(쓰기) (2026-10-05 **제안**, 사용자 확인 전)
사용자 요청(2026-10-05): "애플이랑 구글캘린더가 양방향으로 틱틱처럼 되야하는데 이것도 구현해줘". 근거 조사 [research 31](../ticktick-research/31-calendar-two-way.md).
| # | 질문 | 제안 |
|---|---|---|
| ⑦ | 무엇을 양방향으로 | **구글 + Apple(맥 캘린더 앱) 둘 다** 만들기·고치기(제목·날짜·시간·종일·장소·설명)·끌기·길이·삭제. 틱틱은 구글·iCloud만 양방향이고 맥 "로컬 캘린더"는 읽기 전용이다(research 31 §1) → Apple 쓰기는 **[sprout] 틱틱보다 넓음**(결정 필요 Q1) |
| ⑧ | 어떤 캘린더를 고칠 수 있나 | 구글 `accessRole` = `owner`·`writer`, Apple `allowsContentModifications` = 참. 휴일·공유 보기 전용·생일·구독(ICS)·근무 위치·부재중·집중 시간·Gmail에서 온 일정·**내가 주최자가 아닌 초대 일정**은 읽기 전용 그대로(§12.2) |
| ⑨ | 구글 권한 | `calendar.events.readonly` → **`calendar.events`**(+ `calendar.calendarlist.readonly` 그대로). 기존 연결은 **읽기는 계속 되고**, 처음 고치려 할 때 "쓰기 권한 허용" 대화로 다시 동의(증분 동의) — 강제 다시 연결 없음(Q5) |
| ⑩ | 만들 때 어느 캘린더에 | 빠른 만들기 `일정`의 아래 왼쪽 "● 내 일정"을 **캘린더 고르기**로: 꿈틀 일정 / 구글 캘린더(계정별) / Apple 캘린더(출처별). 기본값 = **이 기기에서 마지막으로 고른 캘린더**(Q2) |
| ⑪ | 반복 일정을 고칠 때 | 범위 대화창: **이 일정만 / 이후 모든 일정 / 모든 일정**(Q3). 반복 규칙 자체 바꾸기는 03 선택기로 표현되는 규칙일 때만 |
| ⑫ | 저장 방식 | **화면 먼저 바꾸고(낙관적) 바로 구글·EventKit에 쓴다.** 실패하면 원래대로 돌리고 토스트. 다른 곳에서 먼저 바뀌었으면(구글 etag 412, Apple 수정 시각) 최신 내용으로 바꾸고 알림. **오프라인 쓰기 대기열은 두지 않는다** — 구글 일정은 오프라인이면 고치지 못하게 막는다(Apple은 EventKit이 기기 안이라 오프라인에도 된다) |
| ⑬ | 휴대폰 | **이번엔 데스크톱만.** 외부 캘린더 캐시·토큰이 이 기기에만 있어(결정 ④·§5) 휴대폰은 구글 일정을 모른다. 휴대폰 연결은 [다음] |
| ⑭ | 꿈틀 일정과의 관계 | 꿈틀 자체 일정(06 §14.4)은 그대로. 외부 일정은 **같은 카드·같은 끌기**를 쓰고, 다른 점은 저장 위치와 "고칠 수 있는지" 판정뿐 |

## 2. 레이아웃
### 2.1 설정 › 연동 [틱틱 위치, sprout 문구]
설정 창(현재 `DesktopSettings`: 계정 · 스마트 목록 · 외관 · 단축키)에 **"연동"** 탭을 더한다(틱틱 "연동 & 가져오기"). 아이콘 = 플러그 선 아이콘.
```
연동
┌ 캘린더 ───────────────────────────────────────────┐
│ 다른 캘린더를 sprout에 구독해요.        + 캘린더 추가 │  ← 강조색 글자 버튼
│ ▭ me@gmail.com      5분 전에 동기화           편집 │  ← 계정 행(연결 뒤)
│ ▭ work@company.com  다시 연결이 필요해요   다시 연결 │  ← 오류 행(빨강 글자)
└───────────────────────────────────────────────────┘
구글 일정은 읽기 전용이에요. sprout에서 구글 일정을 바꾸지 않고, 일정은 이 기기에만 저장돼요.   ← 캡션 11, 3차 글자색 (→ v2 §12.13에서 문구 바뀜)
```
- 카드·행은 기존 `settings-card`·`settings-row`(00 `color.bg.card`) 그대로. 행 높이 44, 계정 이메일 13 본문색, 상태 글자 12 `color.text.tertiary`.
- "+ 캘린더 추가" → 작은 메뉴: **구글 캘린더** · **Apple 캘린더**(맥에서만, §11)(다른 서비스는 [다음], 메뉴에 넣지 않음). 틱틱의 "구독 / 통합" 고르기 모달은 거치지 않고 바로 연결(§4.1) [cal-subscription NOTES 결정].
- 틱틱의 "방해 금지(구독 일정 알림 끄기)" 토글은 두지 않는다 — sprout v1은 구글 일정 알림을 보내지 않는다 [sprout].

### 2.2 계정 편집 모달 [틱틱 로컬 캘린더 모달 모양 — 구글은 [임시]]
```
          me@gmail.com                    ⋯     ← 제목 = 이메일, ⋯ = 지금 새로 고침 · 연결 끊기
 내 캘린더
 ┌ ● me@gmail.com              보이기 ⌃⌄ ┐
 │ ● 운동                      보이기 ⌃⌄ │
 └ ● 가족                      숨기기 ⌃⌄ ┘
 다른 캘린더
 ┌ ● 대한민국의 휴일            보이기 ⌃⌄ ┐
 └ ● 팀 공유 캘린더             숨기기 ⌃⌄ ┘
                         [ 취소 ] [ 확인 ]
```
- 가운데 모달 440 폭(06 옵션 보기 모달과 같은 틀), 높이는 내용에 맞추고 최대 화면 80%에서 안쪽 스크롤.
- 묶음: **내 캘린더**(구글 `accessRole = owner`) / **다른 캘린더**(그 외: 구독·공유·휴일). 각 행 = 캘린더 색 점 8 + 이름(구글의 `summaryOverride` 우선) + 오른쪽 선택.
- 선택지 v1: **보이기 / 숨기기**. 틱틱의 "캘린더에서만 보이기"는 스마트 리스트에 구글 일정을 넣는 기능과 짝이라 [다음].
- 확인을 눌러야 반영(틱틱 Cancel/Confirm). Esc = 취소.
- 색 바꾸기는 없다 — 구글에서 정한 캘린더 색을 그대로 쓴다 [임시].

### 2.3 캘린더 화면 (06에 더하는 것)
| 위치 | 바뀌는 것 |
|---|---|
| 머리글 `...` › **캘린더 구독** | 지금 비활성 → 활성. 누르면 설정 › 연동 탭을 연다 [틱틱 17 §1] |
| 왼쪽 패널 `› 캘린더 구독` | 지금 안내 문구("다음 단계에서 붙어요") → 펼치면 **계정 이름 줄(작은 회색 글자) + 그 아래 캘린더 행**(색 칸 체크 + 이름). 그룹 체크칸 = 구독 캘린더 전부 켜기/끄기. 계정이 없으면 강조색 글자 행 **"구글 캘린더 연결"** → §4.1 [틱틱 모양 17 §8, 문구 sprout] |
| 주·일·월 그리드 | 구글 일정이 태스크와 같은 막대·블록으로 겹쳐 그려진다(§3) |
- 설정의 "숨기기"는 모든 곳에서 숨김, 왼쪽 패널 체크는 **캘린더 보기에서만** 잠깐 거르는 필터다. 숨긴 캘린더는 왼쪽 패널에 나오지 않는다 [임시].
- 왼쪽 패널 체크는 리스트·태그 필터와 **따로 논다**: 리스트·태그를 골라도 구글 일정은 구독 체크만 따른다 [임시].

### 2.4 사이드바 "구독 캘린더" (G2 — 결정 ②) [틱틱 19 §4]
- 01 §4.1 순서대로 Tags 아래 **"구독 캘린더"** 구역. 계정이 있을 때만 보인다. 행 = 캘린더 아이콘 + 이메일 + 오른쪽 **앞으로 3개월 일정 개수**(0이면 숨김, 01 §4.2 규칙).
- 소제목에 마우스를 올리면 `+` → "구글 캘린더" 메뉴(§2.1과 같음).
- 계정 행을 누르면 가운데 목록: 머리 제목 = 이메일(02 머리 규칙), **추가 바 없음**, 그룹 **오늘 / 다음 7일 / 나중에**(나중에 기본 접힘), 앞으로 3개월. 행 = 작은 캘린더 아이콘(체크박스 자리, 누를 수 없음) + 제목 + 오른쪽 날짜(02 날짜 색 규칙). 행 왼쪽 2pt 캘린더 색 줄.
- 행을 누르면 오른쪽 상세 자리에 §3.3 팝오버와 같은 내용을 읽기 전용으로.
- 빈 상태: 02 빈 상태 틀 + **"앞으로 3개월 동안 일정이 없어요."** [틱틱 "It's all clear in the next 3 months." 번역].

### 3.4 연결 진행 모달 [sprout]
- 작은 모달 360: 제목 `구글 캘린더 연결` / 본문 `브라우저에서 구글 로그인과 권한 허용을 마쳐 주세요.` / 회전 표시 / 아래 `링크 다시 열기`(텍스트 버튼) · `취소`.
- 성공: 모달 닫힘 → 설정에 계정 행 + 토스트 `구글 캘린더를 연결했어요`. 첫 동기화가 끝나면 캘린더에 일정이 나타난다.
- 실패 문구(모달 안 빨강 줄 + `다시 시도`):
  | 경우 | 문구 |
  |---|---|
  | 브라우저에서 거부·창 닫음(`access_denied`) | `연결을 취소했어요.` |
  | 5분 동안 응답 없음 | `시간이 지나서 연결을 멈췄어요.` |
  | 일정 권한 체크를 뺌 | `일정을 읽는 권한이 있어야 연결할 수 있어요.` |
  | 테스트 모드에서 등록 안 된 계정(`access_denied`/403 `org_internal`·`access_not_configured`) | `이 구글 계정은 아직 쓸 수 없어요. 운영자에게 테스트 사용자 등록을 요청해 주세요.` [임시 — 결정 ①] |
  | 이미 연결한 계정 | 새 행을 만들지 않고 그 계정 토큰만 바꾼다 + `이미 연결된 계정이라 다시 연결했어요.` |
  | 인터넷 없음 | `인터넷에 연결되어 있지 않아요.` |
- 브라우저 쪽 돌아오는 페이지(로컬 주소): 흰 바탕 가운데 글자 `sprout로 돌아가 주세요. 이 창은 닫아도 돼요.`(실패 시 `연결하지 못했어요. sprout에서 다시 시도해 주세요.`). 외부 이미지·스크립트 없음.

## 5. 데이터 — **동기화 스키마는 건드리지 않는다**
- `packages/schema`·Postgres·PowerSync 동기화 규칙에 **아무것도 더하지 않는다.** 서버 마이그레이션 없음. `view_settings.options_json`(동기화됨)에도 구글 캘린더 id를 넣지 않는다 — 캘린더 id가 이메일 주소 모양이라 서버로 가면 안 된다.
- 구글 일정은 `tasks`가 아니다: XP 없음, 리스트·스마트 리스트 개수에 안 들어감, AI 비서·주간 리포트 입력에 안 들어감(결정 ④), 검색(⌘K)에도 v1은 안 들어감 [임시].
- 01 §데이터의 "기기에만 저장 `calendar_accounts`" 항목을 아래 구조로 구체화한다.

| `calendars:connect(provider)` / `calendars:cancel` / `calendars:reopen` | §7.1(구글)·§11.2(Apple) 연결 시작·취소·브라우저 링크 다시 열기. 결과 `{ ok, account, message }` 또는 `{ ok:false, error }` |
| `calendars:events(from, to, { panel })` | 캐시에서 범위 일정(보이기 + `panel`이면 패널 체크까지, 거절한 일정 제외) |
| `calendars:setVisibility(accountId, changes)` / `calendars:setPanel(accountId, calendarId?, on)` | 표시 설정 저장(숨기면 그 캘린더 캐시 삭제, 보이게 하면 전체 받기) |
| `calendars:refresh(accountId?, force?)` / `calendars:disconnect(accountId)` | 새로 고침(1분 안 중복은 건너뜀, `force`면 즉시) / 끊기 |
| `calendars:open(accountId, calendarId, eventId)` | 구글 = `htmlLink`를 기본 브라우저로, Apple = 캘린더 앱 |
| `calendars:openPrivacy` | (Apple) 시스템 설정 › 개인정보 보호 › 캘린더 |
| 메인 → 렌더러 `calendars:changed` | 캐시·상태가 바뀌면 알림 → 보이는 범위 다시 읽기. `calendars:progress`는 연결 진행 |

## 7. 기술
### 7.1 OAuth: 설치형 앱 흐름 + PKCE + 루프백 (메인 프로세스)
1. 메인에서 `code_verifier`(무작위 43~128자, base64url) → `code_challenge = BASE64URL(SHA256(verifier))`, `state`(무작위) 생성.
2. `http://127.0.0.1:<빈 포트>`에 **127.0.0.1에만** 묶은 임시 HTTP 서버를 연다(포트 0 → 운영체제가 고름). 경로 `/oauth/callback` 하나만 받는다.
3. `shell.openExternal`로 `https://accounts.google.com/o/oauth2/v2/auth?client_id=…&redirect_uri=http://127.0.0.1:<port>/oauth/callback&response_type=code&scope=<§7.2>&code_challenge=…&code_challenge_method=S256&state=…&access_type=offline&prompt=consent` 를 연다. 앱 안 웹뷰로 열지 않는다(구글이 내장 웹뷰 로그인을 막는다).
4. 돌아온 요청에서 `state` 확인 → §3.4 돌아오는 페이지 응답 → 서버 닫기. 5분 안에 안 오면 닫고 실패.
5. `https://oauth2.googleapis.com/token`에 `code` + `code_verifier` + `client_id` (+ 데스크톱 클라이언트가 받는 `client_secret`. 구글 문서상 설치형 앱의 비밀값은 비밀로 취급되지 않는다 — 앱에 넣어 배포해도 되지만 그것만으로 보안이 되지는 않고, 보안은 PKCE가 맡는다)로 교환.
6. 응답의 `scope`를 확인해 §7.2 두 범위가 모두 있어야 성공(사용자가 동의 화면에서 일부만 체크할 수 있다).
7. 계정 이메일은 `calendarList`의 기본 캘린더 id에서 얻는다 → **`openid`·`email` 범위를 따로 받지 않는다.**
8. 토큰 저장(§7.5) → 첫 동기화 시작.
- 렌더러·preload는 인증 코드·토큰을 보지 않는다. 루프백 서버는 흐름이 끝나면 반드시 닫는다.

### 7.2 범위 — 가장 좁게
| 범위 | 왜 |
|---|---|
| `https://www.googleapis.com/auth/calendar.calendarlist.readonly` | 캘린더 목록·이름·색·기본 캘린더(=이메일)·`selected` |
| `https://www.googleapis.com/auth/calendar.events.readonly` | 모든 캘린더의 일정 읽기 |
- `calendar.readonly` 하나로도 되지만 그 범위는 캘린더 설정·공유(ACL) 읽기까지 포함한다 → **나눠진 두 범위가 더 좁다.** 쓰기 범위(`calendar`, `calendar.events`)는 받지 않는다. (→ v2 §12.3에서 `calendar.events.readonly`를 `calendar.events`로 바꾼다)
- `calendar.events.owned.readonly`는 내가 소유한 캘린더만 읽어서 휴일·공유 캘린더가 빠진다 → 쓰지 않는다.
- 두 범위 모두 구글 분류상 **민감(sensitive)** 이다(구글 클라우드 콘솔이 범위를 넣을 때 표시). **제한(restricted) 범위는 아니라서** 유료 외부 보안 평가(CASA)는 필요 없다.

### 7.3 구글 API 호출
- `GET calendar/v3/users/me/calendarList` (새로 고침 때마다 1번, `showHidden=false`) — 사라진 캘린더 정리, 새 캘린더는 숨기기로 추가 [임시].
- 캘린더마다 `GET calendar/v3/calendars/{id}/events`:
  - **처음(전체)**: `singleEvents=true`, `timeMin=오늘−6개월`, `maxResults=2500`, `eventTypes`로 `workingLocation` 제외 [임시], 페이지(`pageToken`) 끝까지 → 마지막 페이지의 `nextSyncToken` 저장.
  - **이후(증분)**: 같은 매개변수에서 `timeMin`만 빼고 `syncToken=…` (구글 규칙: `syncToken`과 `timeMin`·`timeMax`·`q`·`orderBy`·`updatedMin`은 같이 못 쓴다). `status=cancelled`인 항목은 캐시에서 지운다.
  - **410 Gone**(토큰 만료): 그 캘린더 캐시를 비우고 전체 다시.
- 접근 토큰 만료(401) → 리프레시로 갱신 1회 후 재시도. 리프레시가 `invalid_grant`면 `reauth` 상태(§3.2).

### 7.4 새로 고침 주기·한도
- 주기: §4.2(앞에 있을 때 5분, 뒤에 있을 때 30분, 깸·온라인 복귀·화면 진입 즉시, 1분 안의 중복은 건너뜀).
- 한 번의 새로 고침 = 계정당 `calendarList` 1회 + 보이는 캘린더 수만큼 `events` 1회(대부분 바뀐 것만, 1페이지). 숨긴 캘린더는 받지 않는다(다시 보이게 하면 그때 전체 받기).
- 구글 할당량은 프로젝트 전체·사용자별 분당 한도가 있다(콘솔 "할당량"에서 확인, 무료). 위 주기라면 사용자 1명이 분당 수 회라 여유가 크다. 429·`rateLimitExceeded`·5xx는 **지수 백오프**(1·2·4·8초 … 최대 5분) + 무작위 지연.
- 구글 푸시 알림(watch 채널)은 공개 HTTPS 주소가 필요해 데스크톱에 맞지 않는다 → [다음].

### 7.5 토큰 보관: `safeStorage` (keytar 아님)
- 앱은 이미 sprout 로그인 토큰을 **`safeStorage`로 암호화해 `userData/auth.bin`에** 둔다([main/sync.ts](../../apps/desktop/src/main/sync.ts)). AI 사용량 로그인([main/usageLogin.ts](../../apps/desktop/src/main/usageLogin.ts))은 토큰을 직접 보관하지 않고 각 CLI의 프로필 폴더(0700)에 맡긴다. → 구글도 **`safeStorage`** 로 맞춘다.
  - 맥에서 `safeStorage`의 암호화 키는 키체인 항목("sprout Safe Storage")에 있어 PRD의 "OS 키체인 보관"을 만족한다. `keytar`는 개발이 중단(보관 처리)되어 새로 들이지 않는다.
- **sync.ts와 다른 점 [sprout]:** `safeStorage.isEncryptionAvailable()`이 거짓이면 sync.ts는 평문으로 저장하지만, 구글 토큰은 **디스크에 쓰지 않고 메모리에만** 둔다(§3.2 마지막 줄). 파일 권한 0600.
- 패키징·서명 전후로 키체인 접근 주체가 바뀌면 맥이 한 번 묻거나 복호화에 실패할 수 있다 → 실패하면 `reauth` 상태로 처리(일정 캐시는 유지).
- 리프레시 토큰은 구글 계정·클라이언트당 100개 한도(넘으면 가장 오래된 것이 조용히 무효)라, 같은 계정을 다시 연결할 때 이전 토큰을 먼저 폐기한다.

### 7.6 사용자가 준비해야 하는 것 (코드로 대신할 수 없음)
1. **구글 클라우드 프로젝트**(무료) 만들기 → "Google Calendar API" 사용 설정.
2. **OAuth 동의 화면(Google Auth Platform)**: 사용자 유형 "외부", 앱 이름(**제품명 확정 필요** — 지금은 코드네임), 지원 이메일, 개발자 연락처. 게시하려면 + **앱 홈페이지 주소, 개인정보 처리방침 주소(내 도메인), 승인된 도메인**(서치 콘솔에서 소유 확인). 로고는 넣으면 로고 심사가 추가되니 처음엔 빼도 된다.
3. **데이터 접근**에 §7.2 두 범위 추가 + 왜 필요한지 설명 글.
4. **OAuth 클라이언트 ID — 유형 "데스크톱 앱"** 만들기 → 클라이언트 ID(와 비밀값)를 빌드 환경 변수로 넣는다(저장소에 커밋하지 않음).
5. **테스트 사용자**: 심사 전 "테스트" 상태에서는 이메일로 등록한 사람(최대 100명)만 연결된다. 이때 리프레시 토큰은 **7일 뒤 만료** → 일주일마다 "다시 연결이 필요해요"가 뜨는 게 정상이다.
6. **앱 검증(공개 출시 전)**: 쉬운 말로 — "구글 일정 읽기"는 민감한 권한이라, 모르는 사람이 쓰는 앱이 되려면 구글이 "이 앱이 일정을 어디에 어떻게 쓰는지" 직접 확인한다. 낼 것: 홈페이지·처리방침(구글 일정을 이 기기에만 저장하고 서버·AI로 보내지 않는다는 문장 — 구글 "API 서비스 사용자 데이터 정책"의 제한적 사용 조건), 연결 과정과 일정이 보이는 화면을 찍은 시연 영상(유튜브 링크), 범위별 사용 이유. 보통 며칠~몇 주. 검증 없이 "게시"하면 연결 때 **"Google에서 확인하지 않은 앱"** 경고가 뜨고 새 사용자 100명 한도.
- 위 1~5는 사용자가 구글 계정으로 직접 로그인해서 해야 한다. 순서상 PRD §8 "공개 주소(도메인)"와 제품명·처리방침이 6번의 선행 조건이다.

## 11. Apple 캘린더 (맥 캘린더 앱에 등록된 캘린더 읽기) [sprout — 틱틱 "Local Calendars"에 해당]

| 편집 모달 | 제목 "이 Mac의 캘린더", 묶음 = **출처 이름**(iCloud · Exchange · 구독 · 이 Mac 등, EventKit `source.title`). 행 모양·보이기/숨기기·취소/확인은 §2.2와 같음. `⋯` = 지금 새로 고침 · 연결 끊기 |
| 왼쪽 패널·사이드바 | 계정 줄 이름 = "이 Mac의 캘린더". 계정이 없으면 `구글 캘린더 연결` 아래 `Apple 캘린더 연결` |
| 팝오버 맨 아래 | `캘린더 앱에서 열기 ↗`(`ical://ekevent/<id>?method=show&options=more`, 실패하면 캘린더 앱만 연다) [임시] |
| 연결 끊기 확인 본문 | `이 기기에 저장한 Apple 캘린더 일정이 지워져요. 캘린더 앱의 일정은 그대로예요. 접근 권한은 시스템 설정에서 끌 수 있어요.` |

### 11.2 권한 흐름
| 상태(EventKit) | 화면 |
|---|---|
| 처음(notDetermined) | 연결을 누르면 macOS 권한 창("sprout이(가) 캘린더에 접근하려고 합니다")이 뜬다. 연결 진행 모달 본문 `macOS 권한 창에서 "허용"을 눌러 주세요.` |
| 허용(fullAccess) | 계정 행 생성 + 첫 동기화. **처음 보이는 캘린더 = 전부**(생일 캘린더만 숨기기) [임시] |
| 거부(denied) / 쓰기만 허용(writeOnly) | 행 빨강 `캘린더 접근이 꺼져 있어요` + 버튼 `시스템 설정 열기`(개인정보 보호 및 보안 › 캘린더). 모달 실패 문구 `캘린더 접근을 허용해야 볼 수 있어요. 시스템 설정 › 개인정보 보호 및 보안 › 캘린더에서 sprout를 켜 주세요.` |
| 제한(restricted, 관리 정책) | 빨강 `이 Mac에서는 캘린더 접근이 제한돼 있어요` (버튼 없음) |
| 도우미 없음(개발 빌드에서 빌드 안 함) | 빨강 `캘린더 도우미가 없어요. 앱을 다시 설치해 주세요.` (개발: `npm run calendar:build`) |
- 권한은 macOS가 보관한다. sprout는 토큰을 저장하지 않는다. 로그아웃(결정 ⑤)은 Apple 계정 행과 캐시만 지우고 OS 권한은 그대로 둔다(다시 연결할 때 권한 창 없이 바로 됨).

### 11.3 데이터·새로 고침
- 범위: **오늘 − 6개월 ~ 오늘 + 2년**(EventKit 기간 검색은 한 번에 4년까지라 1년씩 나눠 묻는다). 반복 일정은 EventKit이 회차로 펼쳐 준다.
- 동기화 토큰이 없으므로 새로 고침마다 보이는 캘린더의 범위 일정을 통째로 받아 캘린더 단위로 갈아 끼운다(트랜잭션). 주기·창 앞/뒤·깸·1분 중복 건너뜀 규칙은 §4.2와 같다.
- 캘린더 색 = EventKit 캘린더 색(16진수). 시간대는 EventKit이 준 절대 시각을 기기 시간대 floating으로 바꾼다(§5.2와 같은 함수).
- 거절한 초대(참석자 중 나 = declined)는 그리지 않는다.

### 11.4 네이티브 도우미 `sprout-calendar` (apps/desktop/native/calendar/)
- 작은 Swift 명령줄 도구. 메인 프로세스가 `child_process.execFile`로 부르고 표준 출력 JSON을 읽는다(시간 제한 20초, 권한 창은 60초).
  | 명령 | 출력 |
  |---|---|
  | `status` | `{"status":"notDetermined|fullAccess|writeOnly|denied|restricted"}` |
  | `request` | 권한 요청(`requestFullAccessToEvents`, macOS 13 이하는 `requestAccess(to:.event)`) 뒤 같은 모양 |
  | `calendars` | `{"calendars":[{"id","title","color","source","sourceType","type","allowsModify"}]}` |
  | `events --from <ISO> --to <ISO> [--calendars id,id]` | `{"events":[{"id","calendarId","title","notes","location","url","start","end","allDay","timeZone","recurring","status","declined"}]}` (시각은 ISO 8601 UTC) |
- 빌드: `npm run calendar:build`(apps/desktop) → `native/calendar/out/sprout-calendar`. Info.plist(`NSCalendarsFullAccessUsageDescription`)를 바이너리에 넣는다(`-sectcreate __TEXT __info_plist`).
- 패키지 앱: electron-builder `extraResources`로 `Contents/Resources/sprout-calendar`. **앱 Info.plist에도 `NSCalendarsFullAccessUsageDescription`·`NSCalendarsUsageDescription`**(권한 창은 "책임 프로세스"인 sprout 앱 이름·문구로 뜬다) + 하드닝 런타임 entitlement `com.apple.security.personal-information.calendars`.
  - 문구: `sprout가 맥 캘린더 앱의 일정을 할 일과 함께 캘린더에 보여 주려고 읽어요. 일정은 이 Mac에만 저장되고 바꾸지 않아요.`
- **개발 실행 주의:** `electron-vite dev`에서는 권한을 묻는 주체가 **Electron.app**이다. Electron 기본 Info.plist에는 캘린더 사용 문구가 없어서 macOS가 권한 창 없이 바로 거부할 수 있다 → 개발 중 확인은 (가) 패키지 앱(`npm run dist:mac`)으로 하거나, (나) 시스템 설정 › 개인정보 보호 및 보안 › 캘린더에 Electron이 보이면 직접 켠다. 거부되면 화면은 §11.2 "접근이 꺼져 있어요"가 된다.
- 도우미 경로: 패키지 = `process.resourcesPath/sprout-calendar`, 개발 = `native/calendar/out/sprout-calendar`, 시험·확인용 덮어쓰기 = 환경 변수 `SPROUT_CALENDAR_HELPER`(가짜 도우미 스크립트).

### 11.5 온보딩 연결
- 렌더러 `data/calendars.ts`가 `connectCalendar('google' | 'apple')`(연결 진행 모달까지 띄우는 함수)과 `calendarProviders()`(이 기기에서 쓸 수 있는 공급자·준비 상태)를 내보낸다. 첫 실행 안내 화면(다른 명세)은 이 두 함수만 부른다.

## 12. 양방향(쓰기) — v2.0 제안 [틱틱 research 31 + sprout]
§0-2 제안이 확정되면 이 절대로 만든다. 화면·인터랙션은 **꿈틀 자체 일정(06 §14.4)과 똑같이** 하고, 다른 점은 ① 저장이 구글·EventKit로 간다 ② 일정마다 "고칠 수 있는지"를 판정한다 ③ 반복 범위를 묻는다, 세 가지다. 지금 코드(v1)는 읽기 전용이고, 이 절은 아직 구현하지 않는다.

### 12.1 틱틱 기준과 다른 점
| 항목 | 틱틱 | 꿈틀 v2 |
|---|---|---|
| 양방향 서비스 | 구글·iCloud. 맥 로컬 캘린더는 "local viewing only" | 구글 + **Apple(EventKit)** — 맥 캘린더 앱에 등록된 iCloud·구글·Exchange·CalDAV 중 쓰기 가능한 캘린더 전부 [sprout, Q1] |
| 일정 만드는 곳 | 사이드바 구독 캘린더 목록의 입력창 `Add agenda to "<계정>"` | 그 입력창(§12.4.2) **+** 캘린더 보기 빠른 만들기의 캘린더 고르기(§12.4.1) [sprout — 꿈틀은 빠른 만들기에 `할 일 · 일정`이 이미 있다] |
| 동기화 구조 | 틱틱 서버가 구글과 동기화(계정이 기기 사이에 따라다님) | 데스크톱이 직접 구글·EventKit 호출, 이 기기에만(결정 ④·⑬) |
| 반복 범위 | 할 일 대화창: 이번만 / 이후 모든 회차 / 완료 안 된 모든 회차. 일정 대화창은 미확인 | 이 일정만 / 이후 모든 일정 / 모든 일정 [임시, Q3] |

### 12.2 고칠 수 있는지 판정 (`writable`) — 메인 프로세스에서 일정마다 계산해 렌더러에 넘긴다
| 조건 | 결과 | 읽기 전용 이유 글자(팝오버 맨 아래 회색 한 줄) |
|---|---|---|
| 구글 쓰기 권한(`calendar.events`)이 없는 연결 | 읽기 전용, 고치려 하면 §12.3.2 대화 | (없음 — 대화창이 대신) |
| 구글 캘린더 `accessRole` = `reader`·`freeBusyReader` | 읽기 전용 | `이 캘린더는 보기만 할 수 있어요` |
| 구글 휴일 캘린더(`…#holiday@group.v.calendar.google.com`)·생일(`eventType = birthday`) | 읽기 전용 | `공휴일·생일 캘린더는 고칠 수 없어요` |
| 구글 `eventType` = `workingLocation`·`outOfOffice`·`focusTime`·`fromGmail` | 읽기 전용(근무 위치는 v1처럼 아예 받지 않음) | `구글 캘린더에서만 고칠 수 있는 일정이에요` + `구글 캘린더에서 열기 ↗` |
| 구글 `organizer.self` ≠ 참이고 `guestsCanModify` ≠ 참 (남이 초대한 일정) | 읽기 전용 | `주최자가 아니라 옮기거나 고칠 수 없어요` [틱틱 `event_move_non_organizer_hint` 번역] |
| Apple 캘린더 `allowsContentModifications` = 거짓(구독 ICS·생일·휴일·읽기 공유) | 읽기 전용 | `이 캘린더는 보기만 할 수 있어요` |
| Apple 일정 `organizer`가 있고 `isCurrentUser` = 거짓 | 읽기 전용 | `주최자가 아니라 옮기거나 고칠 수 없어요` |
| Apple 권한이 `fullAccess`가 아님 | 일정이 안 보임(v1 §11.2 그대로) | — |
| 구글 계정이 `reauth`·`scope_missing`·`offline`·`retrying` 상태 | **잠깐 읽기 전용** — 고치려 하면 토스트 `인터넷에 연결되면 고칠 수 있어요`(오프라인) / `구글 계정을 다시 연결해 주세요`(그 밖) | — |
| 그 밖 | **고칠 수 있음** | — |
- 꿈틀 공휴일(06 §16, `@sprout/schema/holidays`)은 일정이 아니라 배지·글자라 여기에 해당하지 않고, 늘 고칠 수 없다.
- 읽기 전용 일정의 모양·동작은 v1 §3.1·§3.3·§4.3 그대로(끌기 커서 없음, 끌어도 아무 일 없음). 고칠 수 있는 일정은 꿈틀 일정과 같은 커서·손잡이.

### 12.3 권한
#### 12.3.1 구글 범위 바꾸기
| 범위 | v1 | v2 | 왜 |
|---|---|---|---|
| `calendar.calendarlist.readonly` | ✓ | ✓ 그대로 | 캘린더 목록·이름·색·`accessRole` |
| `calendar.events.readonly` | ✓ | ✗ 뺀다 | 아래 범위가 읽기를 포함 |
| `calendar.events` | — | ✓ 새로 | "모든 캘린더의 일정 보기·수정"(만들기·고치기·지우기·`move`). 구글 분류 **민감(sensitive)** — 제한(restricted)은 아니라 CASA 보안 평가는 여전히 필요 없다 |
- `calendar.events.owned`(내가 소유한 캘린더만 쓰기)는 공유받은 `writer` 캘린더에 쓸 수 없고 휴일·공유 캘린더 읽기도 빠져서 쓰지 않는다. `calendar`(전체)는 캘린더 만들기·공유 설정까지라 넓다 → 쓰지 않는다.
- 새로 연결하는 사람: §7.1 그대로, 범위만 위 두 개. 동의 화면 문구는 "캘린더 목록 보기" + "모든 캘린더의 일정 보기 및 수정"(구글이 정한 문장).
- 응답 `scope`에 `calendar.events`가 없고 `calendar.events.readonly`만 있으면(사용자가 쓰기 체크를 뺌) 연결은 **읽기 전용 연결로 성공**시킨다(v1과 같은 상태) + 토스트 `읽기만 연결했어요. 일정을 고치려면 쓰기 권한을 허용해 주세요.` [sprout]. 일정 읽기 권한까지 빼면 v1 §3.4 실패 그대로.

#### 12.3.2 기존 연결(읽기 전용 토큰) — 강제로 끊지 않는다 [sprout, Q5]
- 업데이트해도 읽기는 그대로 된다(토큰의 `scope`를 보고 `canWrite` = 거짓으로 둔다).
- 처음 고치려는 순간(팝오버 칸에 들어가기·끌기 놓기·삭제·만들기에서 그 계정 캘린더를 고름) **작은 확인 대화**:
  - 제목 `구글 캘린더에 쓰기 권한이 필요해요` / 본문 `<이메일>의 일정을 꿈틀에서 고치려면 구글에서 한 번 더 허용해 주세요. 고친 내용은 바로 구글 캘린더에 반영돼요.` / `나중에` · `허용하기`(강조색).
  - `허용하기` → §7.1 흐름을 `include_granted_scopes=true` + `login_hint=<이메일>`로(증분 동의, 같은 계정이 미리 골라짐) → 성공하면 그 계정 토큰을 바꾸고 **하려던 일을 이어서 한다**(끌기였으면 놓은 자리로 저장). 실패·취소면 원래대로 + 토스트 `쓰기 권한을 받지 못해서 고치지 않았어요`.
  - 끌기 도중에 대화가 뜨면 끌기 미리 보기는 놓은 자리에 남겨 두고(옅게) 결과에 따라 확정·되돌림.
- 설정 › 연동 계정 행: 쓰기 권한이 없으면 상태 글자 옆에 회색 `읽기만` + 오른쪽 `쓰기 허용`(강조색 글자 버튼, 같은 흐름). 쓰기가 되면 아무 표시 없음.
- 사용자가 구글 계정 보안 설정에서 쓰기만 철회하는 경우: 쓰기 호출이 403 `insufficientPermissions` → 그 계정 `canWrite` = 거짓, 화면 되돌림 + 위 대화.

#### 12.3.3 Apple (EventKit)
- 권한은 v1과 같은 **전체 접근(fullAccess)** 하나로 읽기·쓰기 모두 된다(쓰기만 허용 `writeOnly`는 읽지 못해서 v1 §11.2처럼 "접근이 꺼져 있어요"). 새로 묻는 권한은 없다.
- 권한 창 문구(Info.plist `NSCalendarsFullAccessUsageDescription`·`NSCalendarsUsageDescription`, electron-builder.yml, 도우미 Info.plist)를 바꾼다: `꿈틀이 맥 캘린더 앱의 일정을 할 일과 함께 보여 주고, 꿈틀에서 만들거나 고친 일정을 캘린더 앱에 저장해요. 일정은 이 Mac 밖으로 보내지 않아요.` 이미 허용한 사용자는 다시 묻지 않는다(macOS는 문구가 바뀌어도 권한을 유지).

### 12.4 만들기
#### 12.4.1 캘린더 보기 빠른 만들기 — 대상 캘린더 고르기 [sprout]
- 06 §14.4.2 `일정` 팝오버의 아래 왼쪽 **"● 내 일정"(누를 것 없음)을 캘린더 고르기 버튼으로** 바꾼다: `● <캘린더 이름> ⌄`(색 점 + 이름, 길면 말줄임 최대 160).
- 누르면 작은 메뉴(06 머리글 메뉴와 같은 틀, 폭 240, 최대 높이 화면 50% 안쪽 스크롤):
  ```
  ✓ ● 내 일정                 ← 꿈틀 자체 일정(휴대폰까지 동기화)
  ─────────────
  me@gmail.com               ← 작은 회색 머리(계정)
    ● me@gmail.com
    ● 운동
  이 Mac의 캘린더 · iCloud    ← 작은 회색 머리(출처)
    ● 집
    ● 회사
  ```
  - 보이는 것: **고칠 수 있는(§12.2) + 설정에서 "보이기"인** 캘린더만. 읽기 전용·숨긴 캘린더는 넣지 않는다.
  - 구글 계정이 쓰기 권한이 없으면 그 계정 캘린더 행 끝에 회색 `권한 필요` — 고르면 §12.3.2 대화.
  - 오프라인이면 구글 캘린더 행이 비활성(회색, 툴팁 `인터넷에 연결되면 쓸 수 있어요`).
  - 키보드: 메뉴 안 ↑↓·Enter, Esc = 메뉴만 닫기.
- **기본값 = 이 기기에서 마지막으로 고른 캘린더**(localStorage `sprout.cal.qc.target` = `sprout` | `<accountId>/<calendarId>`) [Q2]. 그 캘린더가 사라졌거나 읽기 전용이 되면 `내 일정`으로.
- 고른 캘린더에 따라 팝오버 안에서 바뀌는 것:
  | | 내 일정 | 구글·Apple 캘린더 |
  |---|---|---|
  | 날짜 선택기의 **알림** | 됨(06 §14.4.7) | **숨긴다** — 외부 일정 알림은 v2 범위 밖(v1 §2.1 "방해 금지" 없음과 같은 이유) [다음]. 구글은 그 캘린더의 기본 알림(`reminders.useDefault`)이 붙고, Apple은 알림 없이 만든다 |
  | **반복** | 03 반복 규칙 | 같은 선택기 → RRULE로 바꿔 보낸다(03이 만드는 규칙은 모두 RRULE로 표현됨). "완료일 기준" 반복은 일정에 없으므로 원래 없음 |
  | 장소·설명 | 됨 | 됨(구글 `location`·`description`, Apple `location`·`notes`) |
  | 색 | 내 일정 색 | 그 캘린더 색 |
- 저장(Enter·바깥 클릭)은 06 §7.1과 같다. 저장하면 **막대가 바로 그 자리에 생기고**(낙관적, §12.7) 구글·EventKit에 쓴다. 실패하면 막대를 지우고 팝오버를 **입력한 내용 그대로 다시 연다** + 빨강 한 줄 이유(§12.7 표).
- 시간 칸 한 번 클릭 = 1시간, 끌기 = 그 범위, 종일 칸 = 종일 — 06 §14.4.2와 같다.

#### 12.4.2 사이드바 "구독 캘린더" 목록의 추가 바 [틱틱 research 31 §2]
- v1 §2.4에서 뺐던 **추가 바**를 계정 목록 위에 둔다: 자리 글자 `"<이메일>"에 일정 추가`(틱틱 `Add agenda to "%@"` — 한국어 틱틱 `스케줄을 "%@"로 추가`를 꿈틀 말투로). Apple 계정 목록은 `"이 Mac의 캘린더"에 일정 추가`.
- 02 추가 바와 같은 모양·같은 자연어 날짜 인식(01 빠른 추가 규칙, "내일 3시 치과"). 날짜가 없으면 오늘 종일.
- 대상 캘린더 = 그 계정의 **기본 캘린더**(구글 `primary`, Apple = EventKit `defaultCalendarForNewEvents`가 그 계정에 있으면 그것, 아니면 첫 쓰기 가능 캘린더). 바 오른쪽 끝에 작은 `● <캘린더> ⌄`로 바꿀 수 있다(§12.4.1 메뉴, 그 계정 캘린더만).
- 쓸 수 있는 캘린더가 하나도 없는 계정·쓰기 권한이 없는 계정: 바 자리에 회색 한 줄 `이 계정은 보기만 해요 · 쓰기 허용`(권한이 없을 때만 `쓰기 허용` 링크).

### 12.5 고치기 — 팝오버 [06 §14.4.4와 같은 카드]
- 고칠 수 있는 외부 일정을 누르면 **꿈틀 일정 카드와 같은 팝오버**: 제목(바로 고치는 입력) / 🕐 날짜·시간 줄(03 날짜 선택기 — 날짜·기간·종일·반복, **알림 줄은 숨김**) / 📍 장소 / 📄 설명 / 아래 줄 `● <캘린더 이름> · <계정>` + 오른쪽 `구글 캘린더에서 열기 ↗`(Apple `캘린더 앱에서 열기 ↗`) + 🗑.
- 저장 시점: 칸을 벗어날 때(날짜 선택기는 OK) 바로 — 06 §14.4.4와 같다. 제목을 비우고 닫으면 원래 제목.
- **설명**: 구글 설명은 HTML일 수 있다. 꿈틀은 글자로 보여 주고(v1 §3.3), 사용자가 설명 칸을 **고친 때만** 글자로 바꿔 보낸다(고치지 않으면 HTML 그대로 둠). 설명 칸에 들어갈 때 원문이 HTML이면 칸 아래 회색 `서식은 글자로 바뀌어 저장돼요` [sprout].
- **캘린더 바꾸기**(아래 줄 `● 캘린더 ⌄`): **같은 계정 안에서만** — 구글 `events.move`, Apple 같은 출처(source) 안의 다른 캘린더. 다른 계정·꿈틀 일정으로 옮기기는 [다음](만들고 지우기라 id·참석자가 바뀜). 반복 일정의 회차 하나만 다른 캘린더로 옮길 수는 없어서, 반복 일정은 캘린더 바꾸기를 비활성으로 둔다 [임시].
- **반복 규칙**: 03 선택기가 표현할 수 있는 RRULE(매일·매주 요일·매월 날짜/몇째 주·매년, 간격, 끝 날짜/횟수)이면 고칠 수 있다. 표현할 수 없는 규칙(여러 RRULE·EXDATE 외 RDATE·BYSETPOS 조합 등)이면 반복 줄이 읽기 전용 글자 `사용자 반복 — 구글 캘린더에서 바꿀 수 있어요` [sprout].
- 참석자·화상 회의·첨부: 보이지 않는다(v1과 같음) [다음]. 참석자가 있는 일정(내가 주최자)을 고치면 §12.8 Q4.
- 우클릭 메뉴(외부 일정, 고칠 수 있음): 열기 · 복제 · `구글 캘린더에서 열기`(Apple `캘린더 앱에서 열기`) · (구분선) · 삭제. **할 일로 바꾸기**는 [다음](외부 일정을 지우는 일이라 v2에서는 빼 둔다). 읽기 전용 일정은 v1 그대로 `… 열기` 하나.

### 12.6 옮기기·길이·삭제·되돌리기
- **끌어 옮기기·가장자리로 길이 바꾸기·종일 ↔ 시간 칸·월 칸 이동·⌥ 복제·⌘+클릭 함께 선택·끄는 동안 모양·Esc 취소**는 꿈틀 일정과 같다(06 §7.2·§14.4.5). 시간 칸으로 옮긴 종일 일정 = 1시간, 종일 영역으로 옮긴 시각 일정 = 그날 종일.
- ⌥ 복제 = 같은 캘린더에 새 일정(반복 규칙은 복사하지 않음 — 그 회차 하나만) [임시].
- ⌘+클릭 함께 옮기기에 고칠 수 있는 외부 일정도 들어간다. 읽기 전용 일정은 선택에 끼지 않는다(v1 그대로). 여러 개를 옮기다 일부가 실패하면 실패한 것만 되돌리고 토스트 `N개는 옮기지 못했어요`.
- **반복 일정**: 회차 막대도 끌 수 있다(꿈틀 일정과 다름 — 외부 일정은 회차가 실제로 있으므로). 놓으면 §12.8 범위 대화. Esc·`취소` = 원래 자리.
- **삭제**: 팝오버 🗑 · 우클릭 `삭제` · 고른 뒤 Delete/Backspace.
  - 반복 아님: 바로 지우고 토스트 `일정을 삭제했어요 ⟲`. 되돌리기 = 구글은 같은 id를 `status: confirmed`로 되살리기(실패하면 같은 내용으로 새로 만들기), Apple은 같은 내용으로 새로 만들기(id가 바뀜) [임시].
  - 반복: §12.8 범위 대화(선택지 앞에 제목 `반복 일정 삭제`). **되돌리기 토스트 없음** — 대화가 확인을 대신한다 [sprout].
  - 참석자가 있는 일정(내가 주최자): 지우기 전에 확인 `참석자에게도 일정이 취소돼요. 삭제할까요?` / `취소` · `삭제`(빨강).
- **⌘Z**: 옮기기·길이·고치기는 토스트 없이 저장하고 ⌘Z로 되돌린다(06 §7.2 규칙). 되돌리기도 **한 번 더 쓰기**라서 실패할 수 있다 → 실패하면 토스트 `되돌리지 못했어요. 구글 캘린더에서 확인해 주세요.` 반복 범위를 고른 변경은 ⌘Z 대상이 아니다(되돌리기 목록에 넣지 않음) [sprout].

### 12.7 저장 흐름 — 낙관적 반영 · 바로 쓰기 · 실패 시 되돌림
1. 렌더러가 IPC `calendars:write`(아래 §12.10)를 부른다.
2. 메인은 **캐시(`ext_events`)를 먼저 바꾸고** `calendars:changed`를 보내 화면에 바로 그린다. 바꾸기 전 행을 `ext_ops`에 적어 둔다.
3. 바로 구글 API·EventKit 도우미에 쓴다(시간 제한: 구글 15초, 도우미 20초).
4. 성공: 응답(구글 이벤트 전체, Apple 도우미 결과)으로 캐시 행을 갈아 끼우고(새 `etag`·`updated`·id), `ext_ops`의 그 줄을 지운다.
5. 실패: 캐시를 바꾸기 전 행으로 되돌리고 화면 다시 그림 + 토스트:
   | 경우 | 토스트 |
   |---|---|
   | 오프라인·시간 초과 | `인터넷에 연결되어 있지 않아 저장하지 못했어요` |
   | 401 → 리프레시 실패(`invalid_grant`) | `구글 계정을 다시 연결해 주세요` + 계정 `reauth`(v1 §3.2) |
   | 403 `insufficientPermissions` | §12.3.2 대화 |
   | 403 `forbidden`·`requiredAccessLevel`(캘린더 권한이 보기로 바뀜) | `이 캘린더는 이제 보기만 할 수 있어요` + 그 캘린더 `access_role` 다시 받기 |
   | 404·410(이미 지워짐) | `이미 삭제된 일정이에요` + 캐시에서 지움 |
   | 412 Precondition Failed(먼저 바뀜) | §12.9 |
   | 429·5xx | 한 번만 1~2초 뒤 다시 시도, 그래도 실패면 `구글이 잠시 응답하지 않아요. 다시 시도해 주세요.` |
   | Apple 도우미 오류(권한 꺼짐·캘린더 사라짐) | `캘린더 앱에 저장하지 못했어요` + v1 §11.2 상태 다시 확인 |
   - 토스트는 06 토스트와 같은 자리·모양, 4초. 만들기 실패는 토스트 대신 팝오버를 다시 연다(§12.4.1).
6. 앱이 3~4 사이에 꺼지면: 다음에 켤 때 `ext_ops`에 남은 줄은 **되돌리고**(캐시를 전 행으로) 그 계정을 즉시 새로 고침 — 실제로 쓰였으면 새로 고침이 다시 가져온다. 오프라인 대기열이 아니므로 다시 보내지 않는다 [sprout, ⑫].
- 쓰는 동안 그 일정 막대는 보통 모양 그대로(회전 표시 없음). 1초가 넘게 걸리면 팝오버 아래 줄에 작은 회전만 [임시].
- 같은 일정에 쓰기가 겹치면(끌고 바로 또 끎) 앞 쓰기가 끝난 뒤 뒤 쓰기를 보낸다(일정마다 줄 세우기). 뒤 쓰기는 앞 쓰기 응답의 `etag`를 쓴다.

### 12.8 반복 일정 범위 [틱틱 할 일 대화창 모양 — 선택지는 임시, Q3]
- 반복 일정의 회차를 **고치거나(제목·시간·장소·설명·끌기·길이) 지울 때** 가운데 작은 대화(폭 360, 06 확인 대화와 같은 틀):
  ```
  반복 일정 편집                     ← 지울 때 "반복 일정 삭제"
  반복 일정의 시간을 바꾸고 있어요. 바꿀 범위를 골라 주세요.   ← 틱틱 editing_repeat_msg를 일정으로
  [ 이 일정만 ]
  [ 이후 모든 일정 ]
  [ 모든 일정 ]
  취소
  ```
  - 버튼은 세로로 같은 폭(틱틱 할 일 대화창처럼 선택지가 줄마다). Esc·`취소` = 아무것도 바꾸지 않고 원래 자리.
  - 첫 회차를 고칠 때는 `이후 모든 일정`과 `모든 일정`이 같으므로 `모든 일정`만 보인다.
  - 이미 "이 일정만"으로 바뀐 회차(구글 예외 회차·Apple detached)는 대화 없이 그 회차만 고친다 [임시].
- 구글 동작:
  | 범위 | 호출 |
  |---|---|
  | 이 일정만 | 그 회차 id(`<원본id>_<원래 시작>`)에 `events.patch`. 지우기 = 그 회차 id에 `events.delete` |
  | 모든 일정 | 원본(`recurringEventId`)에 `events.patch`. 시간을 옮겼으면 원본 `start`·`end`를 **같은 만큼 이동**(회차 하나를 2시간 늦췄으면 원본도 2시간). 지우기 = 원본 `events.delete` |
  | 이후 모든 일정 | ① 원본 RRULE에 `UNTIL = 그 회차 시작 − 1초`로 원본을 끊고 ② 그 회차부터 같은 규칙(바뀐 값 반영)으로 **새 반복 일정**을 `events.insert`. 지우기 = ①만. ②가 실패하면 ①을 되돌린다 |
- Apple 동작: `이 일정만` = `save(event, span: .thisEvent)`, `이후 모든 일정` = `.futureEvents`, `모든 일정` = 첫 회차(`occurrenceDate` 가장 이른 것)를 찾아 그 회차에 같은 변경을 시간 차이만큼 적용해 `.futureEvents`. 지우기도 같은 span으로 `remove`.
- 반복 일정은 캐시에 회차로 펼쳐 들어 있으므로(v1 §5.3), 범위 쓰기 뒤에는 **그 캘린더를 증분 새로 고침**해서 회차를 다시 받는다(화면은 그 사이 고친 회차만 낙관적으로).
- **Q4 참석자 알림**: 내가 주최자이고 다른 참석자가 있는 일정을 고치거나 지울 때 — 제안: 구글 기본처럼 저장 전에 `참석자에게 변경 내용을 이메일로 알릴까요?` / `보내지 않기` · `보내기`(구글 `sendUpdates` = `none` / `all`). Apple은 EventKit이 참석자 알림을 조절하지 못해 서버(iCloud·Exchange)가 정한 대로 간다 → 대화 없음.

### 12.9 다른 곳에서 바뀐 일정 (충돌)
- 구글: 모든 고치기·지우기에 **`If-Match: <캐시의 etag>`**. 412가 오면 그 일정을 `events.get`으로 다시 받아 캐시를 갈아 끼우고, 화면의 낙관적 변경은 버린다 + 토스트 `다른 곳에서 먼저 바뀐 일정이라 최신 내용으로 바꿨어요. 다시 고쳐 주세요.` 지우기에서 412면 지우지 않는다(같은 토스트).
- Apple: 도우미가 쓰기 전에 그 일정의 `lastModifiedDate`를 캐시 값과 비교, 다르면 쓰지 않고 `conflict`로 답한다 → 위와 같은 처리.
- 팝오버를 연 채 새로 고침이 그 일정을 바꾸면: **지금 입력 중인 칸은 덮지 않는다.** 다른 칸만 새 값으로 바꾸고, 저장할 때 412 규칙을 따른다. 그 사이 일정이 지워졌으면 팝오버를 닫고 토스트 `다른 곳에서 삭제된 일정이에요`.
- 끄는 도중 새로 고침이 오면 끌기가 끝날 때까지 그 일정의 갱신을 미룬다.
- 쓰기 직후 바로 다음 증분 새로 고침이 같은 변경을 돌려준다 — `etag`가 같으면 건너뛴다(깜빡임 없음).

### 12.10 데이터·모듈 (기기 전용 캐시 — 동기화 스키마는 여전히 건드리지 않는다)
- `packages/schema`·Postgres·PowerSync·`view_settings`에 바뀌는 것 없음(v1 §5 원칙 유지). 대상 캘린더 기억은 localStorage.
- 캐시 DB(`userData/calendars/cache.db`) 추가:
  | 테이블 | 더하는 칸 |
  |---|---|
  | `ext_accounts` | `can_write`(0/1 — 구글은 토큰 `scope`, Apple은 늘 1) |
  | `ext_calendars` | `writable`(0/1, §12.2 캘린더 단위 판정), `is_default`(Apple 새 일정 기본 캘린더) |

#### 12.10.1 Apple 도우미 `sprout-calendar` 새 명령
| 명령 | 입력 | 출력 |
|---|---|---|
| `create` | 표준 입력 JSON `{calendarId, title, notes, location, start, end, allDay, timeZone, rrule?}` | `{"event": {…events 출력과 같은 모양 + modifiedAt, occurrenceDate}}` |
| `update` | `{id, occurrenceDate, span: "this"|"future", expectModifiedAt, patch:{…}, calendarId?}` | `{"event": …}` 또는 `{"error":"conflict"|"notFound"|"readonly"}` |
| `delete` | `{id, occurrenceDate, span, expectModifiedAt}` | `{"ok":true}` 또는 위 오류 |
- `events` 출력에 `modifiedAt`(`lastModifiedDate`), `occurrenceDate`, `organizerIsMe`, `hasAttendees`, `rrule`(첫 규칙의 iCalendar 글자), `allowsModify`(캘린더)를 더한다. `calendars` 출력에 `isDefault`(`defaultCalendarForNewEvents`).
- 쓰기는 `store.save(_:span:commit: true)` / `store.remove(_:span:commit: true)`. 회차 찾기는 `eventIdentifier`로 찾은 뒤 `occurrenceDate`가 같은 회차를 그날 범위 `predicateForEvents`로 고른다.
- 입력은 명령줄 대신 **표준 입력 JSON**(제목·설명에 아무 글자나 들어가므로). 도우미 시간 제한 20초 그대로.
- 쓴 뒤 EventKit 변경 알림(`EKEventStoreChanged`)을 기다리지 않고, 메인이 그 캘린더를 다시 읽는다.

### 12.13 구글 앱 검증(심사)에 주는 영향
- `calendar.events`도 **민감 범위**라 등급은 v1과 같다(제한 범위가 아니라 CASA 보안 평가 없음). 하지만 **범위가 바뀌면 검증을 다시(또는 처음부터 새 범위로) 받아야 한다** — 아직 검증 전이면 처음부터 새 범위로 내는 것이 낫다.
- 제출할 것에 더해지는 것: ① 범위 사용 이유 — "이용자가 꿈틀 캘린더 화면에서 직접 만들거나 고친 일정을 그 이용자의 구글 캘린더에 저장한다. 다른 목적의 쓰기는 없다" ② 시연 영상에 **쓰기 장면**(빠른 만들기에서 구글 캘린더를 골라 만들기 → 구글 캘린더 웹에 나타남, 끌어 옮기기, 삭제) ③ 동의 화면 데이터 액세스에 `calendar.events` 추가하고 `calendar.events.readonly` 빼기.
- "테스트" 상태(결정 ①)에서는 지금처럼 등록한 테스트 사용자만 쓴다. 범위 바꾼 뒤 테스트 사용자는 §12.3.2 대화로 한 번 더 허용.
- 처리방침의 제한적 사용 문장(§12.12)이 검증 전에 사이트에 올라가 있어야 한다.

### 12.15 완료 기준 (틱틱과 나란히 놓고 확인)
- [ ] 새로 구글을 연결하면 동의 화면 권한이 "캘린더 목록 보기"·"모든 캘린더의 일정 보기 및 수정" 두 가지다.
- [ ] v1로 연결해 둔 계정은 업데이트 뒤에도 일정이 그대로 보이고, 처음 고치려 할 때만 `구글 캘린더에 쓰기 권한이 필요해요` 대화가 뜬다. `허용하기` 뒤 하려던 끌기가 그대로 저장된다. `나중에`면 아무것도 바뀌지 않는다.
- [ ] 빠른 만들기 `일정`의 캘린더 고르기에 내 일정·구글(계정별)·Apple(출처별) 중 **고칠 수 있고 보이는** 캘린더만 있고, 휴일·생일·보기 전용 캘린더는 없다. 다음에 열면 마지막에 고른 캘린더가 기본이다.
- [ ] 구글 캘린더를 골라 만든 일정이 바로 그 캘린더 색으로 그려지고, 구글 캘린더 웹에 같은 제목·시간·장소·설명으로 나타난다. 종일 일정이 하루 더 길게 생기지 않는다.
- [ ] 사이드바 "구독 캘린더" 계정 목록 위 `"<이메일>"에 일정 추가` 바에 "내일 3시 치과"를 넣으면 그 계정 기본 캘린더에 내일 15:00–16:00 일정이 생긴다(틱틱 research 31 §2와 같은 자리).
- [ ] 고칠 수 있는 구글·Apple 일정을 끌어 옮기고·길이를 바꾸면 구글 웹·맥 캘린더 앱에 반영되고, ⌘Z로 되돌리면 그쪽도 돌아간다.
- [ ] 팝오버에서 제목·시간·종일·장소·설명을 고치고 바깥을 누르면 저장된다. 🗑 삭제 → 토스트 ⟲로 되살아난다.
- [ ] 휴일 캘린더·남이 초대한 일정·Apple 구독(ICS) 일정은 v1처럼 끌어도 아무 일이 없고, 팝오버 맨 아래에 읽기 전용 이유가 한 줄 보인다.
- [ ] 반복 일정 회차를 끌어 놓으면 `이 일정만 / 이후 모든 일정 / 모든 일정` 대화가 뜨고, 고른 대로 구글 웹·맥 캘린더 앱에 반영된다. `취소`면 원래 자리. 첫 회차에서는 `모든 일정`만 보인다.
- [ ] 구글 웹에서 일정 제목을 바꾼 뒤(꿈틀 새로 고침 전) 꿈틀에서 같은 일정을 끌면 412 → 최신 내용으로 바뀌고 토스트가 뜬다. 내 변경으로 구글 쪽 변경을 덮어쓰지 않는다.

- [ ] `packages/schema`·서버 마이그레이션·`view_settings`에 바뀐 것이 없다(`git diff`). 렌더러에서 토큰·etag 문자열을 찾을 수 없다.

| Q5 | **기존 연결(읽기 전용) 처리** — 업데이트 때 모두 다시 연결 / 처음 고칠 때만 허용 묻기 | **처음 고칠 때만**(§12.3.2) | 읽기만 쓰는 사람은 아무것도 안 해도 된다. 테스트 상태라 어차피 7일마다 다시 연결하므로 그때 새 범위로 바뀐다 |

## 부록 A. 사용자가 할 일 (구글 클라우드 — 코드로 대신할 수 없음)
1. https://console.cloud.google.com 에 본인 구글 계정으로 로그인 → 위쪽 프로젝트 선택 › **새 프로젝트**(이름 예: `sprout`) 만들기.
2. **API 및 서비스 › 라이브러리**에서 "Google Calendar API" 검색 → **사용 설정**.
3. **Google Auth Platform(OAuth 동의 화면) › 시작하기**: 앱 이름 `sprout`(가칭), 사용자 지원 이메일 = 본인 이메일, 대상 **외부(External)**, 개발자 연락처 = 본인 이메일 → 만들기.
4. **대상(Audience)**: 게시 상태가 **테스트**인지 확인 → **테스트 사용자 › 사용자 추가**에 구글 캘린더를 연결할 본인 구글 계정(들)을 넣는다(최대 100명).
5. **데이터 액세스 › 범위 추가**: `.../auth/calendar.calendarlist.readonly`, `.../auth/calendar.events.readonly` 두 개만 체크 → 저장(민감한 범위로 표시되는 것이 정상).
6. **클라이언트 › 클라이언트 만들기**: 애플리케이션 유형 **데스크톱 앱**, 이름 `sprout desktop` → 만들기. 나오는 **클라이언트 ID**와 **클라이언트 보안 비밀번호**를 복사한다. (구글은 데스크톱 클라이언트의 토큰 교환에도 이 비밀값을 요구한다. 설치형 앱에서는 비밀로 취급되지 않으며 보안은 PKCE가 맡는다. 그래도 저장소에는 커밋하지 않는다.)
7. 앱 실행 때 넣기(지금): 
   ```bash
   cd apps/desktop && . ../../scripts/node22.sh && GOOGLE_CLIENT_ID=<클라이언트 ID> GOOGLE_CLIENT_SECRET=<비밀값> npx electron-vite dev
   ```
   이후 패키지 앱에서는 빌드할 때 같은 두 값을 넣어 앱 설정 파일로 묶는다 [다음 — 패키징 단계에서]. 값이 없으면 설정 › 연동에 `구글 연결 준비가 아직 안 됐어요…` 안내가 뜨고 연결 버튼이 비활성이다.
8. 테스트 상태에서는 **7일마다 "다시 연결이 필요해요"**가 뜨는 것이 정상이다(구글 정책).
9. **공개 출시 전 검증(심사)**: Google Auth Platform › 인증 센터에서 제출. 필요: 제품명 확정, 내 도메인의 **홈페이지**와 **개인정보 처리방침** 주소(구글 일정은 이 기기에만 저장하고 서버·AI로 보내지 않는다는 문장 — "제한적 사용" 조건), 서치 콘솔로 도메인 소유 확인, 연결 과정과 일정이 보이는 화면을 찍은 **시연 영상**(유튜브 링크), 범위마다 쓰는 이유. 보통 며칠~몇 주. 제한(restricted) 범위가 아니라 외부 보안 평가(CASA)는 필요 없다.

## 부록 B. 사용자가 할 일 (Apple 캘린더)
1. 맥 **캘린더 앱**에 보고 싶은 계정(iCloud·구글·Exchange 등)이 이미 등록돼 있으면 따로 할 일은 없다.
2. sprout 설정 › 연동 › `+ 캘린더 추가` › Apple 캘린더 → macOS 권한 창에서 **허용**.
3. 개발 실행에서 권한 창이 뜨지 않고 바로 "접근이 꺼져 있어요"가 되면 §11.4 개발 실행 주의대로 패키지 앱으로 확인하거나 시스템 설정에서 Electron을 켠다.
4. 배포 빌드는 하드닝 런타임 entitlement와 Info.plist 문구가 들어가 있어야 권한 창이 뜬다(electron-builder.yml·entitlements에 반영함).
