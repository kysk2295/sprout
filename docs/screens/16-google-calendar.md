## 0-2. v2 결정 — 양방향(쓰기) (2026-10-05 **확정** — 사용자 답 "1. 틱틱처럼 해주고 … 3. 틱틱처럼 해줘 / 4. 괜찮아")
사용자 요청(2026-10-05): "애플이랑 구글캘린더가 양방향으로 틱틱처럼 되야하는데 이것도 구현해줘". 근거 조사 [research 31](../ticktick-research/31-calendar-two-way.md). 사용자가 말한 "양방향"의 뜻(2026-10-05): **① 온보딩 캘린더 단계(18)와 설정 › 연동에서 연결할 때부터 쓰기까지 되는 연결이고 ② 앱에서 만들거나 고친 일정은 꿈틀에도 저장되고(휴대폰까지 동기화) 연결한 캘린더에도 저장된다.**
| # | 질문 | 확정 |
|---|---|---|
| ⑦ | 무엇을 양방향으로 (Q1 "틱틱처럼") | 틱틱 결과와 같게: **쓸 수 있는 캘린더는 양방향**. 구글 + Apple(맥 캘린더 앱에 등록된 iCloud·구글·Exchange·CalDAV 중 `allowsContentModifications`가 참인 캘린더 — 틱틱의 iCloud 양방향과 같은 결과). 쓸 수 없는 캘린더는 읽기 전용 그대로(§12.2) |
| ⑧ | 어떤 캘린더를 고칠 수 있나 | 구글 `accessRole` = `owner`·`writer`, Apple `allowsContentModifications` = 참. 휴일·공유 보기 전용·생일·구독(ICS)·근무 위치·부재중·집중 시간·Gmail에서 온 일정·**내가 주최자가 아닌 초대 일정**은 읽기 전용(§12.2) |
| ⑨ | 구글 권한 (Q5 추천대로) | 범위 `calendar.events.readonly` → **`calendar.events`**(+ `calendar.calendarlist.readonly`). **새 연결(온보딩·설정)은 처음부터 쓰기 권한**을 받는다. v1으로 이미 연결한 계정은 읽기는 그대로 되고, **처음 고치거나 그 계정 캘린더를 고를 때** "쓰기 권한 허용" 대화(증분 동의) |
| ⑩ | 앱에서 만든 일정은 어디에 | **양쪽에 저장 — "연결된 일정"(§12.0).** 꿈틀 `events` 행(휴대폰까지 동기화) + 고른 구글·Apple 캘린더의 일정. 꿈틀 행에 연결 정보(공급자·계정·캘린더·외부 id·etag·수정 시각)를 둔다. 같은 일정이 두 번 보이지 않게 기기 캐시의 사본은 숨긴다 |
| ⑪ | 만들 때 기본 캘린더 (Q2 추천대로) | 빠른 만들기 `일정`의 아래 왼쪽 "● 내 일정"을 **캘린더 고르기**로. 기본값 = **이 기기에서 마지막으로 고른 캘린더** |
| ⑫ | 반복 범위 (Q3 "틱틱처럼") | 맥 TickTick.app에는 **일정용 반복 범위 대화가 없다**(문자열·화면 파일 확인 — research 31 §4). 틱틱 **할 일** 대화의 말을 일정에 맞춰 쓴다: 제목 `반복 일정 편집`/`반복 일정 삭제`, 선택지 **`이번 회차만`(Only This Recurrence) · `이후 모든 회차`(All Future Recurrences) · `모든 회차`**(틱틱 세 번째 `All Unfinished Recurrences`를 완료가 없는 일정에 맞춘 것) — §12.8 |
| ⑬ | 참석자 메일 (Q4 "괜찮아") | 내가 주최자이고 다른 참석자가 있는 일정을 고치거나 지울 때 **매번 묻는다**(`보내지 않기` / `보내기`) |
| ⑭ | 저장 흐름 | **연결된 일정**: 꿈틀에 먼저 저장 → 데스크톱이 다리가 되어 구글·EventKit에 올린다(휴대폰에서 고친 것도 동기화로 데스크톱에 와서 올라간다. 데스크톱이 꺼져 있으면 기다린다). **캐시에만 있는 외부 일정**(구글·Apple에서 직접 만든 것): 꿈틀로 가져오지 않고, 데스크톱에서 화면 먼저 바꾸고 바로 쓴다 — 실패하면 되돌리고 토스트, 구글은 오프라인이면 막는다 |
| ⑮ | 충돌 | 양쪽이 다 바뀌었으면 **나중에 고친 쪽(수정 시각)이 이긴다** + 토스트. 캐시 전용 일정은 구글 etag 412 / Apple 수정 시각으로 막고 최신으로 바꾼다 |
| ⑯ | 휴대폰 | 연결된 일정은 휴대폰에 **꿈틀 일정으로** 보이고 고칠 수 있다(올리는 것은 데스크톱). 휴대폰에서 외부 캘린더를 직접 연결하는 것은 [다음] → **2026-10-05 열림: 휴대폰은 자기 OS 캘린더(휴대폰에 추가한 구글·iCloud 등)를 OS 권한으로 연결한다 — [38](38-mobile-calendars.md)** |

## 2. 레이아웃
### 2.1 설정 › 연동 [틱틱 위치, sprout 문구]
설정 창(현재 `DesktopSettings`: 계정 · 스마트 목록 · 외관 · 단축키)에 **"연동"** 탭을 더한다(틱틱 "연동 & 가져오기"). 아이콘 = 플러그 선 아이콘.
```
연동
┌ 캘린더 ───────────────────────────────────────────┐
│ 다른 캘린더를 sprout에 구독해요.        + 캘린더 추가 │  ← 강조색 글자 버튼
│ ▭ me@gmail.com      5분 전에 동기화           편집 │  ← 계정 행(연결 뒤)
│ ▭ work@company.com  다시 연결이 필요해요   다시 연결 │  ← 오류 행(빨강 글자)
└───────────────────────────────────────────────────┘
구글 일정은 읽기 전용이에요. sprout에서 구글 일정을 바꾸지 않고, 일정은 이 기기에만 저장돼요.   ← 캡션 11, 3차 글자색 (→ v2 §12.11에서 문구 바뀜)
```
- 카드·행은 기존 `settings-card`·`settings-row`(00 `color.bg.card`) 그대로. 행 높이 44, 계정 이메일 13 본문색, 상태 글자 12 `color.text.tertiary`.
- "+ 캘린더 추가" → 작은 메뉴: **구글 캘린더** · **Apple 캘린더**(맥에서만, §11)(다른 서비스는 [다음], 메뉴에 넣지 않음). 틱틱의 "구독 / 통합" 고르기 모달은 거치지 않고 바로 연결(§4.1) [cal-subscription NOTES 결정].
- 틱틱의 "방해 금지(구독 일정 알림 끄기)" 토글은 두지 않는다 — sprout v1은 구글 일정 알림을 보내지 않는다 [sprout].

### 2.2 계정 편집 모달 [틱틱 로컬 캘린더 모달 모양 — 구글은 [임시]]
```
          me@gmail.com                    ⋯     ← 제목 = 이메일, ⋯ = 지금 새로 고침 · 연결 끊기
 내 캘린더
 ┌ ● me@gmail.com              보이기 ⌃⌄ ┐
 │ ● 운동                      보이기 ⌃⌄ │
 └ ● 가족                      숨기기 ⌃⌄ ┘
 다른 캘린더
 ┌ ● 대한민국의 휴일            보이기 ⌃⌄ ┐
 └ ● 팀 공유 캘린더             숨기기 ⌃⌄ ┘
                         [ 취소 ] [ 확인 ]
```
- 가운데 모달 440 폭(06 옵션 보기 모달과 같은 틀), 높이는 내용에 맞추고 최대 화면 80%에서 안쪽 스크롤.
- 묶음: **내 캘린더**(구글 `accessRole = owner`) / **다른 캘린더**(그 외: 구독·공유·휴일). 각 행 = 캘린더 색 점 8 + 이름(구글의 `summaryOverride` 우선) + 오른쪽 선택.
- 선택지 v1: **보이기 / 숨기기**. 틱틱의 "캘린더에서만 보이기"는 스마트 리스트에 구글 일정을 넣는 기능과 짝이라 [다음].
- 확인을 눌러야 반영(틱틱 Cancel/Confirm). Esc = 취소.
- 색 바꾸기는 없다 — 구글에서 정한 캘린더 색을 그대로 쓴다 [임시].

### 2.3 캘린더 화면 (06에 더하는 것)
| 위치 | 바뀌는 것 |
|---|---|
| 머리글 `...` › **캘린더 구독** | 지금 비활성 → 활성. 누르면 설정 › 연동 탭을 연다 [틱틱 17 §1] |
| 왼쪽 패널 `› 캘린더 구독` | 지금 안내 문구("다음 단계에서 붙어요") → 펼치면 **계정 이름 줄(작은 회색 글자) + 그 아래 캘린더 행**(색 칸 체크 + 이름). 그룹 체크칸 = 구독 캘린더 전부 켜기/끄기. 계정이 없으면 강조색 글자 행 **"구글 캘린더 연결"** → §4.1 [틱틱 모양 17 §8, 문구 sprout] |
| 주·일·월 그리드 | 구글 일정이 태스크와 같은 막대·블록으로 겹쳐 그려진다(§3) |
- 설정의 "숨기기"는 모든 곳에서 숨김, 왼쪽 패널 체크는 **캘린더 보기에서만** 잠깐 거르는 필터다. 숨긴 캘린더는 왼쪽 패널에 나오지 않는다 [임시].
- 왼쪽 패널 체크는 리스트·태그 필터와 **따로 논다**: 리스트·태그를 골라도 구글 일정은 구독 체크만 따른다 [임시].

### 2.4 사이드바 "구독 캘린더" (G2 — 결정 ②) [틱틱 19 §4]
- 01 §4.1 순서대로 Tags 아래 **"구독 캘린더"** 구역. 계정이 있을 때만 보인다. 행 = 캘린더 아이콘 + 이메일 + 오른쪽 **앞으로 3개월 일정 개수**(0이면 숨김, 01 §4.2 규칙).
- 소제목에 마우스를 올리면 `+` → "구글 캘린더" 메뉴(§2.1과 같음).
- 계정 행을 누르면 가운데 목록: 머리 제목 = 이메일(02 머리 규칙), **추가 바 없음**, 그룹 **오늘 / 다음 7일 / 나중에**(나중에 기본 접힘), 앞으로 3개월. 행 = 작은 캘린더 아이콘(체크박스 자리, 누를 수 없음) + 제목 + 오른쪽 날짜(02 날짜 색 규칙). 행 왼쪽 2pt 캘린더 색 줄.
- 행을 누르면 오른쪽 상세 자리에 §3.3 팝오버와 같은 내용을 읽기 전용으로.
- 빈 상태: 02 빈 상태 틀 + **"앞으로 3개월 동안 일정이 없어요."** [틱틱 "It's all clear in the next 3 months." 번역].

### 3.4 연결 진행 모달 [sprout]
- 작은 모달 360: 제목 `구글 캘린더 연결` / 본문 `브라우저에서 구글 로그인과 권한 허용을 마쳐 주세요.` / 회전 표시 / 아래 `링크 다시 열기`(텍스트 버튼) · `취소`.
- 성공: 모달 닫힘 → 설정에 계정 행 + 토스트 `구글 캘린더를 연결했어요`. 첫 동기화가 끝나면 캘린더에 일정이 나타난다.
- 실패 문구(모달 안 빨강 줄 + `다시 시도`):
  | 경우 | 문구 |
  |---|---|
  | 브라우저에서 거부·창 닫음(`access_denied`) | `연결을 취소했어요.` |
  | 5분 동안 응답 없음 | `시간이 지나서 연결을 멈췄어요.` |
  | 일정 권한 체크를 뺌 | `일정을 읽는 권한이 있어야 연결할 수 있어요.` |
  | 테스트 모드에서 등록 안 된 계정(`access_denied`/403 `org_internal`·`access_not_configured`) | `이 구글 계정은 아직 쓸 수 없어요. 운영자에게 테스트 사용자 등록을 요청해 주세요.` [임시 — 결정 ①] |
  | 이미 연결한 계정 | 새 행을 만들지 않고 그 계정 토큰만 바꾼다 + `이미 연결된 계정이라 다시 연결했어요.` |
  | 인터넷 없음 | `인터넷에 연결되어 있지 않아요.` |
- 브라우저 쪽 돌아오는 페이지(로컬 주소): 흰 바탕 가운데 글자 `sprout로 돌아가 주세요. 이 창은 닫아도 돼요.`(실패 시 `연결하지 못했어요. sprout에서 다시 시도해 주세요.`). 외부 이미지·스크립트 없음.

## 5. 데이터 — **동기화 스키마는 건드리지 않는다**
- `packages/schema`·Postgres·PowerSync 동기화 규칙에 **아무것도 더하지 않는다.** 서버 마이그레이션 없음. `view_settings.options_json`(동기화됨)에도 구글 캘린더 id를 넣지 않는다 — 캘린더 id가 이메일 주소 모양이라 서버로 가면 안 된다.
- 구글 일정은 `tasks`가 아니다: XP 없음, 리스트·스마트 리스트 개수에 안 들어감, AI 비서·주간 리포트 입력에 안 들어감(결정 ④), 검색(⌘K)에도 v1은 안 들어감 [임시].
- 01 §데이터의 "기기에만 저장 `calendar_accounts`" 항목을 아래 구조로 구체화한다.

| `ext_meta` | `time_zone`(캐시를 만든 기기 시간대) |
- 시각은 받을 때 **기기 시간대의 floating 시각**으로 바꿔 저장해 06의 `CalItem`(floating)과 같은 계산을 쓴다. 기기 시간대가 바뀌면 캐시 일정 전체를 지우고 다시 받는다.
- 0시에 끝나는 시각 일정(예: 22:00–24:00)은 끝을 전날 23:59로 저장해 하루짜리 블록으로 그린다(여러 날 막대로 번지지 않게) [sprout].
- 렌더러에는 `CalItem`에 `ext`(일정 정보)를 붙인 읽기 전용 모양으로 넘기고, 06의 배치·겹침 계산에 함께 넣는다.

### 5.3 저장 범위·양
- 범위: **오늘 − 6개월 ~ 미래 전부**(결정 ⑥). 반복 일정은 구글이 회차로 펼친 것(`singleEvents=true`)을 받는다.
- 캘린더당 일정 상한 5,000개(넘으면 가장 먼 미래부터 버림) [임시]. 끝없는 반복이 많아 상한에 걸리면 `singleEvents=false` + 로컬 펼치기로 바꾼다(§9 위험).
- 하루에 한 번, 범위 밖(6개월보다 오래된) 일정을 지운다.

## 7. 기술
### 7.1 OAuth: 설치형 앱 흐름 + PKCE + 루프백 (메인 프로세스)
1. 메인에서 `code_verifier`(무작위 43~128자, base64url) → `code_challenge = BASE64URL(SHA256(verifier))`, `state`(무작위) 생성.
2. `http://127.0.0.1:<빈 포트>`에 **127.0.0.1에만** 묶은 임시 HTTP 서버를 연다(포트 0 → 운영체제가 고름). 경로 `/oauth/callback` 하나만 받는다.
3. `shell.openExternal`로 `https://accounts.google.com/o/oauth2/v2/auth?client_id=…&redirect_uri=http://127.0.0.1:<port>/oauth/callback&response_type=code&scope=<§7.2>&code_challenge=…&code_challenge_method=S256&state=…&access_type=offline&prompt=consent` 를 연다. 앱 안 웹뷰로 열지 않는다(구글이 내장 웹뷰 로그인을 막는다).
4. 돌아온 요청에서 `state` 확인 → §3.4 돌아오는 페이지 응답 → 서버 닫기. 5분 안에 안 오면 닫고 실패.
5. `https://oauth2.googleapis.com/token`에 `code` + `code_verifier` + `client_id` (+ 데스크톱 클라이언트가 받는 `client_secret`. 구글 문서상 설치형 앱의 비밀값은 비밀로 취급되지 않는다 — 앱에 넣어 배포해도 되지만 그것만으로 보안이 되지는 않고, 보안은 PKCE가 맡는다)로 교환.
6. 응답의 `scope`를 확인해 §7.2 두 범위가 모두 있어야 성공(사용자가 동의 화면에서 일부만 체크할 수 있다).
7. 계정 이메일은 `calendarList`의 기본 캘린더 id에서 얻는다 → **`openid`·`email` 범위를 따로 받지 않는다.**
8. 토큰 저장(§7.5) → 첫 동기화 시작.
- 렌더러·preload는 인증 코드·토큰을 보지 않는다. 루프백 서버는 흐름이 끝나면 반드시 닫는다.

### 7.2 범위 — 가장 좁게
| 범위 | 왜 |
|---|---|
| `https://www.googleapis.com/auth/calendar.calendarlist.readonly` | 캘린더 목록·이름·색·기본 캘린더(=이메일)·`selected` |
| `https://www.googleapis.com/auth/calendar.events.readonly` | 모든 캘린더의 일정 읽기 |
- `calendar.readonly` 하나로도 되지만 그 범위는 캘린더 설정·공유(ACL) 읽기까지 포함한다 → **나눠진 두 범위가 더 좁다.** 쓰기 범위(`calendar`, `calendar.events`)는 받지 않는다. (→ v2 §12.3에서 `calendar.events.readonly`를 `calendar.events`로 바꾼다)
- `calendar.events.owned.readonly`는 내가 소유한 캘린더만 읽어서 휴일·공유 캘린더가 빠진다 → 쓰지 않는다.
- 두 범위 모두 구글 분류상 **민감(sensitive)** 이다(구글 클라우드 콘솔이 범위를 넣을 때 표시). **제한(restricted) 범위는 아니라서** 유료 외부 보안 평가(CASA)는 필요 없다.

### 7.3 구글 API 호출
- `GET calendar/v3/users/me/calendarList` (새로 고침 때마다 1번, `showHidden=false`) — 사라진 캘린더 정리, 새 캘린더는 숨기기로 추가 [임시].
- 캘린더마다 `GET calendar/v3/calendars/{id}/events`:
  - **처음(전체)**: `singleEvents=true`, `timeMin=오늘−6개월`, `maxResults=2500`, `eventTypes`로 `workingLocation` 제외 [임시], 페이지(`pageToken`) 끝까지 → 마지막 페이지의 `nextSyncToken` 저장.
  - **이후(증분)**: 같은 매개변수에서 `timeMin`만 빼고 `syncToken=…` (구글 규칙: `syncToken`과 `timeMin`·`timeMax`·`q`·`orderBy`·`updatedMin`은 같이 못 쓴다). `status=cancelled`인 항목은 캐시에서 지운다.
  - **410 Gone**(토큰 만료): 그 캘린더 캐시를 비우고 전체 다시.
- 접근 토큰 만료(401) → 리프레시로 갱신 1회 후 재시도. 리프레시가 `invalid_grant`면 `reauth` 상태(§3.2).

### 7.4 새로 고침 주기·한도
- 주기: §4.2(앞에 있을 때 5분, 뒤에 있을 때 30분, 깸·온라인 복귀·화면 진입 즉시, 1분 안의 중복은 건너뜀).
- 한 번의 새로 고침 = 계정당 `calendarList` 1회 + 보이는 캘린더 수만큼 `events` 1회(대부분 바뀐 것만, 1페이지). 숨긴 캘린더는 받지 않는다(다시 보이게 하면 그때 전체 받기).
- 구글 할당량은 프로젝트 전체·사용자별 분당 한도가 있다(콘솔 "할당량"에서 확인, 무료). 위 주기라면 사용자 1명이 분당 수 회라 여유가 크다. 429·`rateLimitExceeded`·5xx는 **지수 백오프**(1·2·4·8초 … 최대 5분) + 무작위 지연.
- 구글 푸시 알림(watch 채널)은 공개 HTTPS 주소가 필요해 데스크톱에 맞지 않는다 → [다음].

### 7.5 토큰 보관: `safeStorage` (keytar 아님)
- 앱은 이미 sprout 로그인 토큰을 **`safeStorage`로 암호화해 `userData/auth.bin`에** 둔다([main/sync.ts](../../apps/desktop/src/main/sync.ts)). AI 사용량 로그인([main/usageLogin.ts](../../apps/desktop/src/main/usageLogin.ts))은 토큰을 직접 보관하지 않고 각 CLI의 프로필 폴더(0700)에 맡긴다. → 구글도 **`safeStorage`** 로 맞춘다.
  - 맥에서 `safeStorage`의 암호화 키는 키체인 항목("sprout Safe Storage")에 있어 PRD의 "OS 키체인 보관"을 만족한다. `keytar`는 개발이 중단(보관 처리)되어 새로 들이지 않는다.
- **sync.ts와 다른 점 [sprout]:** `safeStorage.isEncryptionAvailable()`이 거짓이면 sync.ts는 평문으로 저장하지만, 구글 토큰은 **디스크에 쓰지 않고 메모리에만** 둔다(§3.2 마지막 줄). 파일 권한 0600.
- 패키징·서명 전후로 키체인 접근 주체가 바뀌면 맥이 한 번 묻거나 복호화에 실패할 수 있다 → 실패하면 `reauth` 상태로 처리(일정 캐시는 유지).
- 리프레시 토큰은 구글 계정·클라이언트당 100개 한도(넘으면 가장 오래된 것이 조용히 무효)라, 같은 계정을 다시 연결할 때 이전 토큰을 먼저 폐기한다.

### 7.6 사용자가 준비해야 하는 것 (코드로 대신할 수 없음)
1. **구글 클라우드 프로젝트**(무료) 만들기 → "Google Calendar API" 사용 설정.
2. **OAuth 동의 화면(Google Auth Platform)**: 사용자 유형 "외부", 앱 이름(**제품명 확정 필요** — 지금은 코드네임), 지원 이메일, 개발자 연락처. 게시하려면 + **앱 홈페이지 주소, 개인정보 처리방침 주소(내 도메인), 승인된 도메인**(서치 콘솔에서 소유 확인). 로고는 넣으면 로고 심사가 추가되니 처음엔 빼도 된다.
3. **데이터 접근**에 §7.2 두 범위 추가 + 왜 필요한지 설명 글.
4. **OAuth 클라이언트 ID — 유형 "데스크톱 앱"** 만들기 → 클라이언트 ID(와 비밀값)를 빌드 환경 변수로 넣는다(저장소에 커밋하지 않음).
5. **테스트 사용자**: 심사 전 "테스트" 상태에서는 이메일로 등록한 사람(최대 100명)만 연결된다. 이때 리프레시 토큰은 **7일 뒤 만료** → 일주일마다 "다시 연결이 필요해요"가 뜨는 게 정상이다.
6. **앱 검증(공개 출시 전)**: 쉬운 말로 — "구글 일정 읽기"는 민감한 권한이라, 모르는 사람이 쓰는 앱이 되려면 구글이 "이 앱이 일정을 어디에 어떻게 쓰는지" 직접 확인한다. 낼 것: 홈페이지·처리방침(구글 일정을 이 기기에만 저장하고 서버·AI로 보내지 않는다는 문장 — 구글 "API 서비스 사용자 데이터 정책"의 제한적 사용 조건), 연결 과정과 일정이 보이는 화면을 찍은 시연 영상(유튜브 링크), 범위별 사용 이유. 보통 며칠~몇 주. 검증 없이 "게시"하면 연결 때 **"Google에서 확인하지 않은 앱"** 경고가 뜨고 새 사용자 100명 한도.
- 위 1~5는 사용자가 구글 계정으로 직접 로그인해서 해야 한다. 순서상 PRD §8 "공개 주소(도메인)"와 제품명·처리방침이 6번의 선행 조건이다.

## 11. Apple 캘린더 (맥 캘린더 앱에 등록된 캘린더 읽기) [sprout — 틱틱 "Local Calendars"에 해당]
틱틱의 "Local Calendars"(research 19 §3)가 맥 캘린더 앱의 캘린더를 보여 주는 것과 같은 자리다. 맥 캘린더 앱에 이미 등록된 iCloud·Exchange·CalDAV·구독(ICS)·"이 Mac" 캘린더를 **읽기 전용**으로 겹쳐 본다. macOS에서만 보인다(Windows·웹 미리보기에는 메뉴 항목이 없다).

### 11.1 화면 (구글과 같은 컴포넌트, 다른 점만)
| 곳 | Apple |
|---|---|
| 설정 › 연동 `+ 캘린더 추가` 메뉴 | `구글 캘린더` · `Apple 캘린더`(맥) |
| 계정 행 | 캘린더 아이콘 + **"이 Mac의 캘린더"** · 상태 · `편집` (계정은 하나뿐 — 이미 있으면 메뉴 항목 비활성) |
| 편집 모달 | 제목 "이 Mac의 캘린더", 묶음 = **출처 이름**(iCloud · Exchange · 구독 · 이 Mac 등, EventKit `source.title`). 행 모양·보이기/숨기기·취소/확인은 §2.2와 같음. `⋯` = 지금 새로 고침 · 연결 끊기 |
| 왼쪽 패널·사이드바 | 계정 줄 이름 = "이 Mac의 캘린더". 계정이 없으면 `구글 캘린더 연결` 아래 `Apple 캘린더 연결` |
| 팝오버 맨 아래 | `캘린더 앱에서 열기 ↗`(`ical://ekevent/<id>?method=show&options=more`, 실패하면 캘린더 앱만 연다) [임시] |
| 연결 끊기 확인 본문 | `이 기기에 저장한 Apple 캘린더 일정이 지워져요. 캘린더 앱의 일정은 그대로예요. 접근 권한은 시스템 설정에서 끌 수 있어요.` |

### 11.2 권한 흐름
| 상태(EventKit) | 화면 |
|---|---|
| 처음(notDetermined) | 연결을 누르면 macOS 권한 창("sprout이(가) 캘린더에 접근하려고 합니다")이 뜬다. 연결 진행 모달 본문 `macOS 권한 창에서 "허용"을 눌러 주세요.` |
| 허용(fullAccess) | 계정 행 생성 + 첫 동기화. **처음 보이는 캘린더 = 전부**(생일 캘린더만 숨기기) [임시] |
| 거부(denied) / 쓰기만 허용(writeOnly) | 행 빨강 `캘린더 접근이 꺼져 있어요` + 버튼 `시스템 설정 열기`(개인정보 보호 및 보안 › 캘린더). 모달 실패 문구 `캘린더 접근을 허용해야 볼 수 있어요. 시스템 설정 › 개인정보 보호 및 보안 › 캘린더에서 sprout를 켜 주세요.` |
| 제한(restricted, 관리 정책) | 빨강 `이 Mac에서는 캘린더 접근이 제한돼 있어요` (버튼 없음) |
| 도우미 없음(개발 빌드에서 빌드 안 함) | 빨강 `캘린더 도우미가 없어요. 앱을 다시 설치해 주세요.` (개발: `npm run calendar:build`) |
- 권한은 macOS가 보관한다. sprout는 토큰을 저장하지 않는다. 로그아웃(결정 ⑤)은 Apple 계정 행과 캐시만 지우고 OS 권한은 그대로 둔다(다시 연결할 때 권한 창 없이 바로 됨).

### 11.3 데이터·새로 고침
- 범위: **오늘 − 6개월 ~ 오늘 + 2년**(EventKit 기간 검색은 한 번에 4년까지라 1년씩 나눠 묻는다). 반복 일정은 EventKit이 회차로 펼쳐 준다.
- 동기화 토큰이 없으므로 새로 고침마다 보이는 캘린더의 범위 일정을 통째로 받아 캘린더 단위로 갈아 끼운다(트랜잭션). 주기·창 앞/뒤·깸·1분 중복 건너뜀 규칙은 §4.2와 같다.
- 캘린더 색 = EventKit 캘린더 색(16진수). 시간대는 EventKit이 준 절대 시각을 기기 시간대 floating으로 바꾼다(§5.2와 같은 함수).
- 거절한 초대(참석자 중 나 = declined)는 그리지 않는다.

### 11.4 네이티브 도우미 `sprout-calendar` (apps/desktop/native/calendar/)
- 작은 Swift 명령줄 도구. 메인 프로세스가 `child_process.execFile`로 부르고 표준 출력 JSON을 읽는다(시간 제한 20초, 권한 창은 60초).
  | 명령 | 출력 |
  |---|---|
  | `status` | `{"status":"notDetermined|fullAccess|writeOnly|denied|restricted"}` |
  | `request` | 권한 요청(`requestFullAccessToEvents`, macOS 13 이하는 `requestAccess(to:.event)`) 뒤 같은 모양 |
  | `calendars` | `{"calendars":[{"id","title","color","source","sourceType","type","allowsModify"}]}` |
  | `events --from <ISO> --to <ISO> [--calendars id,id]` | `{"events":[{"id","calendarId","title","notes","location","url","start","end","allDay","timeZone","recurring","status","declined"}]}` (시각은 ISO 8601 UTC) |
- 빌드: `npm run calendar:build`(apps/desktop) → `native/calendar/out/sprout-calendar`. Info.plist(`NSCalendarsFullAccessUsageDescription`)를 바이너리에 넣는다(`-sectcreate __TEXT __info_plist`).
- 패키지 앱: electron-builder `extraResources`로 `Contents/Resources/sprout-calendar`. **앱 Info.plist에도 `NSCalendarsFullAccessUsageDescription`·`NSCalendarsUsageDescription`**(권한 창은 "책임 프로세스"인 sprout 앱 이름·문구로 뜬다) + 하드닝 런타임 entitlement `com.apple.security.personal-information.calendars`.
  - 문구: `sprout가 맥 캘린더 앱의 일정을 할 일과 함께 캘린더에 보여 주려고 읽어요. 일정은 이 Mac에만 저장되고 바꾸지 않아요.`
- **개발 실행 주의:** `electron-vite dev`에서는 권한을 묻는 주체가 **Electron.app**이다. Electron 기본 Info.plist에는 캘린더 사용 문구가 없어서 macOS가 권한 창 없이 바로 거부할 수 있다 → 개발 중 확인은 (가) 패키지 앱(`npm run dist:mac`)으로 하거나, (나) 시스템 설정 › 개인정보 보호 및 보안 › 캘린더에 Electron이 보이면 직접 켠다. 거부되면 화면은 §11.2 "접근이 꺼져 있어요"가 된다.
- 도우미 경로: 패키지 = `process.resourcesPath/sprout-calendar`, 개발 = `native/calendar/out/sprout-calendar`, 시험·확인용 덮어쓰기 = 환경 변수 `SPROUT_CALENDAR_HELPER`(가짜 도우미 스크립트).

### 11.5 온보딩 연결
- 렌더러 `data/calendars.ts`가 `connectCalendar('google' | 'apple')`(연결 진행 모달까지 띄우는 함수)과 `calendarProviders()`(이 기기에서 쓸 수 있는 공급자·준비 상태)를 내보낸다. 첫 실행 안내 화면(다른 명세)은 이 두 함수만 부른다.

### 12.0 연결된 일정 — 양쪽 저장
#### 12.0.1 꿈틀 `events`에 더하는 칸 (동기화 — 서버 마이그레이션 `server/db/migrations/20261012-events-ext.sql`)
| 칸 | 뜻 |
|---|---|
| `ext_provider` | `google` / `apple`. 비면 보통 꿈틀 일정 |
| `ext_account` | 기기 캐시의 계정 id(구글 `g_` + 이메일 해시 16자, Apple `apple`) — 이메일 자체는 올리지 않는다 |
| `ext_calendar` | 캘린더 id의 해시(`c_` + SHA-256 앞 16자). 구글 캘린더 id는 이메일 모양이라 서버에 그대로 올리지 않는다. 각 데스크톱이 자기 캐시의 캘린더 목록을 해시해서 찾는다 |
| `ext_id` | 외부 일정 id(구글 event id, Apple `eventIdentifier`). 아직 올리지 않았으면 비어 있다 |
| `ext_etag` · `ext_updated` | 마지막으로 맞춘 때의 구글 etag / 외부 수정 시각(구글 `updated`, Apple `lastModifiedDate`) |
| `ext_hash` | 마지막으로 맞춘 내용(제목·설명·장소·시작·끝·종일·반복·삭제 여부)의 지문. 꿈틀 쪽이 바뀌었는지 외부 쪽이 바뀌었는지를 이것과 비교해서 안다 |
| `ext_error` | 마지막 올리기 오류(사람이 읽는 글자). 비면 정상 |
- 구글 일정 id는 **꿈틀 일정 id로 정한다**(`kk` + uuid 16진수 32자 — 구글이 허용하는 base32hex 글자). 두 데스크톱이 같은 일정을 동시에 올려도 409(이미 있음)가 나서 두 번 생기지 않는다.
- 색: 만들 때 꿈틀 행 `color`에 그 캘린더 색을 넣는다(휴대폰도 같은 색).

#### 12.0.2 다리(데스크톱 메인 프로세스 `main/calendarBridge.ts`)
- 꿈틀 `events` 중 `ext_provider`가 있는 행을 지켜본다(PowerSync watch) + 캘린더 새로 고침이 끝날 때마다 + 1분마다(대기 중인 것 다시 시도).
- 그 행의 계정·캘린더가 **이 기기 캐시에 있을 때만** 다룬다(다른 맥의 Apple 캘린더, 연결 안 한 구글 계정은 건너뜀 — 그 기기가 맡는다).
- 행마다:
  | 상황 | 하는 일 |
  |---|---|
  | `ext_id` 없음, 삭제 아님 | 외부에 **만든다**(구글 `events.insert`(id 지정), Apple 도우미 `create`) → `ext_id`·`ext_etag`·`ext_updated`·`ext_hash` 기록 |
  | 꿈틀 쪽 지문 ≠ `ext_hash` (꿈틀에서·휴대폰에서 고침) | 외부를 **고친다**(구글 `PATCH` + `If-Match`, Apple `update` + 수정 시각 확인). 지웠으면 외부도 **지운다**. 지운 것을 되돌리면(⌘Z) 구글은 같은 id를 되살리고(`status: confirmed`), Apple은 새로 만든다 |
  | 꿈틀 쪽 그대로, 외부 쪽이 바뀜(캐시의 수정 시각 > `ext_updated`) | 외부 원본을 받아(구글 `events.get`, Apple 도우미 `get`) **꿈틀 행을 고친다**(휴대폰에도 감) |
  | 꿈틀 쪽 그대로, 외부에서 지워짐(보이는 캘린더·캐시 기간 안인데 캐시에 없고 원본이 404/cancelled) | 꿈틀 일정도 지운다(`deleted_at`) |
  | **양쪽 다 바뀜** | **나중에 고친 쪽**(꿈틀 `modified_at` vs 외부 수정 시각)으로 맞추고 토스트 `다른 곳에서도 바뀐 일정이라 나중에 고친 내용으로 맞췄어요` |
- 올리기 실패: 꿈틀 행은 그대로 두고 `ext_error`에 이유, 1분 뒤 다시(오프라인이면 온라인이 될 때). 쓰기 권한 없음·캘린더가 보기 전용이 됨·계정 다시 연결 필요는 다시 시도하지 않고 일정 카드 아래 줄에 빨강 이유 + 토스트 한 번.
- 기기 캐시 안의 같은 일정(`ext_id`가 같은 행, 반복이면 그 회차들)은 화면에 **그리지 않는다**(두 번 보이지 않게).
- 반복: 꿈틀 반복 규칙 ⇄ RRULE(`FREQ`·`INTERVAL`·`BYDAY`·`BYMONTHDAY`·`BYMONTH`·`UNTIL`·`COUNT` — 03 규칙 그대로). 연결된 반복 일정은 꿈틀 일정처럼 **늘 전체(모든 회차)**를 고친다(06 §14.4.4). 구글·Apple에서 회차 하나만 바꾼 예외는 꿈틀에 반영되지 않는다 [다음].
- 알림: 꿈틀 `reminders`는 꿈틀이 울린다(06 §14.4.7). 외부 쪽은 그 캘린더 기본 알림(구글 `reminders.useDefault`)을 따른다 — 서로 옮기지 않는다.
- 참석자: 꿈틀에서 만든 일정에는 참석자가 없다. 구글에서 나중에 참석자를 더한 연결된 일정을 꿈틀(또는 휴대폰)에서 고치면 메일을 보내지 않는다(`sendUpdates=none`) [임시].

### 12.1 틱틱 기준과 다른 점
| 항목 | 틱틱 | 꿈틀 |
|---|---|---|
| 양방향 서비스 | 구글·iCloud. 맥 로컬 캘린더는 "local viewing only" | 구글 + Apple(EventKit) 쓰기 가능 캘린더 — 결과는 틱틱 iCloud 양방향과 같다 |
| 앱에서 만든 일정 | 그 외부 캘린더에만 생긴다(틱틱 서버가 동기화) | **꿈틀에도 저장 + 외부 캘린더에도 저장**(사용자 결정 — 휴대폰에서도 보이고 고칠 수 있게) |
| 만드는 곳 | 사이드바 구독 캘린더 목록 입력창 | 그 입력창(§12.4.2) + 빠른 만들기의 캘린더 고르기(§12.4.1) |
| 반복 범위 | 할 일 대화(이번만 / 이후 모든 회차 / 완료 안 된 모든 회차). 일정용 대화 없음 | 캐시 전용 반복 일정에 같은 말로 세 가지(§12.8). 연결된 반복 일정은 늘 전체 |

### 12.2 고칠 수 있는지 판정 (`writable`) — 메인이 캘린더·일정마다 계산해 렌더러에 넘긴다
| 조건 | 결과 | 읽기 전용 이유(팝오버 맨 아래 회색 한 줄) |
|---|---|---|
| 구글 쓰기 권한(`calendar.events`)이 없는 연결 | 고치려 하면 §12.3.2 대화 | — |
| 구글 `accessRole` = `reader`·`freeBusyReader` / Apple `allowsContentModifications` = 거짓 | 읽기 전용 | `이 캘린더는 보기만 할 수 있어요` |
| 구글 휴일 캘린더(`#holiday@group.v.calendar.google.com`)·생일(`eventType = birthday`) | 읽기 전용 | `공휴일·생일 캘린더는 고칠 수 없어요` |
| 구글 `eventType` = `outOfOffice`·`focusTime`·`fromGmail` | 읽기 전용(근무 위치는 v1처럼 받지 않음) | `구글 캘린더에서만 고칠 수 있는 일정이에요` |
| 구글 `organizer.self` ≠ 참이고 `guestsCanModify` ≠ 참 / Apple 주최자가 내가 아님 | 읽기 전용 | `주최자가 아니라 옮기거나 고칠 수 없어요` [틱틱 `event_move_non_organizer_hint`] |
| 계정 `reauth`·`scope_missing`·`denied`·`restricted`·`helper_missing` | 잠깐 읽기 전용 | `구글 계정을 다시 연결해 주세요` / `캘린더 접근을 다시 허용해 주세요` |
| 그 밖 | **고칠 수 있음** | — |
- 꿈틀 공휴일(06 §16)은 일정이 아니라 늘 고칠 수 없다. 읽기 전용 일정의 모양·동작은 v1 §3.1·§3.3·§4.3 그대로.

### 12.3 권한
#### 12.3.1 구글 범위
| 범위 | v1 | v2 |
|---|---|---|
| `calendar.calendarlist.readonly` | ✓ | ✓ |
| `calendar.events.readonly` | ✓ | ✗(아래가 읽기를 포함) |
| `calendar.events` | — | ✓ 민감 범위(제한 범위 아님 — CASA 없음) |
- **새 연결(온보딩 18 캘린더 단계·설정 › 연동 `+ 캘린더 추가`)은 위 두 범위로 처음부터 양방향.** `calendar.events.owned`는 공유받은 쓰기 캘린더·휴일 읽기가 빠져서, `calendar`는 너무 넓어서 쓰지 않는다.
- 동의 화면에서 쓰기를 빼고 읽기만 체크하면 연결은 **읽기 전용 연결로 성공** + 토스트 `읽기만 연결했어요. 일정을 고치려면 쓰기 권한을 허용해 주세요.`
#### 12.3.2 v1으로 이미 연결한 계정 — 처음 고칠 때 묻는다
- 업데이트해도 읽기는 그대로. 토큰 `scope`에 `calendar.events`가 없으면 `canWrite` = 거짓.
- 그 계정 캘린더를 고르거나(빠른 만들기·추가 바) 그 계정 일정을 고치려는 순간 확인 대화: 제목 `구글 캘린더에 쓰기 권한이 필요해요` / 본문 `<이메일>의 일정을 꿈틀에서 만들고 고치려면 구글에서 한 번 더 허용해 주세요. 바꾼 내용은 바로 구글 캘린더에도 저장돼요.` / `나중에` · `허용하기`. `허용하기` = §7.1 흐름에 `include_granted_scopes=true` + `login_hint=<이메일>`. 성공하면 하던 일을 이어서, 실패·취소면 원래대로 + 토스트 `쓰기 권한을 받지 못해서 바꾸지 않았어요`.
- 설정 › 연동 계정 행: 쓰기 권한이 없으면 상태 글자 뒤 회색 `· 읽기만` + 오른쪽 `쓰기 허용`(강조색 글자 버튼, 같은 흐름).
- 쓰기 중 403 `insufficientPermissions` → 그 계정 `canWrite` = 거짓 + 위 대화.
#### 12.3.3 Apple
- v1과 같은 전체 접근(fullAccess) 하나로 읽기·쓰기. 권한 창 문구를 `꿈틀이 맥 캘린더 앱의 일정을 할 일과 함께 보여 주고, 꿈틀에서 만들거나 고친 일정을 캘린더 앱에도 저장해요.`로 바꾼다(앱·도우미 Info.plist, electron-builder.yml). 이미 허용한 사람은 다시 묻지 않는다.

### 12.4 만들기 — 늘 "연결된 일정"
#### 12.4.1 빠른 만들기의 캘린더 고르기
- 06 §14.4.2 `일정` 팝오버 아래 왼쪽 "● 내 일정"을 버튼 `● <캘린더 이름> ⌄`로. 누르면 메뉴(폭 240): `내 일정` / 구분선 / 계정·출처별 작은 회색 머리 아래 **쓸 수 있고 보이는** 캘린더. 쓰기 권한 없는 구글 계정 캘린더는 끝에 회색 `권한 필요`(고르면 §12.3.2 대화).
- **기본값 = 이 기기에서 마지막으로 고른 캘린더**(localStorage `sprout.cal.qc.target` = `sprout` | `<계정>|<캘린더 해시>`). 사라졌거나 읽기 전용이 되면 `내 일정`.
- 외부 캘린더를 고르면 저장할 때 꿈틀 `events` 행을 연결 정보와 함께 만들고(오프라인이어도 바로 저장), 다리가 외부에 올린다. 꿈틀 화면에는 바로 보인다.
- 날짜 선택기·장소·설명·반복·알림은 꿈틀 일정과 같다(알림은 꿈틀 쪽 알림).
#### 12.4.2 사이드바 "구독 캘린더" 목록의 추가 바 [틱틱 research 31 §2]
- 계정 목록 위에 입력칸 `"<이메일>"에 일정 추가`(Apple `"이 Mac의 캘린더"에 일정 추가`). 01 빠른 추가와 같은 날짜 인식("내일 3시 치과"), 날짜가 없으면 오늘 종일, 시각 하나면 1시간.
- 대상 = 그 계정 기본 캘린더(구글 `primary`, Apple 새 일정 기본 캘린더 — 그 계정이 아니면 첫 쓰기 가능 캘린더). 만든 것은 연결된 일정이다.
- 쓸 수 있는 캘린더가 없으면 입력칸 대신 회색 `이 계정은 보기만 해요`(권한이 없을 때는 `· 쓰기 허용` 링크).

### 12.5 캐시 전용 외부 일정 고치기 — 팝오버
- 쓸 수 있는 외부 일정을 누르면 **꿈틀 일정 카드와 같은 줄 구성**: 제목 입력 / 🕐 날짜·시간(03 날짜 선택기 — 날짜·기간·종일, 반복·알림 줄은 숨김) / 📍 장소 / 📄 설명 / 아래 줄 `● <캘린더> · <계정>` + `구글 캘린더에서 열기 ↗`(Apple `캘린더 앱에서 열기 ↗`) + 🗑.
- 저장 시점: 칸을 벗어날 때(날짜 선택기는 OK). 제목을 비우고 닫으면 원래 제목. 구글 설명이 HTML이었으면 사용자가 설명을 고친 때만 글자로 바꿔 보낸다.
- 반복 규칙 바꾸기·다른 캘린더로 옮기기·참석자 보기는 [다음](`구글 캘린더에서 열기`).
- 우클릭(쓸 수 있음): 열기 · `구글 캘린더에서 열기` · (구분선) · 삭제. 읽기 전용은 v1 그대로.

### 12.6 끌기·길이·삭제·되돌리기 (캐시 전용, 쓸 수 있을 때)
- 끌어 옮기기·가장자리 길이·종일 ↔ 시간 칸·월 칸 이동·Esc 취소·끄는 동안 모양은 꿈틀 일정과 같다(06 §7.2). ⌥ 복제·⌘+클릭 함께 옮기기에는 들어가지 않는다 [임시].
- 반복 일정의 회차도 끌 수 있다(외부 회차는 실제로 있다) → 놓으면 §12.8 범위 대화. 참석자가 있고 내가 주최자면 §12.8 메일 대화.
- 삭제: 팝오버 🗑 · 우클릭 `삭제` · 고른 뒤 Delete. 반복 아님 = 바로 지우고 토스트 `일정을 삭제했어요 ⟲`(되돌리기 = 구글은 같은 id를 되살림, Apple은 같은 내용으로 다시 만듦). 반복 = 범위 대화(되돌리기 없음).
- ⌘Z: 반복 아닌 일정의 옮기기·길이·고치기는 되돌리기로 한 번 더 쓴다. 범위를 고른 변경은 되돌리기 대상이 아니다.

### 12.7 캐시 전용 저장 흐름 — 화면 먼저 · 바로 쓰기 · 실패 시 되돌림
1. 렌더러가 IPC `calendars:update`/`calendars:delete`를 부른다. 메인이 캐시 행을 먼저 바꾸고 `calendars:changed`로 화면을 바로 그린다.
2. 바로 구글 API·도우미에 쓴다(구글 15초, 도우미 20초).
3. 성공: 응답으로 캐시 행 갱신(새 etag·수정 시각), 반복 범위 변경이면 그 계정 새로 고침.
4. 실패: 캐시를 원래대로 + 토스트.
   | 경우 | 토스트 |
   |---|---|
   | 오프라인(구글) | `인터넷에 연결되면 고칠 수 있어요`(쓰기 전에 막는다) |
   | 다시 연결 필요 | `구글 계정을 다시 연결해 주세요` |
   | 쓰기 권한 없음 | §12.3.2 대화 |
   | 캘린더가 보기 전용이 됨 | `이 캘린더는 이제 보기만 할 수 있어요` |
   | 이미 지워짐(404·410) | `이미 삭제된 일정이에요`(캐시에서도 지움) |
   | 먼저 바뀜(412·Apple 수정 시각 다름) | `다른 곳에서 먼저 바뀐 일정이라 최신 내용으로 바꿨어요. 다시 고쳐 주세요.` |
   | 그 밖 | `저장하지 못했어요. 잠시 뒤 다시 시도해 주세요.` |

### 12.8 반복 범위 · 참석자 메일 [틱틱 할 일 대화의 말 — ⑫]
- 캐시 전용 반복 일정의 회차를 고치거나(제목·시간·장소·설명·끌기·길이) 지울 때 가운데 대화(폭 360):
  ```
  반복 일정 편집                                   ← 지울 때 "반복 일정 삭제"
  반복 일정을 바꾸고 있어요. 바꿀 범위를 골라 주세요.   ← 틱틱 editing_repeat_msg를 일정에 맞춤(지울 때 "…지우고 있어요. 지울 범위를…")
  [ 이번 회차만 ]
  [ 이후 모든 회차 ]
  [ 모든 회차 ]
  취소
  ```
  - 맥 TickTick.app에는 일정용 대화가 없어서(research 31 §4) 할 일 대화(`Only This Recurrence` · `All Future Recurrences` · `All Unfinished Recurrences`)의 뜻을 따라 옮겼다. 틱틱 한국어 문자열(`지금 반복`·`지금부터 모든 반복`)은 기계 번역이라 쓰지 않는다.
  - 버튼은 세로로 같은 폭. Esc·`취소` = 아무것도 바꾸지 않음.
- 구글: `이번 회차만` = 회차 id에 `PATCH`/`DELETE`. `모든 회차` = 원본(`recurringEventId`)을 같은 만큼 옮겨 `PATCH`/`DELETE`. `이후 모든 회차` = 원본 RRULE을 그 회차 전날로 끊고(`UNTIL`) 그 회차부터 같은 규칙의 새 반복 일정을 `insert`(지울 때는 끊기만).
- Apple: `이번 회차만` = `.thisEvent`, `이후 모든 회차` = `.futureEvents`, `모든 회차` = 첫 회차에 같은 변경을 적용해 `.futureEvents`.
- **참석자 메일(⑬):** 구글 일정에 나 말고 참석자가 있고 내가 주최자면, 고치거나 지우기 전에 `참석자에게 변경 내용을 이메일로 알릴까요?` / `보내지 않기` · `보내기`(`sendUpdates` = `none`/`all`). Apple은 서버가 정하므로 묻지 않는다.

### 12.9 충돌
- 연결된 일정: §12.0.2(나중에 고친 쪽, 토스트).
- 캐시 전용: 구글은 모든 고치기·지우기에 `If-Match: <etag>` → 412면 원본을 다시 받아 캐시를 갈아 끼우고 토스트(§12.7). Apple은 도우미가 수정 시각을 비교해 다르면 `conflict`.
- 팝오버를 연 채 새로 고침이 오면 입력 중인 칸은 덮지 않는다.

### 12.10 기기 캐시·IPC·도우미
- 캐시 DB(기기 전용) 판 번호 `ext_meta.schema = 2`: 올라가면 `ext_events`를 비우고 다시 받는다(캐시라 잃을 것 없음). 더하는 칸 — `ext_accounts.can_write`, `ext_events`: `base_id`(반복 원본 id 또는 자기 id), `etag`, `event_type`, `organizer_self`, `guests_can_modify`, `has_attendees`, `original_start`.
- IPC(렌더러 → 메인) 추가: `calendars:targets()`(쓸 수 있는 캘린더 — 계정·해시·이름·색·`canWrite`), `calendars:grantWrite(accountId)`, `calendars:update(key, patch, {scope, notify})`, `calendars:delete(key, {scope, notify})`, `calendars:restore(snapshot)`. 메인 → 렌더러 `calendars:toast`(다리·쓰기 결과 알림).
- 모듈: `main/googleSync.ts`(insert·patch·delete·get), `main/appleSync.ts`(도우미 쓰기), `main/calendarWrite.ts`(캐시 전용 쓰기·되돌림), `main/calendarBridge.ts`(연결된 일정 다리), `shared/calendarLink.ts`(지문·해시·RRULE ⇄ 반복 규칙·구글/Apple 모양 변환 — 순수 함수).
- 도우미 `sprout-calendar` 새 명령(입력은 표준 입력 JSON): `create {calendarId,title,notes,location,start,end,allDay,rrule?}` · `update {id, occurrence?, span: this|future|all, expectModified?, patch}` · `delete {id, occurrence?, span, expectModified?}` · `get {id}` → 일정 + `rrule`·`modifiedAt`. `events` 출력에 `modifiedAt`·`occurrence`·`organizerIsMe`·`hasAttendees`, `calendars` 출력에 `isDefault`.

- 테스트 상태(결정 ①)의 테스트 사용자는 범위가 바뀐 뒤 §12.3.2 대화로 한 번 더 허용한다.

### 12.13 휴대폰 (⑯)
- 연결된 일정은 휴대폰에 꿈틀 일정으로 보이고, 휴대폰에서 고치거나 지운 것은 동기화로 데스크톱에 와서 다리가 외부에 올린다(데스크톱이 꺼져 있으면 켜질 때). 휴대폰 화면은 바꾸지 않는다.
- 캐시 전용 외부 일정(데스크톱 캐시)은 휴대폰에 보이지 않는다(지금과 같음). **휴대폰은 자기 OS 캘린더를 OS 권한으로 직접 연결한다(구글 로그인 없음) — [38 휴대폰 캘린더 연결](38-mobile-calendars.md).** 휴대폰이 만든 연결은 `ext_provider` = `device-ios`/`device-android`이고 그 휴대폰만 올린다(38 §6).

## 부록 A. 사용자가 할 일 (구글 클라우드 — 코드로 대신할 수 없음)
1. https://console.cloud.google.com 에 본인 구글 계정으로 로그인 → 위쪽 프로젝트 선택 › **새 프로젝트**(이름 예: `sprout`) 만들기.
2. **API 및 서비스 › 라이브러리**에서 "Google Calendar API" 검색 → **사용 설정**.
3. **Google Auth Platform(OAuth 동의 화면) › 시작하기**: 앱 이름 `sprout`(가칭), 사용자 지원 이메일 = 본인 이메일, 대상 **외부(External)**, 개발자 연락처 = 본인 이메일 → 만들기.
4. **대상(Audience)**: 게시 상태가 **테스트**인지 확인 → **테스트 사용자 › 사용자 추가**에 구글 캘린더를 연결할 본인 구글 계정(들)을 넣는다(최대 100명).
5. **데이터 액세스 › 범위 추가**: `.../auth/calendar.calendarlist.readonly`, `.../auth/calendar.events.readonly` 두 개만 체크 → 저장(민감한 범위로 표시되는 것이 정상).
6. **클라이언트 › 클라이언트 만들기**: 애플리케이션 유형 **데스크톱 앱**, 이름 `sprout desktop` → 만들기. 나오는 **클라이언트 ID**와 **클라이언트 보안 비밀번호**를 복사한다. (구글은 데스크톱 클라이언트의 토큰 교환에도 이 비밀값을 요구한다. 설치형 앱에서는 비밀로 취급되지 않으며 보안은 PKCE가 맡는다. 그래도 저장소에는 커밋하지 않는다.)
7. 앱 실행 때 넣기(지금): 
   ```bash
   cd apps/desktop && . ../../scripts/node22.sh && GOOGLE_CLIENT_ID=<클라이언트 ID> GOOGLE_CLIENT_SECRET=<비밀값> npx electron-vite dev
   ```
   이후 패키지 앱에서는 빌드할 때 같은 두 값을 넣어 앱 설정 파일로 묶는다 [다음 — 패키징 단계에서]. 값이 없으면 설정 › 연동에 `구글 연결 준비가 아직 안 됐어요…` 안내가 뜨고 연결 버튼이 비활성이다.
8. 테스트 상태에서는 **7일마다 "다시 연결이 필요해요"**가 뜨는 것이 정상이다(구글 정책).
9. **공개 출시 전 검증(심사)**: Google Auth Platform › 인증 센터에서 제출. 필요: 제품명 확정, 내 도메인의 **홈페이지**와 **개인정보 처리방침** 주소(구글 일정은 이 기기에만 저장하고 서버·AI로 보내지 않는다는 문장 — "제한적 사용" 조건), 서치 콘솔로 도메인 소유 확인, 연결 과정과 일정이 보이는 화면을 찍은 **시연 영상**(유튜브 링크), 범위마다 쓰는 이유. 보통 며칠~몇 주. 제한(restricted) 범위가 아니라 외부 보안 평가(CASA)는 필요 없다.

## 부록 B. 사용자가 할 일 (Apple 캘린더)
1. 맥 **캘린더 앱**에 보고 싶은 계정(iCloud·구글·Exchange 등)이 이미 등록돼 있으면 따로 할 일은 없다.
2. sprout 설정 › 연동 › `+ 캘린더 추가` › Apple 캘린더 → macOS 권한 창에서 **허용**.
