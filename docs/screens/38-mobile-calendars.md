## 2. 레이아웃
### 2.1 설정 › 캘린더 연동 (`app/(tabs)/settings/calendars.tsx`, 머리 ‹ 뒤로 + 가운데 `캘린더 연동`)
설정 첫 화면 `날짜와 시간` 아래에 칸 하나: 아이콘 = 캘린더(빨강 사각 `#e5534b`), 이름 `캘린더 연동`, 오른쪽 값 = `꺼짐` / `캘린더 N개` / `권한 필요`.
```
┌ 휴대폰 캘린더 ─────────────────────────────┐
│ 휴대폰에 추가한 구글·iCloud 캘린더를        │  ← 연결 전: 설명 + 강조색 버튼
│ 할 일과 함께 보고, 꿈틀에서 만든 일정을      │
│ 그 캘린더에도 저장해요.                     │
│            [ 휴대폰 캘린더 연결 ]            │
└────────────────────────────────────────┘
```
연결 뒤:
```
 iCLOUD                                  ← 출처(계정) 묶음 머리 12/600 3차 글자, 대문자 그대로
┌──────────────────────────────────────┐
│ ● 집              보기 ◯━ (스위치)    │  ← 행 46, 점 10 = 캘린더 색
│ ● 회사                       ◯━       │
└──────────────────────────────────────┘
 GOOGLE · me@gmail.com
┌──────────────────────────────────────┐
│ ● me@gmail.com                ◯━       │
│ ● 대한민국의 휴일  보기만       ◯━       │  ← 쓸 수 없는 캘린더: 이름 뒤 회색 `보기만`
└──────────────────────────────────────┘
┌──────────────────────────────────────┐
│ 연결 끊기                              │  ← 빨강 글자
└──────────────────────────────────────┘
꿈틀에서 만들거나 고친 일정은 고른 휴대폰 캘린더에도 저장돼요. 휴대폰 캘린더에서 만든 일정은 이 휴대폰에서만 보이고 꿈틀 서버나 AI로 보내지 않아요.   ← 캡션 12, 3차 글자
```
- 카드·행 = `Cells`/`Cell`(20 설정 칸) 그대로, 스위치 = RN `Switch`(강조색).
- 묶음 순서: 출처 이름 가나다, 그 안은 OS가 주는 순서. 묶음 머리 = 출처 이름(iOS `source.name`, Android `ownerAccount`/`source.name`).

### 2.2 캘린더 탭
- ⋯ 메뉴 맨 아래 `캘린더 구독`(아이콘 CalendarPlus) → §2.1 화면.
- 휴대폰 캘린더 일정은 꿈틀 일정과 같은 모양(20 §7.1 — 월 칸 띠, 일·3일 블록, 그날 목록·목록 보기 일정 행)으로 섞여 그린다. 색 = 그 캘린더 색. 일정 행 메타 줄 `● <캘린더 이름>`(꿈틀 일정은 `● 내 일정`).
- 연결된 꿈틀 일정도 메타 줄이 그 캘린더 이름(주인 휴대폰), 다른 기기에서는 `구글 캘린더`·`Apple 캘린더`·`iPhone 캘린더`·`Android 캘린더`.

### 2.3 휴대폰 캘린더 일정 시트 (`app/device-event.tsx`, 일정 시트 20 §7.1과 같은 formSheet)
- 위 줄 `● <캘린더 이름>` · ⋯(`캘린더 앱에서 열기` · `삭제` — 쓸 수 있을 때만 삭제).
- 🕐 날짜 줄(누르면 날짜 시트 — 날짜·기간·종일만, 반복·알림 줄 숨김) / 제목 / 📍 장소 / 설명.
- **쓸 수 있으면** 꿈틀 일정 시트처럼 바로 고친다(0.6초 쉬거나 닫으면 저장 — 16 §12.5). **읽기 전용**이면 입력칸이 글자로 바뀌고 맨 아래 회색 한 줄 이유(§4).
- 반복 회차면 맨 아래 회색 `반복 일정이에요` 대신 고칠 때마다 범위 대화(§5.4).

### 2.4 빠른 입력 `일정`의 캘린더 고르기 (22 §3.5 · 16 §12.4.1의 휴대폰판)
- 아래 왼쪽 `● 내 일정`을 버튼 `● <캘린더 이름> ⌄`로. 누르면 메뉴(폭 260): `내 일정` / **쓸 수 있고 켜 둔** 휴대폰 캘린더 `● <캘린더 이름> · <출처>`(휴대폰 메뉴에는 묶음 머리가 없어 출처를 이름 뒤에 붙인다).
- 기본값 = **이 휴대폰에서 마지막으로 고른 캘린더**(파일 `sprout-device-cal.json`의 `lastTarget`). 사라졌거나 꺼졌거나 보기만이 되면 `내 일정`.
- 연결 전이거나 쓸 수 있는 캘린더가 없으면 버튼이 아니라 지금처럼 글자 `● 내 일정`.

### 2.6 서랍 `캘린더 구독` 칸 (v1.1, 2026-10-10 — 사용자 "모바일이랑 데탑 모두 이 캘린더 구독 탭이 있어야 해")
- 틱틱 근거: 틱틱 iOS 서랍에 구독한 캘린더 줄(달력 + 전파 아이콘, research 34 §3.2), 틱틱 Mac 사이드바 `캘린더 구독` 구역(사용자 사진 — `내장 캘린더` + 계정 행). 데스크톱은 16 §2.4.1.
- 자리: 서랍 **태그 칸 아래, 완료·계획 취소·휴지통 구분선 위**. 다른 칸과 같은 머리(`캘린더 구독` + ⌄ 접기 + `+`). `+` = 설정 › 캘린더 연동(§2.1, 캘린더 ⋯ › 캘린더 구독과 같은 곳).
- 줄: 휴대폰 캘린더가 연결돼 있고 권한이 있으면 **`내장 캘린더`** 한 줄(전파 화면 아이콘 lucide `Cast`, 오른쪽 숫자 = 앞으로 3개월 일정 개수, 0이면 숨김). 연결 전·권한 없음이면 줄 대신 회색 안내 `휴대폰 캘린더를 연결하면 여기에 보여요`(태그 빈 줄과 같은 모양).
- 누르면 가운데 목록 = 보기 `ext:device`: 큰 제목 `내장 캘린더`, 추가 줄·체크 없음, 그룹 **오늘 / 다음 7일 / 나중에**(앞으로 3개월, 켜 둔 캘린더만 — §2.2와 같음), 줄 = 일정 행(20 §7 모양, 캘린더 색 줄). 줄을 누르면 §2.3 휴대폰 일정 시트, 길게 누르면 캘린더 탭과 같은 메뉴는 [다음](지금은 누르기만).
- 빈 상태: `앞으로 3개월 동안 일정이 없어요.`(16 §2.4와 같은 말). 연결이 끊긴 채 이 보기를 열면 같은 안내 + `캘린더 연동 열기` 단추.
- 데이터: 읽기만(§2.2와 같은 `useDeviceEvents`), 동기화 스키마 변경 없음.
- 완료 기준: 새 계정에서도 서랍에 `캘린더 구독` 칸이 보인다 · 연결하면 `내장 캘린더` 줄과 숫자가 생긴다 · 눌러서 앞으로 3개월 일정이 오늘/다음 7일/나중에로 나온다 · 일정을 누르면 휴대폰 일정 시트.

## 3. 구성 요소와 상태
| 상태 | 설정 › 캘린더 연동 | 캘린더 탭 |
|---|---|---|
| 연결 전 | 설명 + `휴대폰 캘린더 연결` | 휴대폰 일정 없음 |
| 권한 창 | OS 창(§8 문구) | — |
| 거부(iOS 거부·제한 / Android 거부·"다시 묻지 않음") | 카드 문구 `캘린더 접근이 꺼져 있어요. 설정에서 꿈틀의 캘린더 접근을 허용해 주세요.` + `설정 열기`(OS 앱 설정) | 휴대폰 일정 없음, ⋯ › 캘린더 구독은 그대로 |
| iOS 쓰기 전용 허용(iOS 17 "일정 추가만") | 거부와 같은 문구 + `설정 열기`(읽기가 안 되므로 연결할 수 없음) | 없음 |
| 연결됨 | 캘린더 목록 + 스위치 | 켜 둔 캘린더 일정 |
| 읽는 중 | 목록 자리 회색 `불러오는 중…` | 이전에 그린 것 그대로 |
| 캘린더 0개 | `휴대폰에 캘린더가 없어요. 휴대폰 설정에서 계정을 추가해 주세요.` | 없음 |
| 앱 밖에서 권한을 끔 | 다음에 앞으로 올 때 거부 상태로. 연결된 일정은 꿈틀에 그대로, 올리기 오류 `캘린더 접근을 다시 허용해 주세요` | 휴대폰 일정 사라짐 |
- 연결 끊기: 확인 대화 `휴대폰 캘린더 연결을 끊을까요?` / `휴대폰 캘린더 일정이 꿈틀에서 보이지 않아요. 휴대폰 캘린더의 일정은 지워지지 않아요.` / `취소` · `연결 끊기`. 권한은 OS 것이라 그대로(16 ⑤ Apple과 같음). 연결된 일정은 꿈틀 일정으로 남고 더는 올리지 않는다(올리기 오류 `휴대폰 캘린더 연결이 꺼져 있어요`).
- 로그아웃: 연결 설정(켜 둔 캘린더·마지막 캘린더)을 지운다. 연결 id는 기기 id에 묶여 있어 다시 로그인하면 같은 id(§6.1).

## 4. 고칠 수 있는지 판정 (휴대폰판 16 §12.2)
| 조건 | 결과 | 시트 맨 아래 이유 |
|---|---|---|
| 캘린더 `allowsModifications` = 거짓 | 읽기 전용 | `이 캘린더는 보기만 할 수 있어요` |
| iOS 캘린더 종류 `birthdays`·`subscribed` | 읽기 전용 | `공휴일·생일·구독 캘린더는 고칠 수 없어요` |
| 주최자가 있고 내가 아님(`organizer.isCurrentUser` = 거짓, iOS) / Android `accessLevel` 읽기 | 읽기 전용 | `주최자가 아니라 옮기거나 고칠 수 없어요` |
| 그 밖 | **고칠 수 있음** | — |
- 읽기 전용 일정은 일·3일에서 길게 눌러도 끌리지 않고(메뉴만), 시트는 글자만.

## 5. 인터랙션
### 5.1 연결
1. `휴대폰 캘린더 연결` → OS 권한 창(iOS 17+ = 전체 접근, Android = 캘린더 읽기·쓰기 한 창).
2. 허용 → 휴대폰의 캘린더를 읽고 **모두 켠 채로** 목록을 보인다(데스크톱 Apple과 같음) + 토스트 `휴대폰 캘린더를 연결했어요`. 이 기기에 `연결됨`을 기억(파일 `sprout-device-cal.json`).
3. 거부 → §3 거부 상태. Android에서 "다시 묻지 않음"이면 버튼이 `설정 열기`가 된다.
### 5.2 보기·새로 고침
- 앱이 앞으로 올 때, 캘린더 탭에 들어올 때, 보이는 기간이 바뀔 때, 휴대폰 캘린더에 쓴 뒤 다시 읽는다(OS에서 바로 읽으니 따로 저장하지 않는다 — 기기 캐시 없음).
- 스위치를 끄면 그 캘린더 일정이 바로 사라진다(이 휴대폰에만 기억).
### 5.3 만들기 (연결된 일정)
- 빠른 입력 `일정`에서 휴대폰 캘린더를 골라 저장 → 꿈틀 `events` 행(`ext_provider` = `device-ios`|`device-android`, `ext_account` = 이 휴대폰 연결 id, `ext_calendar` = 캘린더 id 해시, `color` = 캘린더 색)을 만들고 곧바로 휴대폰 캘린더에도 만든다(§6). 토스트는 지금 문구(`일정을 추가했어요`).
- 꿈틀 알림(`reminders`)은 꿈틀이 울린다. 휴대폰 캘린더 쪽 알림은 그 캘린더 기본값(옮기지 않음 — 16 §12.0.2).
### 5.4 캐시 전용 휴대폰 일정 고치기·옮기기·삭제
- 시트에서 고치기(§2.3), 일·3일에서 길게 눌러 끌기(15분 칸 — 꿈틀 일정과 같음), 길게 누르고 놓으면 메뉴(`열기` · `캘린더 앱에서 열기` · `삭제`).
- 저장: **바로 휴대폰 캘린더에 쓰고 다시 그린다**(휴대폰 안 쓰기라 바로 끝나서 데스크톱처럼 화면을 먼저 바꿀 필요가 없다). 실패하면 원래 모양 그대로 + 토스트 `저장하지 못했어요. 잠시 뒤 다시 시도해 주세요.`(지워진 일정이면 `이미 삭제된 일정이에요`). 네트워크가 없어도 된다.
- 시트 입력: 반복 아닌 일정은 0.6초 쉬거나 닫을 때 저장, 반복 회차는 칸을 벗어날 때 저장(범위 대화가 시트 위에 떠야 해서 닫은 뒤에는 묻지 않는다).
- 삭제: 반복 아님 = 바로 지우고 토스트 `일정을 삭제했어요`(되돌리기 = 같은 내용으로 다시 만든다). 
- 옮기기·고치기(반복 아님) 토스트 `옮겼어요 ⟲`(되돌리기 = 원래 값으로 다시 쓴다).
- **반복 회차**를 고치거나 옮기거나 지우면 16 §12.8과 같은 가운데 대화(폭 320, 버튼 세로):
  | | iOS | Android |
  |---|---|---|
  | 고치기·옮기기 | `이번 회차만` · `이후 모든 회차` · `모든 회차` | `모든 회차`만(Android 캘린더는 회차 하나 고치기를 앱에 열어 주지 않음) — 대화 본문 끝에 `이 휴대폰에서는 모든 회차를 함께 바꿀 수 있어요.` |
  | 지우기 | 세 가지 | `이번 회차만` · `모든 회차` |
  - `모든 회차` = 첫 회차를 같은 만큼 옮기거나 같은 내용으로 고친다. 범위를 고른 변경은 되돌리기가 없다(16 §12.6).
- 참석자 메일은 묻지 않는다(휴대폰 OS가 보낸다 — 16 §12.8 Apple과 같음).
### 5.5 연결된 일정 고치기
- 꿈틀 일정과 똑같다(일정 시트·끌기·⌘Z 대신 토스트 되돌리기·할 일로 바꾸기 등 20 §7.1). 바꾸면 꿈틀 행이 바뀌고 주인 휴대폰이 곧 올린다(§6.2).
- 일정 시트 위 줄 `● <캘린더 이름>`. 올리기 오류가 있으면 시트 맨 아래 빨강 한 줄 `ext_error`, 아직 못 올렸으면 회색 `연결한 캘린더에 아직 올리지 않았어요`(데스크톱 EventCard와 같은 말).

## 6. 기기 사이 규칙 — 누가 올리나 (M6)
### 6.1 연결 정보
| 칸 | 휴대폰 값 | 데스크톱 값(16 §12.0.1, 그대로) |
|---|---|---|
| `ext_provider` | `device-ios` / `device-android` | `google` / `apple` |
| `ext_account` | `d_` + (기기 id `sprout.deviceId` 해시 16자) — 이 앱 설치마다 하나 | 구글 `g_`+이메일 해시 / Apple `apple` |
| `ext_calendar` | `c_` + (휴대폰 캘린더 id 해시 16자) | `c_` + 캘린더 id 해시 |
| `ext_id` | 휴대폰 캘린더 일정 id(iOS `eventIdentifier`, Android 일정 번호) | 구글 event id · Apple `eventIdentifier` |
| `ext_updated` | iOS `lastModifiedDate`, Android 빈 값 | 구글 `updated` · Apple 수정 시각 |
| `ext_hash` | 마지막으로 맞춘 내용 지문(이 휴대폰이 계산 — 주인만 비교하므로 데스크톱 지문과 같을 필요 없다) | 같은 뜻 |
- 이메일·캘린더 이름·캘린더 id 원문은 서버에 올리지 않는다(해시만).
### 6.2 주인 판정
- **올리는 기기 = `ext_provider`를 다룰 줄 알고 + `ext_account`가 자기 것인 기기 하나.**
  - 데스크톱 다리(`main/calendarBridge.ts`): `google`·`apple`만(지금 코드 그대로 — `device-*`는 건너뜀).
  - 휴대폰 다리(`src/calendars/bridge.ts`): iOS는 `device-ios`, Android는 `device-android`이고 `ext_account` = 자기 연결 id인 행만. `google`·`apple`·다른 휴대폰 행은 건너뛴다(꿈틀 일정으로 보이고 고치면 꿈틀 행만 바뀜).
- 다시 설치해 기기 id가 바뀐 경우: 같은 종류(`device-ios` 등)의 다른 `ext_account` 행 중 `ext_id`가 **이 휴대폰에 그대로 있고** 그 일정의 캘린더 해시가 `ext_calendar`와 같으면 이 휴대폰의 옛 연결로 보고 `ext_account`를 자기 것으로 바꾼다(휴대폰 캘린더 id는 기기마다 달라 다른 휴대폰과 겹치지 않는다) [임시].
- 주인 휴대폰이 꺼져 있거나 앱을 지웠으면: 다른 기기에서 고친 것은 꿈틀에 저장되고, 주인 휴대폰이 앱을 열 때 올라간다(16 ⑭ "데스크톱이 꺼져 있으면 기다린다"와 같음).
### 6.3 휴대폰 다리 — 행마다 (16 §12.0.2와 같은 표, 다른 점만)
- 도는 때: 앱이 앞으로 올 때 · 연결된 꿈틀 일정이 바뀔 때(PowerSync 감시 — 다른 기기에서 고친 것 포함) · 휴대폰 캘린더에 직접 쓴 뒤 · 앱이 앞에 있는 동안 5분마다. 네트워크와 상관없다.
- 판단은 **세 지문 비교**(`꿈틀 지금` · `ext_hash` · `휴대폰 지금`):
  | 꿈틀 = ext_hash? | 휴대폰 = ext_hash? | 하는 일 |
  |---|---|---|
  | `ext_id` 없음 | — | 휴대폰에 만든다(지운 상태면 기록만) |
  | 다름 | 같음(또는 없음) | 휴대폰을 고친다 · 지웠으면 지운다 · 지운 것을 되살렸으면 새로 만든다 · 휴대폰에서 사라졌으면 새로 만든다 |
  | 같음 | 다름 | 휴대폰 내용으로 꿈틀 행을 고친다 |
  | 같음 | 휴대폰에서 사라짐 | 꿈틀 일정도 지운다(`deleted_at`) |
  | 다름 | 다름 | **나중에 고친 쪽**(꿈틀 `modified_at` vs iOS `lastModifiedDate`). Android는 휴대폰 수정 시각이 없어 **꿈틀 쪽**으로 맞춘다 [임시] + 토스트 `다른 곳에서도 바뀐 일정이라 나중에 고친 내용으로 맞췄어요` |
- 반복: 꿈틀 반복 규칙 ⇄ OS 반복 규칙(매일·매주·매월·매년, 간격, 요일, 날짜, 달, 끝 날짜, 횟수). 연결된 반복 일정은 늘 모든 회차(16 §12.0.2와 같음). 꿈틀 규칙이 OS로 옮길 수 없는 모양(날짜 목록 `RDATE`)이면 첫 회차만 올리고 오류 줄 `반복 규칙을 휴대폰 캘린더에 옮기지 못했어요` [임시].
- 오류: 캘린더를 찾을 수 없음 `휴대폰에서 이 캘린더를 찾을 수 없어요` · 권한 없음 `캘린더 접근을 다시 허용해 주세요` · 보기만 `이 캘린더는 이제 보기만 할 수 있어요` · 연결 끊음 `휴대폰 캘린더 연결이 꺼져 있어요` — 다시 시도하지 않고 오류 줄 + 토스트 한 번 `일정을 연결한 캘린더에 저장하지 못했어요: <이유>`. 그 밖 실패는 오류 줄 `잠시 뒤 다시 할게요`, 다음에 돌 때 다시.

## 7. 두 번 보이지 않게 (M7)
- **휴대폰:** 휴대폰 캘린더 일정 중 ① `ext_id`가 이 휴대폰 연결 일정의 것이면 숨긴다(반복이면 모든 회차) ② 지우지 않은 **연결된 꿈틀 일정**(공급자 상관없음 — 데스크톱이 구글에 올린 것, 다른 휴대폰이 iCloud에 올린 것)과 **제목·시작·끝이 같으면** 숨긴다.
- **데스크톱:** 기기 캐시의 외부 일정 중 지우지 않은 `device-*` 연결 꿈틀 일정과 제목·시작·끝이 같은 것은 그리지 않는다(휴대폰이 iCloud·구글 캘린더에 쓴 것을 맥이 다시 읽어도 한 번만). 데스크톱 다리가 `device-*` 행으로 "같은 모양" 목록을 만들어 캐시 읽기에서 뺀다.
- 비교: 제목은 앞뒤 공백을 지우고, 시각은 꿈틀 모양(`YYYY-MM-DDTHH:mm`, 종일은 날짜)으로.

- [ ] 허용하면 출처별 캘린더 목록(색 점·이름·`보기만`)이 보이고, 캘린더 탭 월·일·3일·목록에 그 캘린더 색으로 일정이 보인다. 스위치를 끄면 바로 사라진다.
- [ ] 빠른 입력 `일정`의 캘린더 고르기에 내 일정 + 쓸 수 있고 켜 둔 캘린더만 있고, 다음에 열면 마지막 캘린더가 기본이다.
- [ ] 휴대폰 캘린더를 골라 만든 일정이 꿈틀(그 색)과 휴대폰 캘린더 앱에 같은 제목·시간·장소·설명으로 있고, 꿈틀에는 한 번만 보인다. 데스크톱에도 꿈틀 일정으로 한 번만 보인다.
- [ ] 그 일정을 휴대폰·데스크톱에서 고치거나 지우면 주인 휴대폰 캘린더에도 반영된다(데스크톱에서 고친 것은 휴대폰 앱을 열 때). 데스크톱은 휴대폰 연결 일정을 구글·맥 캘린더에 올리지 않고, 휴대폰은 데스크톱 연결 일정을 휴대폰 캘린더에 올리지 않는다.
- [ ] 휴대폰 캘린더 앱에서 그 일정을 고치면 꿈틀 앱을 열 때 꿈틀(다른 기기 포함)이 따라 바뀌고, 지우면 꿈틀에서도 사라진다.
- [ ] 휴대폰 캘린더에서 직접 만든 일정(캐시 전용)은 서버로 가지 않고, 쓸 수 있으면 시트 고치기·끌기·삭제가 휴대폰 캘린더에 반영된다. 반복 회차는 §5.4 대화가 뜬다(Android는 고치기 `모든 회차`만).
- [ ] 휴일·구독·남이 초대한 일정은 끌리지 않고 시트에 이유가 보인다.
- [ ] 연결 끊기 뒤 휴대폰 일정이 사라지고 휴대폰 캘린더 앱의 일정은 그대로다.
