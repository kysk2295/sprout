## 1. 지금 그림 진단 (CharacterArt.tsx · 휴대폰 같은 도형)
- 몸은 단계와 상관없이 같은 동그라미 하나(rx 34·ry 32)다. 단계마다 **크기만 0.79배 → 1.07배**로 커진다(`scale = 0.72 + stage × 0.07`).
- 종을 알아보는 부분(등딱지 타원·꼬리 한 획·귀 원·세모)은 1단계와 5단계가 같다.
- 단계 표시는 머리 위 새싹 하나다. 잎 1→2→3장, 4단계는 원 하나짜리 나무, 5단계는 그 나무에 꽃 점 3개. 112px로 봐도 차이가 10~20px이다.
- 색은 종마다 2색(body·accent)으로 고정이고 단계로 늘지 않는다.
- 30px(AI 답 얼굴·진화 길 점)에서는 새싹 차이가 2~3px라 단계를 구별할 수 없다.
- 움직임은 무대가 감싸개에 주는 숨쉬기·깡충·흔들기뿐이다. 꼬리·귀·눈이 따로 움직이지 않고(깜빡임은 그림 바꾸기), 종·단계가 달라도 똑같이 움직인다.
- 진화 연출(10 §3.2.6)은 약 3초다. 흰 실루엣(`filter: brightness(0) invert(1)`)이 3번 깜빡이는데, filter라서 40 §7의 "transform·opacity만" 원칙에서 벗어난다.

## 2. 원칙
1. **한눈에 다른 단계.** 단계마다 ① 몸 비율, ② 새 소품 하나, ③ 색 한 겹이 바뀐다. 단계 이름을 가려도 순서를 맞힐 수 있어야 한다.
2. **머리 쪽에 단계 표시.** 30px에서는 머리만 잘라 그리므로(§5.3) 단계마다 머리 근처에 알아볼 표시를 하나씩 둔다(새싹 모양·귀 털·핀·관).
3. **화풍은 그대로.** _(v0.2: §10이 대신한다 — 캐릭터 자리에서만 둥근 음영·하이라이트를 쓴다, 결정 ⑥)_ 둥근 몸·큰 점 눈(흰 반짝임)·분홍 볼·진한 선 `#3A3A3A`·납작한 단색 면. 40 §0.1 그대로 그라데이션·빛·글로우·반짝이(✦)·보라·이모지는 쓰지 않는다. 별은 5각 별 무늬(고양이 망토)로만 쓴다.
4. **배경은 꼭대기 두 단계만.** 4단계는 발밑 원판, 5단계는 뒤 원판과 떠다니는 종 소품 3개. 모두 단색 면이다.
5. **싸게 움직인다.** transform·opacity만 쓴다. 반복해서 움직이는 캐릭터는 한 화면에 하나뿐이다(40 §7).

## 4. 움직임 (transform · opacity만)
### 4.1 대기 동작 — 단계가 오를수록 동작이 늘어난다
| 단계 | 모든 종 | 거북이 | 다람쥐 | 고양이 | 수달 |
|---|---|---|---|---|---|
| 1 | 빠른 숨(2.4초, 세로 3.5%), 3.4초마다 깜빡, 4초마다 껍데기째 흔들(±4°) | — | 꼬리 끝 살랑 | 꼬리 끝 살랑 | — |
| 2 | 숨 3초 · 깜빡 4.6초 · 새싹 흔들(±3.5°) | 고개 끄덕(1.2px, 3.4초) | 꼬리 흔들(±5°, 1.8초) | 꼬리 휘두름(±7°, 2.6초) · 귀 쫑긋(5.5초마다) | 몸 둥실(±2°, 3초) · 꼬리 · 조약돌 톡(5초마다) |
| 3 | 숨 3.2초 · 소품 흔들기 | + 이끼 꽃 | + 귀 쫑긋(5초마다) | + 실뭉치 | 조약돌 둘이 번갈아 |
| 4 | 숨 3.4초 · **7초마다 제자리 깡충**(7px) | + 지팡이 | + 목도리 끝 흔들(±4°) | + 9초마다 고개 갸웃(−6°) | **조약돌 셋 저글링**(1.5초 한 바퀴) |
| 5 | 숨 3.6초 · 6초마다 깡충 · 배경 소품 | 등 나무 흔들(±2.5°, 4초) · 잎이 떠다님 | 꼬리 ±8° · 잎이 떨어짐(6초) | 별이 깜빡(투명도 25↔100%, 3초) | 거품이 올라감(4.5초) |
- 깜빡임은 눈 묶음을 `scaleY(0.1)`로 0.12초 접는다(지금의 그림 바꾸기 대신). 웃는 눈·감은 눈 얼굴은 깜빡이지 않는다.
- 기준점: 몸 전체는 발밑(60, 108). 꼬리·귀·소품은 붙은 자리를 기준점으로 둔다(그림 데이터에 `origin`).
- 성장 무대(XL)와 AI 비서 빈 대화(L 96)에서만 위 표대로 움직인다. M 64는 깜빡임과 숨만, S 30 이하는 멈춘다(40 §2.1 그대로). 10 §3.2.3의 12~20초 대기 동작(두리번·기지개…)은 그대로 위에 얹는다.

| 졸림 | 감은 눈 · 숨 5초(10 §3.2.3) | — |
- 조각 = 강조색 네모 + 종 소품(거북 잎·꽃잎, 다람쥐 단풍잎, 고양이 5각 별, 수달 거품 고리). 색종이처럼 보이되 빛은 없다.

### 4.3 진화하는 순간 (10 §3.2.6의 "진화(약 3초)"를 대신한다)
| 시각 | 무엇 |
|---|---|
| 0 – 0.25초 | 무대가 어두워진다(검정 55%). 옛 모습이 한 번 웅크린다 |
| 0.25 – 0.55초 | 옛 모습 위에 **옛 실루엣**(같은 그림을 흰 한 색으로 칠한 층)이 페이드로 덮인다 |
| 0.65 – 1.32초 | 옛·새 실루엣이 **세 번 엇갈린다**(각 0.12초 페이드). 그동안 1 → 1.08배로 조금씩 커진다 |
| 1.32 – 1.42초 | 새 실루엣이 1.18배로 부푼다 |
| 1.42 – 1.95초 | 새 모습이 톡 나타난다(1.12 → 0.95×1.04 → 1.02×0.98 → 1). 종 소품 조각 8개가 흩어진다 |
| 1.55초 | 이름 카드가 10px 올라온다. `단짝으로 자랐어요` / **정원 거북** / `+ 새 모습 · 어깨에 작은 정원` |
| 1.9 – 2.3초 | 어둠이 걷히고 새 모습이 대기 동작을 시작한다. 카드는 3초 더 머물다 사라진다 |
- **알 깨기(성향 조사 결과·알 → 1단계):** 알이 두 번 흔들리고(±6~7°) 금이 하나씩 3개 생긴다(0.3·0.53·0.76초). 1.08초에 윗껍질이 왼쪽 위로 튀어 날아가며 사라지고, 껍데기 아랫단에 앉은 아기가 톡 올라온다. 아기 그림에 아랫단 껍데기가 이미 있어서 장면이 끊기지 않는다. 껍데기 조각 8개, 카드 `알이 깨졌어요 / 아기 거북`. 약 1.6초.
- **건너뛰기:** 무대 아무 곳이나 누르거나 오른쪽 위 `건너뛰기`를 누르면 끝 장면(새 모습 + 카드)으로 바로 간다.
- **번쩍임 안전:** 실루엣 교체는 초당 3번 이하이고 0.12초 페이드라 번쩍이지 않는다(WCAG 2.3.1). 실루엣은 filter가 아니라 같은 그림을 한 색으로 칠한 층이다.
- **움직임 줄이기:** 옛 모습 → 새 모습 0.3초 페이드 + 이름 카드 페이드만(10 §3.2.11 원칙).
- 레벨업 창(10 §2.4, 다른 화면에서 레벨이 올랐을 때)의 "진화 애니메이션 1.2초"도 같은 순서를 0.55배로 줄여 쓴다(실루엣 교체 2번).
- 휴대폰: 같은 시각표를 Reanimated `withSequence`·`withDelay`·`withTiming`으로(층 4개의 opacity·transform). 새 스프링 값은 만들지 않는다(40 §7). 진화 중 완료 진동은 21의 것 한 번만 쓴다.

## 5. 그림 만들기 계획
### 5.1 부품 데이터 하나, 그리는 곳 둘
- 그림을 **도형 데이터**로 옮긴다: `packages/schema/src/characterArt.ts` → `characterParts(species, stage, { mood, detail })`가 `{ tag: 'circle'|'ellipse'|'path'|'rect'|'g', attrs, cls?, origin?, children? }[]` 나무를 돌려준다. 35의 `AVATAR_FACES`와 같은 방식이고, 데스크톱(SVG)·휴대폰(react-native-svg)이 같은 데이터를 그린다. 지금처럼 두 파일에 같은 도형을 따로 두지 않는다.
- 층(그리는 순서): `aura`(4·5단계) → `shadow` → `back`(등딱지·꼬리·망토·등 나무) → `body` → `belly` → `feet` → `head`(`ears` → 머리 → `face` → `top` = 새싹·관·핀) → `neck`(목줄·목도리·목걸이) → `front`(팔·든 것). 1단계는 `back → head → eggBottom → paws`.
- 단계 소품은 **쌓는 목록**이다: `ACC[species] = [{ id: 'moss-l', from: 3 }, { id: 'mushroom', from: 4, to: 4 }, { id: 'tree', from: 5 }, …]`. 단계 = 비율 표(§3.1) + `from ≤ stage ≤ to`인 소품. 소품마다 `detail: 'full'`이면 작은 그림에서 뺀다(무늬·작은 꽃·별·수염).
- 움직이는 부품에는 이름(cls)을 붙인다: `c-breath`·`c-hop`·`c-sway`(몸), `c-eyes`, `c-tail`, `c-ear-l`/`c-ear-r`, `c-sprout`, `c-swing`, `c-tree`, `c-pb1~3`, 배경 `c-float`·`c-fall`·`c-twinkle`·`c-rise`. 데스크톱은 이 이름에 CSS 키프레임을, 휴대폰은 같은 이름의 `Animated.G`를 붙인다. 움직임 값 표(§4.1)도 schema에 둔다(`IDLE[species][stage]`).
- 시안 HTML의 `art()`·`SP`·`GEO`가 그대로 옮길 도형이다(좌표 그대로).

### 5.2 CharacterArt API (데스크톱 · 휴대폰 같은 모양)
```ts
<CharacterArt
  species={Species | null} stage={1..5} size={number} mood={CharacterMood}   // 그대로
  look={...} blink={...} cracks={0..3}                                         // 그대로(blink는 motion='still'일 때만 씀)
  motion?: 'still' | 'idle'        // 새로: idle이면 부품 대기 동작(§4.1). 기본 still
  detail?: 'auto' | 'full' | 'small' // 새로: auto = size ≤ 40이면 small
  crop?: 'auto' | 'full' | 'bust'   // tight 대신: auto = size ≤ 40이면 bust(머리 쪽만)
  silhouette?: boolean              // 새로: 진화 연출용 한 색 층
/>
```
- `tight`·`tightViewBox`는 `crop='bust'`·`cropBox()`로 바꾼다(부르는 곳: AI 비서 답 얼굴·오프라인 띠·퀘스트 줄 — 40 §12).
- 새 컴포넌트 `EvolutionMoment`(데스크톱 `components/growth/EvolutionMoment.tsx` WAAPI, 휴대폰 `src/growth/EvolutionMoment.tsx` Reanimated): `{ species, from: 0..4, to: 1..5, reduced, onDone }`. 0은 알. Stage.tsx의 `reveal` 단계와 레벨업 창(GrowthBits·휴대폰 LevelUp)이 이것을 부른다.
- `BuddyArt`(휴대폰 일기·지도)와 `CompanionFace`는 `CharacterArt`를 감싸므로 `motion`만 넘긴다.

### 5.3 크기마다

|---|---|---|---|---|
| S | 18~30(AI 답·진화 길 점·퀘스트 줄·오프라인 띠) | small | bust | 멈춤(40 그대로 한 번만 깡충) |

## 8. 완료 기준 (시안과 나란히, 라이트·다크)
- [ ] 4종 × 5단계 + 알이 시안 B와 같은 모양이다. 단계 이름을 가린 20장을 섞어도 단계 순서를 맞힐 수 있다(사람 2명 확인).
- [ ] 30px(AI 답 얼굴·진화 길 점)에서 1~5단계가 서로 다르게 보인다(머리 쪽 자르기, 작은 그림 모드).
- [ ] 1단계는 모든 종이 알껍데기 아랫단에 앉아 있고, 2단계부터 머리와 몸이 나뉜다.
- [ ] 성장 무대에서 §4.1 대기 동작이 종·단계마다 다르다. 4단계 7초·5단계 6초마다 제자리 깡충, 깜빡임은 눈 접기.
- [ ] 누르기·할 일 완료·레벨업 반응이 §4.2 값이고, `+1`·레벨 칩·조각이 나온다.
- [ ] 진화: 실루엣 3번 교체 → 톡 → 조각 8개 → 이름 카드, 2.3초 안에 끝난다. 누르면 끝 장면으로. 알 깨기는 윗껍질이 날아가고 아기가 아랫단 껍데기째 나온다.
- [ ] 움직임 줄이기(OS·성장 ⋯ 스위치): 대기 동작이 모두 멈추고, 진화는 0.3초 페이드 + 카드, 반응은 얼굴·`+1` 페이드만.
- [ ] 쓰는 속성은 transform·opacity뿐이다(filter·크기·자리 움직임 없음). 창이 안 보이면 반복 움직임이 멈춘다. 반복해서 움직이는 캐릭터는 화면에 하나다.
- [ ] 휴대폰: 성장 탭에서 대기 동작이 돌 때 UI 스레드 프레임이 떨어지지 않는다(39 측정 방식, 시뮬레이터 10번). AI 비서 대화 50개 스크롤도 그대로다(정지 그림).
- [ ] 그라데이션·빛·글로우·✦·보라·이모지가 없다. 다크에서 배경 원판이 빛나 보이지 않는다(20%).
- [ ] 데스크톱·휴대폰이 같은 `characterParts` 데이터를 그린다. 도형 시험(`characterArt.test.ts`): 단계마다 소품 목록, small에서 빠지는 부품, bust 칸.
- [ ] 사이트 SVG·맥 위젯 PNG·iOS 위젯 PNG가 새 그림으로 다시 나온다. 아바타에 저장된 `char-*` 값은 그대로 보인다.

### 10.6 v0.3 — 더 귀엽게, 진화마다 크게 (2026-10-09 초안)
사용자 피드백: "지금 방향은 좋은데, 캐릭터를 좀 더 귀엽고 진화시 좀 더 변화가 있게 해줄 수 있어?" 세트(꿈틀 정원 친구들)·성향 칸·갈래 두 개·옷 23개는 그대로, 그림과 진화 순간만 바꾼다. 그림 [kkumteul-art.js](mockups/kkumteul-art.js) v3, 이전 그림은 [kkumteul-art-v1.js](mockups/kkumteul-art-v1.js)(`KK1`)에 남기고 시안 머리의 `새 그림 / 이전 그림`으로 같은 자리에서 비교한다.

**귀엽게 (모든 종·단계 공통)**
- 아기 비율: 머리가 몸보다 크다(머리 : 보이는 몸 ≈ 1.5 : 1 꼬마 → 1.2 : 1 전설). 머리는 살짝 옆으로 넓은 찹쌀떡(가로 1.05 · 세로 0.96).
- 눈: 머리 아래쪽 반에 넓게(눈 사이 = 머리 반지름 × 0.84), 크기 = 반지름 × 0.25. 빛점 둘(오른쪽 위 큰 것 + 왼쪽 아래 작은 것) + 아래쪽 푸른 반사. 볼 번짐 + 기쁠 때 볼 빗금 두 줄.
- 입: 기본 `ω`, 웃음 `‿`, 기쁨·간지럼 = 벌린 입 + 분홍 혀, 놀람 `o`, 졸림 작은 점. 팔다리는 짧고 통통한 타원(nub).
- 색: 파스텔이지만 채도 있게, 단계가 오를수록 한 칸씩 진해진다(`shellBy`·`skinBy`). 빛은 왼쪽 위 그대로(§10.2).
- 종 표시(모든 단계에 남는 것): 달팽이 **하트 나선** 껍데기 · 꿀벌 **솜털 목도리** · 애벌레 **분홍 방울 더듬이** · 올챙이 **잎 모자**(새싹이 잎 모자 가운데서 자란다).

**단계 표 (크기 = 단계와 상관없이 늘 같은 상자, `FILL` — 아래 §10.6.1)**
| 종 | 1 아기 | 2 꼬마 | 3 친구 (A / B) | 4 단짝 (A / B) | 5 전설 (A / B) |
|---|---|---|---|---|---|
| 달팽이 | **씨앗알**: 씨앗 껍질 아랫단에 앉은 머리 + 짧은 눈 더듬이, 뒤에 작은 하트 나선 | **아기 달팽이**: 배발(한 덩어리 발)이 생기고 하트 나선 껍데기 | **꽃 달팽이** 흰 데이지 / **분홍꽃 달팽이** — 껍데기 위 꽃 넷 + 잎 | **이끼집 달팽이** 이끼 지붕 + 둥근 창(불 켜짐) + 굴뚝 연기 + 버섯 / **꽃집 달팽이** 꽃 지붕 + 하트 창 · 나뭇가지 지팡이 · 발밑 원판 | **나무집 달팽이** 껍데기 위 오두막 + 열매 나무 / **온실 달팽이** 유리 온실 + 하트 바람개비 · 금 테 · 머리 화관 · 풀·돌·떠다니는 잎 장면 |

- 실루엣이 단계마다 바뀐다: 1 = 씨앗·칸·알·물방울(둥근 덩어리 하나), 2 = 몸이 생김, 3 = 몸이 길어지거나 다리가 남, 4 = 집·여왕·고치·개구리(새 모양), 5 = 장면이 붙은 완성형. 30px 얼굴(bust)은 머리만 자르므로 단계 구별은 새싹·관·더듬이로 한다.
- **크기는 늘 같다(§10.6.1, 2026-10-09 사용자 결정)**: 발밑(60,108)을 중심으로 `scale(k)`, k = 그 종·단계 그림이 같은 상자를 채우는 배율(`FILL`). 무대·도감·진화·아바타·위젯 어디서나 같은 크기이고, 성장은 모양·소품·새싹 잎·무늬로 보인다. `fit` 인자는 결과가 같다. 머리가 가운데에서 비켜난 종(달팽이, 머리 x = 50)은 머리 쪽 층만 옮기고 옷 기준점 데이터는 그대로다(`A.dx`).
- 옷 기준점: 종·단계마다 그림 함수가 돌려준다(`SP[sp](st).A` = top·hy·hr·ny·hx·hy2·by·brx·bry). 옷 23개 그림은 그대로이고 기준점만 새 몸에 맞췄다. 등 칸: 달팽이 껍데기·꿀벌 날개·고치·나비 날개는 몸이라 등 옷을 입어도 남고, 애벌레 잎 가방·개구리 망토만 등 옷이 덮는다.

#### 10.6.1 단계마다 같은 크기 (2026-10-09 사용자 결정 — 결정 ⑨를 바꿈)
- 사용자: "처음에 캐릭터가 너무 작은거 같아 캐릭터 크기는 동일하게 항상 해줘". 예전 ⑨(무대·도감·진화 = 실제 비율 0.7 → 1.45, 아기가 전설의 절반)는 버린다.
- 규칙: 그림마다 실제로 그려진 테두리(옷 없이, 빛 원판·그림자 빼고, 두 갈래 합)를 재서 **위로는 발밑에서 96(y 12까지), 옆으로는 가운데 x 60에서 58(x 2–118) 안**을 채우는 배율 k를 쓴다(`characterArt.ts` `FILL[종][단계] = [k, 그린 뒤 꼭대기 y]`, `artScale`·`artTop`). 날개·물방울·양산·나무가 상자 밖으로 잘리지 않는다. 아기는 1.1~1.4배로 커지고, 전설은 0.85~0.92배로 줄어든다.
- 재는 법: 헤드리스 Chrome에서 `art(종, 단계, { fit: true, noAura: true })`의 `.c-hop` 묶음 `getBBox()` → k = min(96 ÷ (108 − 위), 58 ÷ max(60 − 왼쪽, 오른쪽 − 60)). 그림을 고치면 다시 재서 표를 바꾼다(시험 `characterArt.test.ts`가 배율·꼭대기 범위를 본다).
- 씨앗(조사 전 알)은 1배, 부화 뚜껑은 아기와 같은 배율. 무대 상자도 레벨과 상관없이 같다(`STAGE_BOX` 260, 휴대폰 × 0.8). 43 §3.1의 "키 +3cm"(레벨마다 상자 3px)는 없앴다 — 레벨 안 성장은 새싹 잎·무늬 점으로만 보인다.
- 위젯 PNG 이름 판은 v4로 올렸다(옛 v3 그림 캐시를 다시 굽게).
