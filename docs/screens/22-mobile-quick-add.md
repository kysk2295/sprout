## 3. 구성 요소와 상태
### 3.1 자연어 인식 — **데스크톱과 같은 함수**
- `@sprout/schema/recognition`의 `recognize(raw, lists, tags, now)`를 그대로 쓴다. 데스크톱과 **코드가 같으므로 결과가 같다**(동급 보장). 시험 문장 세트(PRD A6, `recognition.test.ts`)도 같이 쓴다.
- 지금 인식하는 것(코드 기준 2026-10-04):
| 종류 | 예 | 결과 |
|---|---|---|
| 상대 날짜 | `오늘` `내일` `모레` | 마감일 |
| 매일 | `매일` | 반복 `FREQ=DAILY` + 오늘 |
| 요일 | `이번 주 금` `다음 주 월요일` `매주 수` | 마감일(매주는 반복) |
| 날짜 | `2026-10-12` | 마감일 |
| 시각 | `3시` `오후 3시 30분` `15:30` `오전 9시` | 시각(날짜 없으면 오늘) — 지난 시각 처리는 데스크톱과 같게 |
| 우선순위 | `!높음` `!중간` `!낮음` `!없음` | priority 3·2·1·0 |
| 태그 | `#운동` (있는 태그만) | task_tags |
| 리스트 | `~업무` (있는 리스트만) | list_id |
- 인식 범위를 늘리는 일(예: `다음 달`, `10월 12일`, `저녁`, `까지`)은 **공용 함수에서** 하고 데스크톱·모바일이 함께 받는다. 모바일에서 따로 파싱하지 않는다 [sprout 원칙].
- 제목에 인식 문구를 남길지·지울지는 데스크톱 설정과 같은 규칙(02 §0 "인식 문자열 삭제" 기본 끔)을 따른다.

### 3.2 하이라이트
- 인식된 글자에 옅은 강조색 배경(`color.accent.subtle`, 모서리 3) [틱틱 iOS 캡처]. 입력 중 매 글자마다 다시 계산(150ms 묶음) [임시].
- 하이라이트 글자를 **누르면 인식 취소** → 그 부분은 그냥 글자, 칩도 사라짐 [틱틱 "인식된 부분을 클릭"]. 지우기 키로 하이라이트 끝을 지워도 취소 [틱틱 "Delete 키"].
- 구현 위험: RN `TextInput` 안 부분 글자 꾸미기(안쪽 `Text` 자식)가 iOS·Android에서 커서가 튀는지 첫날 확인. 안 되면 하이라이트 없이 §2의 인식 칩 줄로 대신 [임시 대안, 20 M5].

### 3.3 도구 막대 시트
| 버튼 | 시트 | 비고 |
|---|---|---|
| 📅 날짜 | **날짜 시트**(키보드 대신 올라옴): 머리 왼쪽 둥근 **✕** · 가운데 세그먼트 **날짜 / 기간** · 오른쪽 **강조색 원 ✓** [틱틱 iOS] → 빠른 버튼 4개(오늘 · 내일 · 다음 주 월 · 오늘 밤 — 20 M6, 최신 틱틱 iOS 시트엔 없음) → 달력(월 머리 ‹ ›, 오늘 = 강조색 원) → 둥근 카드 `시간` · `알림` · `반복`(값 + ⌃⌄). 시간 = iOS 휠(오전/오후·시·5분), 알림 = 여러 개 고르기 목록. 값을 지우는 것은 각 줄의 ×(틱틱 "On time ×") | 03 §0 문구·항목 그대로(“날짜 / 지속 시간” 탭 중 **지속 시간은 [다음]**). 알림 목록은 03 §3.2(종일 / 시각 있음 표, 여러 개). 반복은 프리셋만(직접 설정 [다음]) |
| ⚑ 우선순위 | 작은 메뉴 4줄: 높음 · 중간 · 낮음 · 없음(깃발 색 = `color.priority.*`) | 02 |
| # 태그 | 제목 칸에 `#`를 넣고 태그 제안 줄(키보드 위 가로 칩: 기존 태그, 글자 맞는 것 먼저 + `새 태그 "<글자>" 만들기`) | 02 §4 `#` 드롭다운을 모바일 제안 줄로 [임시] |
| → 리스트 | 리스트 고르기 시트(기본함 + 리스트, 폴더 묶음) | 02 §4 `~` |
- 시트에서 고르면 칩 줄에 반영되고 키보드로 돌아온다.

### 3.4 상태
| 상태 | 표시 |
|---|---|
| 빈칸 | 보내기 흐림, 키보드 `완료/보내기` 키도 아무 일 없음 |
| 보냄 | 입력 창은 **비운 채 열려 있다**(연속 입력, 02 §4 Enter 규칙) [틱틱 데스크톱·모바일 동작은 실기기 확인 — 임시]. 목록 맨 위(해당 그룹)에 새 행이 잠깐 `color.accent.subtle`로 빛남 |

| 저장 실패 | 글 그대로 두고 빨간 토스트 `저장하지 못했어요. 다시 시도해 주세요` |
| 오프라인 | 차이 없음(로컬 저장) |

## 4. 인터랙션
| 동작 | 결과 |
|---|---|
| + 누름 | 입력 창 + 키보드. 기본값(02 §4 "새 태스크 기본값"): 오늘 탭 → **마감 오늘(종일)**, 리스트 = 기본함, 우선순위 없음. 인식된 날짜가 있으면 그 날짜가 이긴다 |
| 키보드 보내기 키 / ↑ | 저장(§3.4) |
| 줄바꿈 | 제목은 한 할 일 = 한 덩어리. 키보드 Return은 **보내기**로 쓴다(iOS `returnKeyType=send`) [임시]. 여러 줄 붙여 넣기 = `3개로 나눠 추가할까요?` 확인 [틱틱 클립보드 일괄 추가와 비슷 · 다음] |
| 한글 조합 중 보내기 | 조합을 끝낸 뒤 보낸다(마지막 글자 빠짐 없음) — 데스크톱 IME 규칙과 같음 |
| 덮개 누름 / 아래로 끌기 / Android 뒤로 | 닫힘. 쓴 글은 **초안으로 남아** 다음 + 때 그대로 [임시] |
| 알림 권한 | 인식·날짜 시트로 알림이 처음 생긴 할 일을 저장하는 순간 OS 권한 요청(20 §4.4) |
- 흔들림: 보낼 때 가벼운 충격 한 번 [임시].
- + 버튼 길게 누르기(음성)·끌어 놓기(위치 지정)는 [다음].

## 8. 구현 메모 (2026-10-05 — `apps/mobile`)
- 파일: 화면 `app/quick-add.tsx`·`app/date.tsx`, 부품 `src/ui/DateSheet.tsx`(날짜 시트 본체 — 빠른 입력은 키보드 대신 올라오는 패널로, 그 밖은 85% formSheet로 같은 부품), `src/ui/Wheel.tsx`(네이티브 의존성 없는 스냅 휠), `src/ui/MonthCalendar.tsx`, 순수 계산 `src/ui/quickAddModel.ts`·`src/ui/dateSheetModel.ts`(시험 있음), 쓰기 `src/data/tasks.ts`의 `createTask`(설명·기간·알림 추가)·`getSchedule`·`applySchedule`.
- **하이라이트는 RN에서 된다**(iOS 시뮬레이터 확인): 입력칸 위에 같은 글꼴의 `Text`를 겹쳐(글자는 투명·누름 통과) 인식 구간만 반투명 강조색(라이트 16%·다크 30%)으로 칠한다. 그래서 인식 칩 줄(대안)은 만들지 않았다(20 M5 그대로). 입력칸은 4줄 제한 대신 늘어나기만 한다(겹친 층과 줄이 어긋나지 않게).
- **인식 취소**: 하이라이트 안쪽을 눌러 커서를 옮기면 그 글자는 인식하지 않는다(입력 직후 120ms 안의 커서 이동은 타이핑으로 보고 무시). 구현은 그 글자 사이에 보이지 않는 글자(U+2060)를 끼워 공용 `recognize()`가 못 잡게 하고, 제목에서는 지운다 → 공용 함수는 그대로.
- 제목: 인식된 날짜·시각·`!` `#` `~` 글자는 제목에서 빠진다(공용 `recognize()`, 데스크톱 추가 바와 같음 — 2026-10-05 결정). 시각이 있으면 알림 "정각에"(`-PT0M`).
- 우선순위·리스트는 떠 있는 메뉴(리스트는 앞 12개까지 [임시] — 많으면 `~` 제안 줄). 태그 버튼은 제목에 `#`를 넣어 제안 줄을 연다. 제안 줄의 `새 태그 "<글자>"`는 `tags`에 바로 넣는다.
- 날짜 칩은 직접 정한 날짜(인식·시트)만 보인다. 보기 기본값(오늘)은 칩이 아니다. 시트에서 고른 뒤 새 날짜 글자를 치면 그 인식이 이긴다(마지막 동작).
