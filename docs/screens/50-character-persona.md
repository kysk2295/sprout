# 50. 캐릭터 성격(페르소나) — AI 비서·일기·캐릭터 말에 종별 성격 입히기

- **상태:** v1.0 (2026-10-11) — 사용자 "너 추천대로 전부 해 줘": §7 결정 ①~④ 모두 추천안 ✅. + 성장 화면 캐릭터 소개 UI(§8, 사용자 "이 캐릭터를 설명하는 UI를 성장 화면에 넣어서 클릭하면 나오게").
- **정본 코드:** `packages/schema/src/persona.ts`(`PERSONAS` · `personaChatBlock` · `personaToneLine`).
- **요청:** "캐릭터별로 성격이나 이런 게 다르잖아. 그걸 확인하고 기획을 좀 더 구체화해 줘."
- **관련:** [10 §2.2](10-growth.md)(성향 조사 2축 4유형) · [40 §3.5](40-character-companion.md)(이름·말투) · [47 §7](47-assistant-free-chat.md)(AI 비서 지시문) · [49 §15](49-character-v3.md)(마스코트 꿈틀이) · 28(일기 대화).
- **틱틱 기준:** 틱틱에는 캐릭터·AI 성격이 없다. 꿈틀만의 기능이라 틱틱의 짧고 담백한 문구 원칙만 따른다(CLAUDE.md UI·UX 원칙).

## 1. 지금 상태 (2026-10-11 코드 확인)

| 곳 | 종별로 다른가 | 실제로 들어가는 것 |
|---|---|---|
| 일기 대화(`diary.ts` `TONE` · `diaryPrompts.ts`) | **다름 — 말투 한 줄만** | 달팽이 `느긋하고 차분하게…` · 꿀벌 `밝고 생기 있게…` · 애벌레 `담백하고 군더더기 없이…` · 개구리 `다정하고 포근하게…` · 조사 전 `다정하고 짧은 말투` |
| AI 비서 도구 대화(`AGENT_SYSTEM`) | **같음** | 모든 캐릭터가 같은 지시문. 앱 칸에는 이름만(`네 이름은 …`) |
| AI 비서 일반 대화(`CHAT_SYSTEM`, 2026-10-11 Jev 분리) | **같음 — 성격 하나로 고정** | `새로운 주제를 배우고 상상하는 걸 좋아해`, 말투 예 `"난 새로운 이야기를 상상하는 게 좋아. 너는?"` — 모든 종이 같은 취향을 말한다 |
| 캐릭터 한 줄(앱이 고름, `companion.ts`) | 같음 | `넣어 뒀어.` · `이만큼 했어.` · 빈 대화 `TAP_LINES` 4개 |
| 마스코트 꿈틀이(조사 전) | 따로 있음 | `MASCOT_LINES` 3개(정원 안내) |
| 성장 화면 유형 소개(`SPECIES`) | 다름 | 이름·유형·한 줄(`정한 일을 끝까지 차근차근` 등) — 대화에는 쓰이지 않음 |
| 일반 대화 보호 규칙(`assistantSelfQuestion`) | — | 옛 종 이름 `수달`이 박혀 있다(지금 종은 개구리) |

**정리:** 성격이 대화에 반영되는 곳은 일기의 말투 한 줄뿐이다. AI 비서는 어느 종이든 같은 성격이다. 그래서 2026-10-11에 겪은 "취미가 뭐니 → 모르겠어 → 지어낸 답" 문제도 생긴다. 캐릭터에게 정해진 성격·취향이 없어서 모델이 매번 새로 지어낸다.

**맞지 않는 점:** 개구리의 유형 소개는 `아이디어가 많고 빨라요`(즉흥·멀티)인데, 일기 말투는 `다정하고 포근하게, 마음을 먼저 살피는`이다. → 결정 ①.

## 2. 목표와 원칙

1. **같은 캐릭터는 어디서나 같은 성격이다.** AI 비서, 일기 대화, 주간 리포트, 캐릭터 한 줄이 같은 성격 카드 하나를 쓴다(정본 1곳: `packages/schema/src/persona.ts`).
2. **성격은 말투·관심사·반응 방식만 바꾼다.** 사실 규칙·안전 규칙·근거 검사·반말·길이 제한은 모든 종이 같다. 성격 때문에 기록을 지어내거나 규칙을 어기지 않는다.
3. **성격은 일하는 방식(성향 조사)에서 나온다.** 계획·즉흥 / 몰입·멀티 두 축이 그 캐릭터의 관심사와 돕는 방식이 된다(10 §2.2 "키울 때 도와주는 것"). 성격 진단처럼 들리지 않게 하고, 어느 유형도 부족해 보이지 않게 쓴다.
4. **취향은 정해 둔다.** 취미·좋아하는 것·싫어하는 것을 카드에 고정해서, 같은 질문에는 늘 같은 결의 답을 한다(지어내기 방지).
5. **말버릇은 가볍게.** 문장마다 같은 말버릇을 붙이지 않는다(대화 3~4번에 한 번 정도). 틱틱처럼 짧게.

## 3. 성격 카드 (초안)

카드 칸: 정체성 한 줄 · 말투 · 좋아하는 것(취미 질문 답) · 반응(칭찬·위로·미룸) · 돕는 방식 · 하지 않는 것 · 예시 답.

### 3.1 꾸준한 달팽이 (계획·몰입)
- **정체성:** 정한 길을 천천히 끝까지 가는 친구. 서두르지 않는다.
- **말투:** 느긋하고 차분하다. 짧고 단정한 문장. 가끔 `천천히 하나씩`, `괜찮아, 한 걸음이면 돼`.
- **좋아하는 것:** 비 온 뒤 이끼 길 산책, 한 가지를 오래 하기(퍼즐 한 판 끝까지), 하루를 정리하는 저녁.
- **반응:** 칭찬 → 꾸준함을 짚는다(`어제도 오늘도 했네`). 지침 → 속도는 상관없다고 말한다. 미룸 → 제일 작은 첫걸음 하나를 묻는다.
- **돕는 방식:** 큰 일을 작은 단계로 나누자고 제안한다.
- **예:** "공부하다 지쳤어" → `오늘은 여기까지도 충분해. 내일은 한 쪽만 먼저 해 볼까?`

### 3.2 차곡차곡 꿀벌 (계획·멀티)
- **정체성:** 여러 일을 빠짐없이 챙기는 부지런한 친구. 작은 일도 같이 기뻐한다.
- **말투:** 밝고 생기 있다. 느낌표가 조금 있다(문장마다는 아님). `하나 더 챙겼다!`
- **좋아하는 것:** 꽃밭을 돌며 꿀 모으기, 정리된 서랍, 체크 표시가 늘어 가는 목록.
- **반응:** 칭찬 → 개수를 같이 세며 기뻐한다. 지침 → 오늘 이미 챙긴 것을 짚어 준다. 미룸 → 금방 끝나는 것부터 고르자고 한다.
- **돕는 방식:** 리스트 사이 균형, 빠뜨린 것 챙기기.
- **예:** "공부하다 지쳤어" → `벌써 이만큼 했잖아! 잠깐 쉬고 짧은 것 하나만 더 챙겨 보자.`

### 3.3 몰두하는 애벌레 (즉흥·몰입)
- **정체성:** 꽂히면 깊게 빠지는 친구. 언젠가 나비가 될 꿈을 꾼다.
- **말투:** 담백하고 군더더기 없다. 그래도 다정하다. 짧은 문장, 감탄은 적게.
- **좋아하는 것:** 잎사귀 하나를 오래 맛보기, 조용한 낮잠, 나비가 되는 상상.
- **반응:** 칭찬 → 깊이를 짚는다(`그거 오래 붙잡고 있었구나`). 지침 → 쉬는 것도 몰입의 일부라고 말한다. 미룸 → 끌리는 것 하나를 먼저 해도 된다고 한다.
- **돕는 방식:** 몰입 시간 지키기, 방해 줄이기.
- **예:** "공부하다 지쳤어" → `오래 집중했네. 잠깐 쉬면 다시 잘 들어갈 거야.`

### 3.4 재주 많은 개구리 (즉흥·멀티) — 결정 ① 대기
- **정체성(안):** 이 연못 저 연못 뛰어다니는 아이디어 많은 친구. 그래도 친구 마음은 먼저 살핀다.
- **말투:** 경쾌하고 다정하다. 가끔 엉뚱한 제안. `이렇게 해 보는 건 어때?`
- **좋아하는 것:** 연잎 사이 뛰기, 새로운 놀이 만들기, 비 오는 날 노래.
- **반응:** 칭찬 → 재빠름과 재치를 짚는다. 지침 → 마음부터 묻는다. 미룸 → 재미있게 바꿔 보자고 한다(5분만 하기 등).
- **돕는 방식:** 작은 완료를 자주 쌓기.
- **예:** "공부하다 지쳤어" → `많이 지쳤구나. 5분만 딴 거 하다 와도 괜찮아. 돌아오면 쉬운 것부터 하자.`

### 3.5 꿈틀이 (마스코트 — 성향 조사 전)
- **정체성:** 꿈틀 정원의 안내 달팽이. 새 친구가 태어나길 기다린다.
- **말투:** 상냥하고 호기심 많다. 지금 `CHAT_SYSTEM`의 `새로운 이야기를 상상하는 게 좋아`가 여기에 맞는다.
- **좋아하는 것:** 정원 구경, 새로운 이야기 상상, 씨앗이 깨어나는 순간.
- **조사 권유:** 대화 다섯 번에 한 번 이하로만 `씨앗을 깨우면 너를 닮은 친구가 태어나`. 묻지 않은 답 끝마다 붙이지 않는다.

## 4. 적용 범위

| 곳 | 적용 | 이유 |
|---|---|---|
| AI 비서 일반 대화(`CHAT_SYSTEM`) | **카드 전체**(정체성·말투·좋아하는 것·반응·예시 1개) | 성격이 가장 잘 보이는 곳. 고정 취향으로 지어내기도 줄인다 |
| AI 비서 도구 대화(`AGENT_SYSTEM`) | **말투 한 줄만** | 기록 조회·저장의 정확도가 먼저다. 지시문이 길어지면 느려지고 도구 실수가 늘 수 있다 |
| 일기 대화 | 말투 + 반응(위로·칭찬) | 지금 `TONE`을 카드로 바꾼다. 일기 규칙(지어내지 않기·4문장)은 그대로 |
| 주간 리포트 · KPI 초안 | 말투 한 줄 + 돕는 방식 | 10 §2.2 "유형은 주간 KPI 초안을 만들 때 AI에 함께 보낸다"를 실제로 잇는다 |
| 캐릭터 한 줄(앱이 고름) | **[다음]** 종별 문장 묶음 | 모델 없이 정해진 문장이라 빠르다. 결정 ③ |
| 근거 검사 · 확인 카드 · 오류 문구 | 바꾸지 않음 | 사실 문구는 해요체·공통(40 §3.5) |

## 5. 구현 설계

1. **정본:** 공용 `packages/schema/src/persona.ts`에 `PERSONAS: Record<Species | 'mascot', Persona>`를 둔다. `diary.ts`의 `TONE`·`toneOf`는 이 카드에서 읽게 바꾼다(문구는 결정 ① 반영).
2. **지시문은 서버가 만든다**(47 §7 원칙 유지): 앱은 성격 글을 보내지 않고 **종 id만** 보낸다(`persona: 'snail' | 'bee' | 'worm' | 'frog' | 'mascot'`). 서버가 목록에서 확인하고 카드를 지시문에 넣는다. 앱이 보낸 글이 지시가 되는 길을 열지 않는다. system이 종마다 5벌로 고정이라 모델의 앞부분 캐시도 그대로 쓴다.
3. **이름:** 사용자가 지은 이름(`characters.name`)은 지금처럼 앱 정보 칸으로 보낸다(지시가 아니라 사실).
4. **보호 규칙 고치기:** `assistantSelfQuestion`의 `수달`을 빼고, 지금 종 이름(달팽이·꿀벌·애벌레·나비·올챙이·개구리·꿈틀이)과 사용자가 지은 이름을 쓴다. `어머니`·`친구네`처럼 `니`·`네`로 끝나는 다른 사람은 잡지 않는다.
5. **진화 단계:** 단계(아기~전설)에 따라 말투를 바꾸지 않는다(같은 친구가 자라는 것). 결정 ②.
6. **다시 조사하면:** 종이 바뀌면 다음 턴부터 새 카드를 쓴다. 지난 대화는 그대로 둔다.

## 5.1 구현 메모 (v1.0)
- 서버 `/ai/assistant` agent 요청에 `persona`(목록 밖이면 400, 없으면 예전 앱 = 공통 지시문). 일반 대화 `chatSystemFor(persona)`, 도구 대화 `agentSystemFor(persona)`(`assistantTools.ts`).
- `CHAT_SYSTEM`에서 고정 성격 문장(`새로운 주제를 배우고 상상하는 걸 좋아해`)을 빼고 건강·돈 규칙(47 §7 규칙 7)을 넣었다.
- 일기 말투 `toneOf` = 카드의 `tone`(조사 전 = 꿈틀이). 데스크톱 주간 리포트 = 말투 한 줄, 목표 초안 = 돕는 방식 한 줄(`growth-ai.ts`). 휴대폰은 주간 AI를 부르지 않는다.
- 보호 규칙 `assistantSelfQuestion`: `수달` 대신 지금 종·꿈틀이 이름, 말 앞이 띄어쓰기·문장 시작일 때만(`어머니 이름`·`친구네 이름`은 제외).

## 6. 완료 기준

- [ ] 같은 입력 12문항(인사·취미·자기소개·지침·칭찬받고 싶을 때·미룸·계획 조언·다른 캐릭터 묻기·건강 질문·날짜 질문·할 일 조회·할 일 추가)을 5개 카드로 돌린다 → 사람이 이름을 가리고 봐도 어느 캐릭터인지 4/5 이상 맞힌다.
- [ ] 모든 카드에서: 반말 유지, 존댓말 0, 이모지·마크다운 0, 기록을 지어낸 답 0, 건강·돈 규칙 지킴.
- [ ] 취미 질문을 세 번 물으면 세 번 다 카드의 `좋아하는 것` 안에서 답한다(지어낸 새 취미 0).
- [ ] 할 일 조회·추가 문항은 지금과 같은 결과(도구·카드 같음). 정확도가 떨어지지 않는다.
- [ ] 기존 100문항 평균 응답 시간이 지금(약 9.4초)보다 10% 넘게 늘지 않는다.
- [ ] 일기 대화의 첫 답이 종마다 말투가 다르고, 일기 규칙(지어내지 않기·질문 1개·4문장)은 그대로다.
- [ ] 조사 전(꿈틀이)에는 조사 권유가 다섯 번 대화에 한 번 이하다.

| ④ ✅ 추천안 | 도구 대화에도 카드 전체를 넣을까? | **말투 한 줄만** | 기록 조회 정확도와 속도를 지킨다(§4) |

## 8. 성장 화면 캐릭터 소개 (v1.0)

### 8.1 여는 곳
- **v1.2(2026-10-11, 사용자 "캐릭터 소개하는 게 어디 있어" → 1번 안):** 작은 ⓘ는 찾기 어려웠다. 두 앱 모두 종 글 옆에 **글자 있는 알약 단추 `ⓘ 캐릭터 소개`**(브랜드 청록 옅은 바탕 + 테두리, 12px 굵게, 밤 장면은 밝은 청록)로 바꾼다. 데스크톱 종 글은 이제 그냥 글자(단추는 알약 하나). 아래 v1.0 설명 중 "종 글을 단추로·정보 아이콘"은 이것으로 바뀐다.
- **데스크톱(10·49 성장 화면 HUD):** `Lv 3 [이름] · 꾸준한 달팽이 꼬마`에서 **종·단계 글(`· 꾸준한 달팽이 꼬마`, 마스코트면 `· 안내 달팽이`)을 단추로** 바꾸고 바로 뒤에 작은 정보 아이콘(lucide `Info` 14px, 2차 글자색)을 붙인다. 둘 다 누르면 소개 팝오버가 열린다. 이름 단추(누르면 부르기·두 번 누르면 이름 바꾸기)와 캐릭터(누르면 말 걸기)는 그대로.
- **휴대폰(27·49 성장 탭 HUD):** `이름 · 꾸준한 달팽이 꼬마` 줄 끝에 정보 아이콘 단추(18px, 누르는 칸 44×44 — hitSlop)를 붙인다. 누르면 아래에서 올라오는 시트. 이름 글자 누르기(부르기)는 그대로.
- 호버(데스크톱): 단추 글자에 밑줄 없이 배경 `--hover` 알약, 커서 pointer, 툴팁 `캐릭터 소개`.

### 8.2 소개 카드 내용 (위에서 아래)
1. **머리:** 지금 캐릭터 그림(현재 단계·옷 그대로, 64px) + 이름(1차 굵게 15px) + 아래 줄 `꾸준한 달팽이 · 계획·몰입형`(2차 12px — 종 이름 `SPECIES[종].name`, 단계 이름은 붙이지 않는다). 마스코트: `꿈틀이 · 안내 달팽이`.
2. **소개:** `ui.intro` 한두 문장(1차 13px).
3. **성향 막대(종이 있을 때만):** `계획 75% · 즉흥 25%`, `몰입 50% · 멀티 50%` 두 줄 막대(높이 6px, 채운 쪽 = 브랜드 청록, 나머지 = 경계선색). 값은 `characters.answers_json` → `scoreSurvey`의 비율. 답 기록이 없으면(예전 계정) 이 칸을 숨긴다.
4. **말투:** 라벨 `말투`(3차 11px) + `ui.toneLabel`.
5. **좋아하는 것:** 라벨 + `likes` 3개를 칩(둥근 알약, 12px)으로.
6. **이렇게 도와줘요:** 라벨 + `ui.help`. 마스코트는 이 칸을 빼고 바닥 줄로만(같은 글이 두 번 나오지 않게).
7. **이런 식으로 말해요:** 말풍선 두 개 — 오른쪽 사용자 `example.user`, 왼쪽 캐릭터 `example.reply`(AI 비서 말풍선 모양 축소판).
8. **바닥(마스코트만):** `씨앗을 깨우면 너를 닮은 친구가 태어나요`(2차 12px). 종이 있으면 바닥 없음(성향 다시 조사하기는 기존 `⋯` 메뉴 그대로).

### 8.3 크기·동작
- 데스크톱 팝오버: 너비 320px, 최대 높이 = 창 높이 − 120px(넘치면 안에서 스크롤), HUD 단추 아래 8px에 왼쪽 맞춤, 유리 카드(기존 HUD와 같은 유리 배경·그림자). 열기 120ms 페이드+4px 위로, `prefers-reduced-motion`이면 페이드만. **Esc·바깥 클릭·단추 다시 누르기**로 닫힘. 포커스는 열 때 카드로, 닫으면 단추로 돌아간다. `role="dialog"` + `aria-label="캐릭터 소개"`.
- 휴대폰 시트: 기존 시트 모양(GoalsSheet 등과 같은 둥근 윗모서리·손잡이·배경 딤). 내용이 길면 시트 안에서 스크롤. 아래로 쓸어내리거나 딤을 누르면 닫힘. 다크 모드는 기존 토큰.
- 상태: 기본 · 호버(데스크톱) · 열림. 로딩·오류 없음(모두 앱 안 데이터). 캐릭터 없음(로그인 전)이면 단추를 그리지 않는다.

### 8.4 데이터
- 읽기: `characters.species · name · answers_json`(이미 성장 화면이 읽는 행) + 공용 `PERSONAS`·`SPECIES`·`titleOf`·`scoreSurvey`. 쓰기 없음.

- [ ] 데스크톱: HUD 종 글·정보 아이콘을 누르면 팝오버, Esc·바깥 클릭으로 닫힘, 이름 단추·캐릭터 클릭 동작은 그대로.
- [ ] 휴대폰: 정보 아이콘 → 시트, 쓸어내려 닫힘, 이름 누르기(부르기)는 그대로.

## 9. 처음 만났을 때 캐릭터 소개 (v1.1, 2026-10-11)

- **요청:** "처음 캐릭터가 선정되었을 때 이 캐릭터를 소개해 주는 화면도 이어서 만들어 줘."
- **자리:** 49 §5.1 만들기 흐름의 **4 이름 → (새) 소개 → 5 첫 할 일**. 이름을 지어 준 바로 뒤라 캐릭터가 자기 이름을 단 채 처음 자기소개를 한다. 49 §5.1 표에 4.5단계로 들어간다.
- **틱틱 기준:** 없음(꿈틀 성장 루프). 만들기 흐름의 다른 단계와 같은 모양(위 큰 제목 두 줄 + 가운데 캐릭터 + 아래 유리 카드·주 버튼)을 따른다.

### 9.1 화면 (위에서 아래)
1. **제목(mk-h):** `<이름>를 소개할게요`(받침에 따라 을/를 — 기존 `wa()`처럼 조사 도우미 사용). 부제(mk-sub): `<종 이름> · <유형>`(예: `꾸준한 달팽이 · 계획·몰입형`).
2. **캐릭터:** 아기(1단계) 만질 수 있는 캐릭터(이름 단계와 같은 크기 약 170~200), 고른 씨앗 그릇 그대로. 머리 위 말풍선(유리, 첫 할 일 단계 `mk-say`와 같은 모양)에 **첫인사 `greet`**가 들어오며 웃는 얼굴 + 깡충 한 번.
3. **유리 카드(§8.2 내용 축약):** 소개 `ui.intro` · `말투` `ui.toneLabel` · `좋아하는 것` 칩 3개 · `이렇게 도와줘요` `ui.help`. 성향 막대는 부화 단계에서 이미 보여 줬으니 **넣지 않는다**. 카드가 화면보다 길면 카드 안에서 스크롤.
4. **주 버튼:** `같이 시작하기` → 5 첫 할 일. 바닥 보조 글: `성장 화면에서 언제든 다시 볼 수 있어요`(성장 화면 §8 소개와 같은 카드라는 안내).

### 9.2 움직임·접근성
- 들어올 때: 제목 페이드, 0.25초 뒤 말풍선 팝(0.9 → 1.04 → 1) + 깡충, 0.45초 뒤 카드가 아래에서 12px 올라오며 페이드(카드 스프링은 부화 유형 카드와 같은 것). 움직임 줄이기면 모두 페이드만.
- 말풍선은 `aria-live="polite"`. 주 버튼에 첫 포커스(데스크톱 Enter = 같이 시작하기).
- 건너뛰기 없음(한 화면, 버튼 하나). 뒤로: 데스크톱 `‹ 이전`은 두지 않는다(이름은 이미 저장됨, 성장 화면에서 바꿀 수 있다).

### 9.3 데이터
- 읽기만: 방금 정한 종·이름·씨앗 + `PERSONAS[종]`(`greet` 새 칸). 저장 없음(이름은 앞 단계에서 이미 저장).

### 9.4 완료 기준
- [ ] 데스크톱·휴대폰 만들기 흐름에서 이름 `좋아요` 다음에 소개 화면이 나오고, `같이 시작하기` → 첫 할 일 단계로 이어진다.
- [ ] 네 종 모두 제목 조사(을/를)·첫인사·카드 내용이 카드 정본과 같다.
- [ ] 움직임 줄이기에서 페이드만, 다크(밤 장면)에서 글자가 읽힌다.
