## A. 리스트·폴더 아이콘 고르기 [틱틱]
### A.1 지금 문제
- 목록 추가·편집 창의 이름 왼쪽 `≡` 칸이 **눌러도 아무것도 안 열린다**(05에 "이모지" 항목이 있지만 선택기가 없음).
- "스마트 목록에 표시" 드롭다운이 브라우저 기본 모양(파란 테두리)이다.
- 오른쪽 **실시간 미리보기**가 없다(틱틱은 두 칸).

### A.2 아이콘 선택기 (틱틱 Add List와 같게)
| 요소 | 내용 |
|---|---|
| 여는 곳 | 이름 왼쪽 정사각 버튼(36×36). 기본 `≡`(리스트 아이콘), 고른 뒤엔 그 이모지 |
| 팝오버 (폭 320) | 맨 위 검색칸(`이모지 검색` — 한국어·영어 이름) → `자주 쓰는` 줄(최근 고른 16개, 기기 저장) → 분류 탭(사람·자연·음식·활동·여행·사물·기호·깃발) → 8열 격자, 칸 36 |
| 맨 위 왼쪽 | `없음`(기본 `≡`로 되돌리기) |
| 키보드 | 검색칸 자동 초점, ↑↓←→ 이동, Enter 고르기, Esc 닫기 |
| 저장 | `lists.emoji`(이미 있는 칸). 스키마 변경 없음 |
| 이모지 자료 | 오픈 라이선스 이모지 이름표(유니코드 CLDR 한국어 이름 포함)를 앱에 넣는다. 그림은 OS 기본 이모지 글꼴 — 틱틱 자산 사용 없음 |

### A.3 목록 추가·편집 창 두 칸 [틱틱]
- 왼쪽 폼(폭 360): 아이콘+이름 · 목록 색상(없음 + 8색) · 폴더(드롭다운) · 스마트 목록에 표시(드롭다운: `모든 작업` / `표시 안 함`).
- 오른쪽 미리보기(폭 260): 사이드바 행 모양(아이콘·이름·색 점) + 그 리스트 화면 축소 그림(머리 제목, 회색 행 3줄). 고르는 즉시 바뀐다.
- 드롭다운은 앱 공용 메뉴 팝오버(02 메뉴 모양)로 — 브라우저 기본 `select` 쓰지 않음.
- 좁은 창(폭 < 640)에서는 미리보기 숨김.

### A.4 폴더 아이콘 [sprout — 틱틱 폴더는 이모지 칸이 없음]
- **오류 원인:** 틱틱에서 가져온 폴더 이름에 이모지가 붙어 있다(`🥺Me`, `🎓Study`). 리스트는 가져올 때 이모지를 따로 떼지만 폴더는 `folders`에 이모지 칸이 없어 이름째 저장 → 사이드바에 **📁 + 🥺Me** 두 아이콘이 붙어 보인다.
- **표시 규칙(스키마 변경 없음):** 폴더 이름이 이모지로 시작하면 그 이모지를 폴더 아이콘 자리에 쓰고, 이름에서는 뗀다. 아니면 기존 폴더 그림. 편집 창도 리스트와 같은 아이콘 선택기 — 고른 이모지는 이름 앞에 붙여 저장(`🎓Study`)하고 표시할 때 떼어 낸다.
- 이름에서 이모지를 떼는 함수는 틱틱 가져오기의 `splitEmoji`와 같은 것을 공용으로 쓴다.

## B. "내 리스트"와 "AI 정리"를 구분한다 [sprout]
### B.1 왜 헷갈리나
sprout에는 **할 일을 묶는 방법이 세 가지** 있다. 지금은 화면마다 이름·모양이 비슷해 구분이 안 된다.
| | 무엇 | 누가 만드나 | 할 일 하나당 | 지금 보이는 곳 |
|---|---|---|---|---|
| **리스트**(폴더 안) | 내가 정한 보관함 — 틱틱과 같은 개념 | **사용자** | 정확히 1개 | 사이드바 |
| **영역 › 주제** | 할 일을 삶의 영역(학교·회사…)과 주제(과목·프로젝트)로 묶은 **관점** | **AI가 제안**, 사용자가 고칠 수 있음 | 0~1개 | 작업 지도 |
| **위키 주제** | 수집함 자료(메모·링크)를 공부 주제로 묶은 페이지 | **AI**, 사용자가 고칠 수 있음 | (할 일 아님) | 수집함 › 위키 |

### B.2 원칙
1. **리스트는 내 것, 영역은 AI의 정리.** 리스트는 AI가 절대 만들거나 바꾸지 않는다(할 일을 다른 리스트로 옮기지도 않는다). AI는 영역·주제·위키만 만든다.
2. **AI가 만든 것은 항상 표시가 있다.** 같은 모양으로 섞지 않는다.
3. **사용자가 손대면 "내 것"이 된다.** AI 표시가 사라지고 AI가 다시 바꾸지 않는다(14의 `source = user` 규칙 그대로).

### B.3 보이는 모양 (시각 언어)
| 요소 | 리스트(사용자) | 영역·주제(AI) | 사용자가 고친 영역·주제 |
|---|---|---|---|
| 아이콘 | 고른 이모지 또는 `≡` | **✦ 반짝이 배지**가 붙은 영역 그림 | 반짝이 없이 영역 그림 |
| 이름 옆 | 없음 | 작은 꼬리표 `AI 정리`(3차 글자, 처음 7일 [임시]) | 없음 |
| 색 | 리스트 색 | 영역 색(중립 회색 계열 + 강조색 테두리) — 리스트 색과 같은 팔레트를 쓰지 않는다 | 사용자가 고른 색 |
| 툴팁 | 리스트 이름 | `AI가 할 일 제목을 보고 묶었어요 · 직접 고치면 그대로 둬요` | 영역 이름 |
| "확인 필요" | — | 확신이 낮으면 점선 테두리 + `확인 필요` | — |

### B.4 화면별 규칙
| 화면 | 리스트 | 영역·주제 |
|---|---|---|
| **사이드바** | 지금처럼 `리스트` 구역 | **새 구역 `AI 정리` (기본 접힘)** — 리스트 구역 아래, 태그 위. 영역 → 주제 2단, ✦ 머리 아이콘, 누르면 그 영역의 할 일 목록(읽기 전용 스마트 목록). 머리 `⋯` → `작업 지도에서 보기`·`구역 숨기기` |
| **할 일 행** | 오른쪽 메타에 리스트 이름(지금과 같음) | 표시 안 함(행이 복잡해짐) |
| **할 일 상세** | 맨 위 리스트 선택기(지금과 같음) | 아래 속성 줄에 칩 `✦ 학교 › 운영체제` — 누르면 영역 바꾸기 팝오버(바꾸면 `source=user`) · `작업 지도에서 보기` |
| **작업 지도** | 거름틀 `범위: 리스트`(있음). 카드에 리스트 색 점(있음) | 영역 노드·열에 ✦ 배지와 `AI 정리` 꼬리표 규칙 적용 |
| **검색 · 필터** | `~리스트` 문법 | 필터 조건에 `영역/주제` 추가(`영역 = 학교`), 검색 결과에 영역 칩 |
| **빠른 추가** | `~리스트` | 영역은 고르지 않는다(자동 분류가 한다) |
| **수집함 위키** | — | 위키 주제에도 같은 ✦ 규칙(AI가 만든 주제 = ✦, 이름을 바꾸면 사라짐) |
| **모바일** | 서랍의 리스트 | 더보기 › 작업 지도 + 상세 칩(같은 규칙) |

### B.5 이름 충돌
- AI가 만든 영역 이름이 리스트 이름과 같으면(예: 리스트 `대학교`, 영역 `대학교`) 영역 이름 뒤에 `· AI` 를 붙여 보이고, 작업 지도 첫 화면에 한 번 안내: `리스트 '대학교'와 이름이 같은 AI 영역이 있어요 — 리스트는 내가 만든 보관함, 영역은 AI가 묶은 관점이에요.`
- 설정에 `AI 정리를 리스트로 만들기`는 두지 않는다(원칙 1) [임시 — 요청이 많으면 다음에 "이 영역을 리스트로 옮기기" 일괄 기능].

### B.6 처음 쓰는 사람에게 설명
- 작업 지도 첫 실행 카드(14 첫 상태)에 그림 한 장: 왼쪽 "리스트 = 내 서랍", 오른쪽 "영역 = AI가 펼친 지도". 문구 두 줄.
- 사이드바 `AI 정리` 구역을 처음 펼칠 때 같은 한 줄 안내(한 번만).

## C. 데이터
- A: `lists.emoji` 그대로, 폴더는 이름 앞 이모지(스키마 변경 없음). 최근 고른 이모지 = 기기 저장.
- B: 영역·주제 = 기존 `map_areas`(`source` 'ai'|'user'), 할 일 배정 = `task_areas`. **새 칸 없음.** AI 정리 꼬리표 7일 = `map_areas.created_at` 기준. 사이드바 구역 접힘 = 기기 저장.
- 필터에 영역 조건 = `filters.rule_json`에 `area` 조건 추가(형식만 늘림, 스키마 변경 없음).
