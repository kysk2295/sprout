## A. 리스트·폴더 아이콘 고르기 [틱틱]
### A.1 지금 문제
- 목록 추가·편집 창의 이름 왼쪽 `≡` 칸이 **눌러도 아무것도 안 열린다**(05에 "이모지" 항목이 있지만 선택기가 없음).
- "스마트 목록에 표시" 드롭다운이 브라우저 기본 모양(파란 테두리)이다.
- 오른쪽 **실시간 미리보기**가 없다(틱틱은 두 칸).

### A.2 아이콘 선택기 (틱틱 Add List와 같게)
| 요소 | 내용 |
|---|---|
| 여는 곳 | 이름 왼쪽 정사각 버튼(36×36). 기본 `≡`(리스트 아이콘), 고른 뒤엔 그 이모지 |
| 팝오버 (폭 320) | 맨 위 검색칸(`이모지 검색` — 한국어·영어 이름·태그, 한국어는 띄어쓰기 무시) → `자주 쓰는` 줄(최근 고른 16개, 기기 `sprout.emoji.recent`) → 분류 탭(사람·자연·음식·활동·여행·사물·기호·깃발) → 8열 격자, 칸 36(격자 높이 216, 세로 스크롤) |
| 맨 위 왼쪽 | `없음`(기본 `≡`로 되돌리기) |
| 키보드 | 검색칸 자동 초점, ↑↓←→ 이동, Enter 고르기, Esc 닫기 |
| 저장 | `lists.emoji`(이미 있는 칸). 스키마 변경 없음 |
| 이모지 자료 | emojibase-data 16.0.3(MIT) ko/en — 이름·태그는 유니코드 CLDR 주석. 1,906개(피부색 변형 제외)를 `data/emojiData.ts`로 앱에 넣고 선택기를 처음 열 때 따로 불러온다(약 220KB 별도 묶음). 그림은 OS 기본 이모지 글꼴 — 틱틱 자산 사용 없음 |

### A.3 목록 추가·편집 창 두 칸 [틱틱]
- 왼쪽 폼(폭 360): 아이콘+이름 · 목록 색상(없음 + 8색) · 폴더(드롭다운) · 스마트 목록에 표시(드롭다운: `모든 작업` / `표시 안 함`).
- 오른쪽 미리보기(폭 260): 사이드바 행 모양(아이콘·이름·색 점) + 그 리스트 화면 축소 그림(머리 제목, 회색 행 3줄). 고르는 즉시 바뀐다.
- 드롭다운은 앱 공용 메뉴 팝오버(02 메뉴 모양)로 — 브라우저 기본 `select` 쓰지 않음.
- 좁은 창(폭 < 640)에서는 미리보기 숨김.

### A.4 폴더 아이콘 [sprout — 틱틱 폴더는 이모지 칸이 없음]
- **오류 원인:** 틱틱에서 가져온 폴더 이름에 이모지가 붙어 있다(`🥺Me`, `🎓Study`). 리스트는 가져올 때 이모지를 따로 떼지만 폴더는 `folders`에 이모지 칸이 없어 이름째 저장 → 사이드바에 **📁 + 🥺Me** 두 아이콘이 붙어 보인다.
- **표시 규칙(스키마 변경 없음):** 폴더 이름이 이모지로 시작하면 그 이모지를 폴더 아이콘 자리에 쓰고, 이름에서는 뗀다. 아니면 기존 폴더 그림. 편집 창도 리스트와 같은 아이콘 선택기 — 고른 이모지는 이름 앞에 붙여 저장(`🎓Study`)하고 표시할 때 떼어 낸다.
- 이름에서 이모지를 떼는 함수는 틱틱 가져오기의 `splitEmoji`와 같은 것을 공용으로 쓴다(`src/shared/emoji.ts`, 가져오기는 다시 내보내기만). 폴더 이름 바꾸기(작업 지도에서 두 번 눌러 고치기)는 앞 이모지를 그대로 둔다.
- 폴더 편집 창은 한 칸(아이콘 + 이름). 목록 편집 창만 두 칸.
- 리스트도 같은 표시 규칙: 이모지 칸(`lists.emoji`)이 비었는데 이름이 이모지로 시작하면(`💰가계부`) 그 이모지를 아이콘 자리에 쓰고 이름에서 뗀다 — `≡ + 💰가계부` 겹침 방지. 사이드바·리스트 고르기·캘린더 왼쪽 패널에 적용(`listView`, 저장 값은 그대로).

### A.5 폴더 그림은 폴더에만 (2026-10-06 사용자 "리스트에 폴더 아이콘이 있는데 그게 왜 있는지 모르겠어")
- **원인 세 곳:** ① 휴대폰 서랍 폴더 행이 A.4를 안 따라 `📁 + 🥺Me`로 보였다 — 이름 앞 이모지가 있는 폴더가 리스트처럼 보이는데 폴더 그림이 붙음. ② 휴대폰 작업 지도 프로젝트 카드(29 §9.1)·데스크톱 프로젝트 보드·프로젝트 화면 제목(31 §12.9.0)이 이모지 없는 프로젝트에 **회색 폴더 그림**을 썼다 — 프로젝트(🚀 태그)가 폴더처럼 보임. ③ 데스크톱 주간 점검 ③ 프로젝트 제안 기본 아이콘 `📁`, 알림 판 프로젝트 알림 폴더 그림.
- **규칙(틱틱 그대로 + 프로젝트):**
  | 무엇 | 아이콘 |
  |---|---|
  | 리스트 | 고른 이모지(`lists.emoji`) → 이름 앞 이모지 → 없으면 기본 리스트 아이콘 `≡`. 리스트 색은 오른쪽 작은 점(틱틱 서랍) |
  | 기본함 | 기본함 그림(스마트 목록 색) |
  | 폴더 | 이름 앞 이모지가 있으면 그 이모지(A.4), 없으면 폴더 그림. **폴더 그림은 여기에만 쓴다.** 행 오른쪽 `›`/`⌄`로 펼침이 보인다 |
  | 프로젝트(태그 kind project) | 이름 앞 이모지 → 없으면 `🚀`(33 §4.1 종류 아이콘과 같음). 폴더 그림 금지 |
- 휴대폰 서랍: 리스트 = 이모지 또는 `≡`(18, 회색 2차) + 리스트 색이 있으면 개수 오른쪽 색 점(8). 폴더 = A.4 규칙, 이름은 이모지를 뗀 글. 리스트 화면 머리(큰 제목)도 같은 규칙으로 폴더 이모지를 떼어 앞에 둔다.
- 휴대폰 서랍 태그 묶음: 종류 있는 태그는 `#` 대신 종류 아이콘(프로젝트 🚀 · 사람 👤 · 장소 📍, 이름 앞 이모지가 있으면 그것) + 이모지를 뗀 이름. 길게 누름 메뉴 `프로젝트에서 빼기` 아이콘도 폴더 그림이 아닌 빼기(⊖).
- 공용 함수: 휴대폰 `src/data/emojiLead.ts` `splitLead(name)`·`listShow` + 그림 `src/ui/OrgIcons.tsx`(데스크톱 `shared/emoji.ts` `splitEmoji`와 같은 규칙) — 저장 값은 그대로.
- 완료 기준: 서랍에 `📁 + 이모지` 겹침 없음 · 이모지 없는 리스트는 `≡` · 이모지 없는 프로젝트는 휴대폰 카드·데스크톱 보드·프로젝트 화면 제목·점검 ③ 모두 `🚀` · 폴더 그림은 폴더 행·폴더 고르기에만.
- **태그도 같은 규칙(2026-10-10, 사용자 "🚀🎓 졸업 프로젝트 태그에 아이콘이 두 개"):** 태그 아이콘 = 이름 앞 이모지 → 없으면 종류 아이콘(👤🚀📍) → 주제는 `#`/태그 그림. 이름에서는 앞 이모지를 뗀다. 이름 앞 이모지가 여럿이면(`🚀🎓 졸업 프로젝트`) **모두 떼고 하나만** 쓰며, 종류 기본 아이콘(👤🚀📍)이 아닌 것을 먼저 고른다 → `🎓 졸업 프로젝트`. 아이콘 칸이 없는 알약(데스크톱 행·상세 태그 알약, 태그 고르기 메뉴, 필터 편집, 캘린더 태그 묶음)은 `이모지 하나 + 이름`(이름 앞 이모지가 없으면 이름만). 공용 함수 `tagShow`·`tagText`(데스크톱 `src/shared/emoji.ts`, 휴대폰 `src/data/emojiLead.ts` — 같은 규칙, 시험 있음). 적용: 휴대폰 행 태그 알약·상세 태그 칩·태그 페이지 머리/관련 태그·빠른 입력 `#` 제안·태그 시트·더보기 › 태그·서랍 태그·검색 태그·태그 묶기 머리·태그 보기 제목 / 데스크톱 사이드바 태그·행·상세 알약·태그 고르기·필터 편집·태그 페이지 머리·`[[` 자동 완성·캘린더 왼쪽 태그·색 기준 태그·정렬 패널 태그 묶음. 저장 값(태그 이름)은 그대로, 편집 창은 저장된 이름 그대로 보여 준다. 프로젝트 카드·주간 점검 프로젝트 줄이 쓰는 공용 `projectEmoji`·`projectTitle`(`packages/schema/src/projects.ts`)도 같은 규칙(앞 이모지 여럿 → 하나, 이름에서는 모두 뗌).

## B. 리스트 하나로 — AI는 제안만 [sprout]
### B.0 사용자 결정 (2026-10-05, 그대로 기록)
1. "리스트와 AI 정리를 하나로 합친다. 틱틱처럼 내가 수정도 할 수 있는 구조. 괜히 기능을 나누면 헷갈린다."
2. "기본함에 들어온 새 할 일(리스트를 직접 고르지 않은 것)은 확실하면 자동 이동, 애매하면 제안." 확신도(high/low)를 받아 high이고 이미 있는 리스트면 바로 옮기고 토스트 `🏫대학교로 옮겼어요 · 되돌리기`(되돌리면 그 할 일은 다시 제안하지 않음). low면 제안 칩. 사용자가 직접 리스트를 고른 할 일·이미 다른 리스트에 있는 할 일은 절대 옮기지 않는다. 쌓여 있던 기본함 할 일(264개)은 자동 이동하지 않고 기본함 정리로만(일괄은 사용자가 누를 때). 설정 › 할 일에 `새 할 일 자동 분류`(기본 켬).
3. 사용자는 틱틱에서 리스트를 귀찮아서 안 썼다(그래서 기본함 264개) → **AI가 리스트 구조까지 제안하고 사용자가 승인**한다. 새 주제가 쌓이면 새 리스트를 제안한다. **AI는 승인 없이 리스트를 만들지 않는다.**

→ 개념은 하나: **폴더 › 리스트 › 할 일**(틱틱 모델). 따로 있던 AI "영역 › 주제"와 ✦ AI 배지·`AI 정리` 사이드바 구역은 없앤다. 작업 지도는 내 폴더·리스트를 보여 주고 거기서 직접 고친다([14 v2.0](14-work-map.md)).

### B.1 AI가 하는 일 3가지 (전부 제안, 쓰기는 사용자 승인 뒤)
| | 언제 | 무엇 | 쓰기 |
|---|---|---|---|
| ① **기본함 정리** | 기본함이 20개 넘으면 기본함 화면 위 카드 · 작업 지도 기본함 노드/열의 ✦ · 작업 지도 머리 ✦ · 설정 › 할 일 | 기본함 할 일 전체를 보고 **리스트 5~8개 제안**(이모지 · 이름 · 할 일 수 · 예시 제목 3개). 이미 있는 리스트와 같은 주제면 그 리스트를 다시 쓴다(중복을 만들지 않음) | [이대로 만들기] = 켠 것만 한 번에 리스트 만들기 + 할 일 옮기기(한 트랜잭션). 남는 것은 기본함 |
| ② **새 할 일 분류** | 기본함에 새로 들어온 할 일(기준 시각 뒤), 5초 모아 한 번에 최대 20개 | 이미 있는 리스트 하나 + 확신 점수(0~100) | **확실**(낱말 검사 또는 점수 85 이상, B.3 "확실의 기준") + 있는 리스트 + 설정 켬 → **바로 옮김**(토스트 + ⟲). 50~84 → 제안 칩만. 50 미만 → 칩도 없음 |
| ③ **새 주제 감지** | ②·①의 결과에서 같은 **새** 리스트 이름이 기본함에 5개 이상 | 카드 `새 리스트 '📜 자격증' 만들까요? 기본함에 같은 주제 할 일이 5개 있어요` [만들기] [괜찮아요] | [만들기] = 리스트 만들고 그 할 일들 옮김(⟲). [괜찮아요] = 그 이름은 다시 묻지 않음 |

| **기본함 화면 위 카드**(우선순위 하나만) | 새 주제(③) → 기본함 정리(①, 20개 넘고 `나중에` 7일 안 지났을 때) → `기본함 정리: AI 제안 N개 [모두 적용] [하나씩]`(②의 low 제안들) |
| **기본함 정리 창**(폭 640) | 머리 `✦ 기본함 정리` · 설명 한 줄 · 진행 띠(`할 일 264개를 살펴보는 중… 80/264` + 멈추기, 창을 닫아도 계속 돈다) · 제안 줄: 체크 · 아이콘(새 리스트만 이모지 선택기) · 이름(새 리스트는 고칠 수 있음, 같은 이름 둘이면 빨간 테두리·만들기 막음) · 꼬리표 `새 리스트`(점선)/`있는 리스트` · `N개` · 합치기(⇄ → `다른 리스트와 합치기 ›`) · 예시 제목 3줄 · 아래 `새 리스트 N개 · 옮길 할 일 M개 · 나머지 K개는 기본함에 남아요` [나중에] [이대로 만들기] |
| **하나씩 창** | 제안 줄마다 `제목 → 🏫 대학교` [옮기기] [무시] |
| **설정 › 할 일** | `새 할 일 자동 분류`(스위치, 기본 켬) · `기본함 정리 [열기]` · `마지막 기본함 정리 되돌리기`(24시간) · `무시한 AI 제안 다시 받기` |
| **AI를 못 쓸 때** | 칩·카드(①은 안내만)가 생기지 않고 나머지는 그대로. 창에서는 `지금은 AI를 쓸 수 없어요. 리스트는 직접 만들어 옮길 수 있어요.` + [다시 시도] |

### B.3 규칙
- **절대 옮기지 않는 것:** 기본함이 아닌 리스트의 할 일(쓰기 직전에 다시 확인), 무시한 할 일, 하위 할 일 단독(부모와 함께 옮김), 보관한 리스트로.
- "리스트를 직접 고르지 않은 새 할 일" = 기준 시각(`sprout.map.since`, 기기) 뒤에 만든 **기본함** 할 일. 다른 리스트 화면·`~리스트`로 만든 할 일은 기본함에 오지 않으므로 대상이 아니다. [임시] `~기본함`으로 일부러 고른 경우는 구분하지 않는다.
- ②의 토스트 ⟲ = 기본함으로 돌리고 그 할 일은 무시 목록에(다시 제안·이동 안 함). 여러 개면 `새 할 일 N개를 리스트로 옮겼어요` + ⟲.
- ① 되돌리기: 마지막 1회, 24시간(기기 `sprout.listSuggest.undo`). 그 뒤 사용자가 다른 곳으로 옮긴 할 일은 그대로, 만든 리스트는 비었으면 지우고 다른 할 일이 들어갔으면 남긴다. 토스트 ⟲ · 작업 지도 `⋯ › 기본함 정리 되돌리기` · 설정에서.
- 이름 규칙: 앞 이모지 떼고 20자 이내. 기존 리스트 이름과 같으면(이모지·공백·대소문자 무시) 그 리스트를 쓴다. 새 리스트는 2개 이상 모인 것만, 전체 8개까지(할 일 많은 순).
- AI 호출: 서버 프록시 `aiChat` 용도 `map`(JSON 형식 지시), 할 일은 짧은 키(t1…)·리스트는 l1…로. ①은 40개씩 묶어 차례로(264개 = 7번), ②는 5초 묶음 최대 20개, 같은 기기에서 한 줄로 세운다(Mac mini 부담). 답은 검증: 보낸 키만, 기본함·보관 리스트 거부, 같은 할 일은 처음 답만. 형식이 깨지면 설명 글을 걷어 내고 읽는다.
- AI 입력: 할 일 **제목**(120자까지) + 리스트 이름·이모지 + 리스트마다 **최근 할 일 제목 5개**(60자까지, 그 리스트가 무엇을 담는지 보여 주는 예시). 본문·메모는 보내지 않는다.
- **확실의 기준(2026-10-05 조정, `data/listSuggest.ts`):**
  1. **낱말 검사(AI 없이 먼저):** 제목의 뚜렷한 낱말(조사·`하기` 등 끝말 뗌, 2글자 이상, 숫자·흔한 낱말 `정리·확인·준비·메모·연락·통화·예약·사기…` 뺌, 두 리스트 이상에 나오는 낱말 뺌)이 **딱 한 리스트의 최근 할 일(리스트당 8개) 3개 이상**과 겹치면 AI 없이 확실 → 바로 옮김. 제목에 다른 리스트 이름이 들어 있으면(`회사 과제 정리`) 낱말 검사로 정하지 않고 AI에 넘긴다. AI가 꺼져 있어도 이건 옮긴다.
  2. **AI 점수:** 나머지는 AI가 리스트와 `confidence`(0~100)를 준다 — 지시문에 눈금 예시(90~100 = 이름·이모지·예시와 분명히 맞음, 60~89 = 아마도, 0~59 = 추측·주제 낱말 없음). **85 이상 = 확실, 50~84 = 칩, 50 미만 = 칩도 없음**(엉뚱한 칩보다 없는 게 낫다). 예전 `sure: high/low` 답도 읽는다.
  3. **막는 장치:** 점수가 높아도 ① 제목에 주제 낱말이 하나도 없으면(`정리하기`·`오후 3시 통화`) ② 낱말이 다른 리스트를 2개 이상 가리키는데 고른 리스트와는 하나도 안 겹치면 → 칩으로만. 지시문에 "개인·기타 같은 넓은 리스트에 억지로 넣지 말 것".
- 실측(2026-10-05, Mac mini `qwen3.5:9b`, 리스트 14개 — 기본 5개 + 대학교·운동·회사(각 6개) + 쇼핑·여행·재테크·사이드 프로젝트·건강·집안일(각 3개), 새 기본함 할 일 26개 중 옮겨야 할 것 22개·막연한 것 4개): **조정 전** 자동 이동 맞음 17 · **틀림 2**(`오후 3시 통화`→회사, `정리하기`→집안일) · 칩 맞음 2 · 칩 틀림 3 · 없음 2. **조정 후(3회)** 자동 이동 맞음 14~15 · **틀림 0** · 칩 맞음 4~5 · 칩 틀림 0~1 · 없음 6~7(막연한 4개는 모두 그대로 기본함). 서버에 JSON 모양 지시가 들어간 뒤로는 "high를 안 낸다"는 문제는 재현되지 않았다(조정 전에도 17/22 자동 이동) — 실제 문제는 막연한 제목의 잘못된 이동과 엉뚱한 칩이었다. 낱말 검사: 대학교에 `…과제` 3개가 있을 때 `네트워크 과제 제출` → AI 없이 6초 만에 대학교로.

### B.4 없앤 것 (초안 v0.1·14 v1.2에서)
- 사이드바 `AI 정리` 구역, 상세 `✦ 영역 › 주제` 칩, `AI 정리` 꼬리표·✦ 배지·이름 충돌 `· AI`, 필터의 영역 조건.
- 할 일을 `task_areas`에 자동으로 나누던 분류기(`mapClassifier`)와 ✦ 다시 정리(영역 만들기), AI 분류 지우기·직접 옮긴 것 맡기기.

- **정리 들어가는 곳 (2026-10-05, 31 §12.0):** 기본함 정리 카드의 `지도에서 정리 ›` → **`정리하기 ›`** — 작업 지도가 아니라 **정리 화면**(분류 책상, 본문 자리 전체)을 연다. ⌘K `기본함 정리하기`도 같은 화면.
