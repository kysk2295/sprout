# AI 사용량 — 계정별 구독 한도

## 기준

사용자가 지정한 CodexBar의 한도 표시 방식을 따른다. TickTick에 없는 화면이므로 앱의 기존 토큰·타이포그래피·메뉴 패턴을 사용한다.

상세 데이터/연결 정책: [계정 한도 설계](../superpowers/specs/2026-10-04-account-usage-dashboard.md).
참고: https://github.com/steipete/CodexBar/tree/main/docs

## 레이아웃

독립 탐색 메뉴 ‘AI 사용량’. 상단 제목과 ‘계정 추가’, ‘새로고침’. 아래 서비스 필터와 GPT/Codex·Claude·Grok·Gemini 그룹. 여러 계정이 동시에 보이는 카드 격자. 카드 최소 너비 280px, 공간이 부족하면 한 열로 전환하며 본문만 세로 스크롤한다. 카드 간격·색·모서리는 기존 디자인 토큰을 쓴다.

계정 카드: 별칭 → 서비스/제품 범위·플랜 → 각 한도 이름 및 남은 비율 → 한도 막대 → 초기화까지 남은 시간 → 마지막 갱신 시각 → 계정 메뉴 순서.

공급자 응답에 있는 한도 창을 모두 표시한다. ‘세션/주간’ 고정 두 줄을 가정하지 않는다. 초기화 시각은 앱 시간대의 정확한 날짜·시각도 확인 가능하게 한다. 막대는 남은 양이라는 라벨을 일관되게 사용한다.

## 상태

- 빈 상태: 연결된 계정 없음, 계정 추가 안내.
- 첫 조회 중: 숫자 대신 로딩 표시.
- 갱신 중: 기존 값과 기존 관측 시각 유지, 갱신 중 표시.
- 정상: 값·범위·출처·갱신 시각 표시.
- 오래된 값: ‘마지막 확인값’, 현시점의 사용 가능 계정으로 분류하지 않음.
- 재로그인 필요: 해당 계정에만 재연결 버튼.
- 조회 미지원/값 누락: ‘조회 불가’와 원본 페이지 열기. 0%/100%로 표현하지 않음.
- 한도 도달: 수치와 텍스트로 표시하고 색상만으로 구분하지 않음.

## 인터랙션

계정 추가에서 서비스와 지원되는 연결 방식을 고른다. 로그인 성공 후 계정 식별을 확인한 다음 카드에 추가한다. 이메일만으로 기존 계정과 병합하지 않는다.

계정 메뉴에서 별칭 변경·개별 갱신·재연결·연결 해제. 연결 해제는 해당 앱 연결만 제거한다. 여러 계정에 동일 세션을 재사용하지 않는다. 전체 갱신은 계정별 결과가 독립적으로 표시된다.

Tab으로 버튼과 필터를 이동한다. Escape로 메뉴/추가 대화창을 닫고 진입 버튼에 포커스를 돌린다. 호버와 포커스 스타일은 기존 컴포넌트와 동일하다. 단축키·더블클릭·우클릭 전용 기능은 추가하지 않는다. 장식 애니메이션 없이 로딩만 표시한다.

## 데이터

계정 메타데이터·조회 스냅샷은 Electron 메인 프로세스가 관리하는 로컬 전용 저장소에 보관한다. 렌더러에는 비밀값 없는 Account/Snapshot만 전달한다. 자격 증명은 OS 보안 저장소 또는 검증된 격리 프로필에 보관한다. tasks 및 AI 대화 기록을 사용량으로 계산하지 않는다.

## 완료 기준

- CodexBar/공급자 원본과 계정별 남은 값·한도 범위·초기화 시각 대조.
- 동일 서비스의 두 계정이 함께 표시되고 갱신/재로그인 결과가 섞이지 않음.
- 누락값·오류·오래된 값이 현재 사용 가능으로 오인되지 않음.
- 좁은 창, 키보드 접근, 연결 해제, 계정 변경 중 늦은 응답 검증.
- 네 서비스의 실연결 검증 여부를 각각 기록. 더미 카드만으로 완료 판정하지 않음.

## 실제 구현 경로 (2026-10-04)
설치된 CodexBar CLI 0.67.0을 조회 전용 어댑터로 사용한다. 소스를 복사하거나 토큰/쿠키를 읽지 않고 JSON 결과의 허용된 계정/한도 필드만 전달한다. Codex/Claude는 OAuth 소스를 지정하고 Grok/Gemini는 공급자의 auto 경로를 사용한다. Codex/Claude/Grok은 --all-accounts, 등록 계정이 없을 때 기존 로그인 조회로 대체한다. Gemini CLI는 다중 토큰 계정을 지원하지 않아 기존 로그인 한 개만 표시하며 제한을 안내한다.
계정 추가/재인증은 기존 CodexBar에서 수행하고 앱은 재조회하여 반영한다. 앱의 ‘숨기기’는 로컬 대시보드 표시만 해제하며 CodexBar 로그인·다른 앱에 영향을 주지 않는다. 별칭/숨김은 로컬 화면 설정으로 보관한다. 공급자별 갱신/캐시/요청 합치기, 5분 자동 갱신, 오류 백오프, 실제 관측 시각 및 만료 후 재조회 필요 상태를 제공한다. 자격 증명 파일을 복사하거나 별도 OAuth 기능을 가장하지 않는다.
근거: CodexBar main 6dca28df4a543ee445fd12717057c1dd7b1f572d docs/cli.md, docs/codex.md, docs/gemini.md, docs/grok.md (MIT). CLI 호출로 통합하며 소스 재배포 없음. 실제 응답: Codex 2계정(1개 재인증 필요), Grok SuperGrok 주간, Claude/Gemini 미인증.

## 앱에서 계정 연결 (2026-10-04 변경)
사용자 요청에 따라 CodexBar 설정으로 이동하는 연결 흐름을 제거한다. ‘계정 연결’ → 서비스 선택 → 공식 로그인 페이지 → 이 화면에서 연결 완료/오류 확인 → 해당 서비스 자동 갱신으로 변경한다. 비밀번호 입력은 공급자 공식 브라우저 페이지에서 수행한다. 앱은 로그인 시작·대기·취소·재시도 상태와 다시 열기 링크를 제공한다.
Codex/Claude/Grok 공식 CLI의 로그인 전용 명령을 앱에서 실행한다. 각 연결은 UUID 프로필 디렉토리(0700)로 격리하고 CLI가 자격 증명을 관리한다. 원래 CLI 계정이나 CodexBar 설정을 덮어쓰지 않는다. 완료된 프로필만 대시보드에 포함하고 CodexBar CLI는 각 프로필을 지정한 조회 어댑터로만 사용한다. 로그인 stdout/stderr 원문과 비밀값은 UI/로그에 전달하지 않는다. 로그인 제한시간 10분, 동시에 한 번만 진행, 취소/종료 시 자식 프로세스 정리. 앱 재시작 후에도 완료된 프로필 유지.
현재 설치된 Gemini CLI는 격리된 로그인 전용 명령을 제공하지 않으므로 연결 버튼을 미지원으로 안내한다. 기존 Gemini 한도 조회는 유지한다. 로그인 완료 판정은 CLI 성공 종료이며 한도 미제공은 별도 조회 상태로 보여준다. 기존 CodexBar 계정은 출처를 구분해 계속 표시한다.
검증: 격리 환경, 잘못된 서비스/세션 ID 거부, 취소 후 늦은 성공 방지, 성공 프로필 재로딩, 로그인 화면에서 오류/대기/취소 상태, 실제 사용자 인증이 필요한 완료 검증은 미검증으로 기록한다.
Claude의 공식 로그인에서 일회용 코드를 반환하면 대기 카드에 비밀번호 형식의 코드 입력란과 ‘연결 완료’를 표시한다. 코드는 진행 중인 같은 세션의 CLI stdin에만 전달하며 파일·로그·화면 설정에 저장하지 않는다. 제출/취소 후 입력값을 지우고, 종료된 세션 및 줄바꿈이 포함된 입력을 거부한다.
