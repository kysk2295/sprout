## v3-3. 수집 — AI 자동 분류
들어온 것(추가 바·카톡 가져오기·[다음] 카톡 채널)은 **바로 저장**하고 AI가 뒤에서 네 갈래로 나눈다.
| 갈래 | 행 표시 | 결과 |
|---|---|---|
| **할 일·일정** | 점선 체크 칸 + 꼬리표 `할 일 제안 · 내일 오후 3:00` + 작은 `등록` 버튼 | **자동으로 만들지 않는다.** `등록` 한 번 = v2 전환과 같은 경로로 할 일 생성(기본함으로 가면 새 할 일 자동 분류도 탐 — 30 §B). 등록 후 꼬리표 `할 일로 등록됨` |
| **볼 것**(링크) | 링크 아이콘 + 꼬리표 `볼 것` | 볼 것 탭에 들어감. 제목은 메인 프로세스가 가져온다(유튜브 oEmbed, 그 밖은 페이지 `<title>`), 못 가져오면 주소 그대로. ~~요약하지 않는다~~ → **3줄 요약(v3-8, 2026-10-10)** |
| **위키** | 책 아이콘 + 초록 꼬리표 `위키 · LLM 공부` | 해당 주제 페이지에 자동 반영(v3-5). 맞는 주제가 없으면 AI가 새 주제를 만든다 |
| **메모** | 문서 아이콘 + 꼬리표 `메모` | 그대로 남김 |
- 정리 중 = 작은 회전 표시 + `정리 중…`. 실패·AI 없음 = 꼬리표 없이 두고 나중에 다시(작업 지도 §0.3과 같은 규칙).
- 글 안에 링크와 할 일이 섞여 있으면(예: "이 영상 보고 금요일까지 요약") 할 일 제안 + 링크를 볼 것에도 넣는다.
- 상세(336): 원문(편집 가능, v2와 같음) + **AI 판단 카드**(`AI가 할 일로 봤어요` · 제목/날짜/리스트 · [할 일로 등록] [메모로 두기] · `다른 종류로: 볼 것 · 위키 · 메모`). 사용자가 바꾼 종류는 AI가 다시 바꾸지 않는다.
- `카톡` 꼬리표(테두리만) = 카카오톡에서 가져온 것.
- **구현 메모(2026-10-05):** 뒤 정리는 앱에 항상 붙은 대기열이 한다(묶음 최대 4개, 앱에서 넣은 것 먼저·최신순). 링크 옆 글이 40자 이하이고 날짜·마감 말(까지·내일·요일·N시·요약·제출 등)이 없으면 AI 없이 바로 `볼 것`. AI가 없으면 그대로 두고 1분 뒤 다시, 같은 항목이 한 실행에서 3번 틀리면 `정리하지 못했어요`(실패) → 상세 [AI로 정리]. `⋯ → 자동 분류`를 끄면 AI를 부르지 않는다(상세 [AI로 정리]를 누른 항목만 정리). 행 꼬리표가 없으면(정리 전·실패·v2 메모) 오른쪽에 시각·날짜. 처음 저장할 때 한 번 `수집함 글은 외부 AI가 아니라 오너의 Mac mini AI가 정리해요` 토스트.

## v3-4. 카카오톡 대화 가져오기
- `⋯` → `카카오톡 대화 가져오기` → 대화 상자(폭 440): 안내 3단계(나와의 채팅 열기 → 메뉴 → 대화 내보내기 → 텍스트 저장 → 파일 놓기) → 파일 놓기 칸 → **미리보기**(`메시지 312개 · 기간 · 링크 84 · 글 228 · 이미 가져온 40개는 건너뜀 · 사진·이모티콘·파일은 빼고`) → [취소] [가져와서 정리하기].
- 가져온 뒤 수집 탭 위 진행 띠 `카카오톡에서 가져온 312개를 정리하는 중 · 120/312 · 멈추기`. 정리는 Mac mini 부담을 줄이려고 묶어서 천천히(4개씩, 20개마다 5초 쉼). 멈춤·AI 없음·자동 분류 꺼짐이면 띠 글이 `…312개 · 정리를 멈췄어요 · [다시 시작]` / `지금은 AI를 쓸 수 없어요(돌아오면 이어서)` / `자동 분류가 꺼져 있어요 · [켜기]`로 바뀐다. 합계는 이 기기에서 마지막으로 가져올 때의 남은 수 + 새로 가져온 수.
- 파싱: 카카오톡 PC·모바일 내보내기 형식(날짜 줄 + `[이름] [오후 3:12] 내용` / `2026. 10. 4. 오후 3:12, 이름 : 내용`)을 읽는다. 여러 줄 메시지는 이어 붙인다. **원래 보낸 시각**을 작성 시각으로 쓴다.
- 중복: (보낸 시각 + 내용) 지문으로 이미 가져온 것은 건너뛴다(같은 파일을 두 번 올려도, 한 파일 안에 같은 메시지가 두 번 있어도 한 번만). 행 id는 새로 만든다(지문을 id로 쓰면 같은 단톡방을 내보낸 다른 사용자와 서버에서 부딪친다) — 그래서 두 기기에서 동기화 전에 같은 파일을 동시에 가져오면 중복될 수 있다.
- macOS 카카오톡의 CSV(`Date,User,Message`)도 읽는다. `.txt`·`.csv`, 50MB까지.
- 파일은 기기 안에서만 읽고 서버에 올리지 않는다(메시지만 수집함 항목으로 저장).
- **[다음] sprout 카카오톡 채널(챗봇):** 채널에 보내면 바로 수집함으로. 서버 공개 주소·카카오 채널/챗봇 신청·계정 연결 코드가 필요.

## v3-5. 위키 (LLM 위키)
| 항목 | 내용 |
|---|---|
| 자동 반영 | 위키로 분류된 자료가 들어오면 AI가 **알아서** 그 주제 페이지를 고친다("AI로 정리하기" 버튼 없음). 위에 띠 `방금 들어온 자료 1개를 '핵심 정리'에 반영했어요 · 바뀐 곳 · 되돌리기`, 새로 들어간 줄은 잠시 강조색 배경 |
| 페이지 구역 | `개요` · `핵심 정리` · `볼 것`(이 주제 링크들) · `관련 주제`(다른 주제로 가는 링크) · `열린 질문`. 근거 없는 구역은 숨김 |
| 출처 | 문장마다 꼬리표(`카톡 10/2`, `메모 9/30`, `오늘`) → 누르면 수집 탭에서 그 항목 |
| 직접 고침 보호 | 구역을 직접 고치면 🔒, 이후 AI는 그 구역을 덮어쓰지 않고 `제안 1개`로만 보여 준다 |
| 이력 | 버전마다 저장, `이력`에서 이전 버전 보기·되돌리기 |
| 주제 관리 | AI가 새 주제를 만들 수 있다. 사용자는 이름 바꾸기·합치기·삭제(자료는 메모로) |
| 찾기 | AI 비서가 위키·볼 것을 찾아 답한다("저번에 저장한 LangGraph 영상 뭐였지?" → 그 링크) |
| 띠 기준 | 주제를 열 때 이 기기에서 마지막으로 본 버전이 기준. 그 뒤 바뀐 게 있으면 띠(여러 번이면 `N번 바뀌었어요 — <마지막 이유>`) + 그 뒤 AI가 넣은 줄 강조. `되돌리기` = 기준 버전으로, `×` = 띠 닫기. 내가 직접 고친 것(구역 고침·제안 넣기·되돌리기)은 띠로 알리지 않는다. 목록의 점은 열면 사라진다 |
| 빈 구역 쓰기 | 숨은 구역은 페이지 아래 `+ 직접 쓰기: 개요 · 열린 질문`으로 연다. 잠긴 구역 제목 옆 `AI에게 맡기기` = 🔒 풀기 |
| 이력 | `이력` 팝오버(폭 300) — 버전·이유·시각. 누르면 페이지가 그 버전 미리보기(띠 `버전 3 미리보기 · [이 버전으로 되돌리기] [닫기]`) |
| 주제 없음 | 책 아이콘 + `자료가 쌓이면 주제별로 정리해 드려요` + `공부한 것·알게 된 것을 수집에 던져 두면 AI가 주제 페이지를 만들어요` + [수집으로 돌아가기] [주제 직접 만들기] |
| 검색 | 위키 탭의 검색은 주제 이름·내용으로 주제 목록을 거른다 |
| 주제 삭제 | 바로 지우고 토스트(되돌리기). 합치기는 되돌리기 없음(이력에는 남음) |
- **[다음] 찾기(AI 비서)** 는 이번에 만들지 않았다 — 비서의 의도 스키마에 위키·볼 것 검색 동작을 더해야 해서 13 명세와 함께 정한다.

- **E2E 메모(2026-10-04, 실제 Mac mini AI):**
  - 서버 프록시 경로에서 `format`(JSON 스키마)이 **강제되지 않는다** — Ollama 0.31.1 + qwen3.5:9b는 `think:false`일 때 `format`을 무시한다(서버 `api/src/ai.ts`가 늘 `think:false`). 그래서 모델이 `{items:[…]}` 대신 맨 배열·빠진 칸으로 답해 모든 항목이 `정리하지 못했어요`가 됐다 → 앱이 느슨하게 받는다(맨 배열·다른 이름 배열 하나·항목 하나·앞뒤 설명 글, 빠진 칸 = 빈 값). 프롬프트에 출력 모양을 적었다.
  - 날짜: 작은 모델이 보낸 시각 기준 셈을 자주 틀린다 → 항목마다 보낸 시각 기준 날짜 표(오늘·내일·모레·이번 주·다음 주, 주는 월요일 시작)를 같이 보내고, **글에 날짜·시각 말이 없으면 모델이 준 날짜를 버린다**, **요일 말이 하나뿐이면 날짜는 앱이 정한다**(`금요일까지` = 보낸 날 이후 첫 금요일, `다음 주 월요일` = 다음 주 월요일).
  - 위키 주제: 사실 하나마다 새 주제를 만들던 것을 프롬프트로 고침(주제 = 넓은 과목 이름, 같은 과목이면 기존 이름 그대로).
  - 정리 대기 행: AI 없음·멈춤·자동 분류 끔이면 `정리 중…` 대신 꼬리표 없이 시각(v3-3 규칙대로).

## v3-8. 볼 것 링크 요약 (2026-10-10, 사용자 "수집함에서 링크를 넣었을 때 요약해 주는 것도")
- **결정 바꿈:** v3 결정 "링크는 제목 + 주소만(요약 없음)" → **요약한다.** 사용자 답(2026-10-10): 넣을 때 자동 · 목록 한 줄 + 상세 3줄 · 유튜브는 제목·설명 기준(자막 안 읽음). 틱틱에 없는 기능이라 [sprout].
- **누가:** 데스크톱 수집기(링크 제목 다음 단계)와 **휴대폰도**(2026-10-10 사용자 "휴대폰에서도 하게 해 줘" — 26 M-C5의 예외, `src/collect/summarize.ts`: 앱이 앞에 있을 때 하나씩, 제목이 없으면 페이지 제목도 채움). 먼저 만든 쪽 것이 동기화되면 다른 쪽은 건너뛴다.
- **흐름:** 볼 것 항목(`kind='link'`)에 제목이 생기면 → 메인 프로세스가 페이지를 읽는다(내부망 주소 금지·리다이렉트 뒤 주소도 검사·8초·본문 앞 256KB). 일반 페이지 = `<title>`·설명(meta/og)·본문 글(문단·제목, 스크립트·메뉴 뺌) 앞 3,000자 / 유튜브 = 영상 제목 + 설명란(`shortDescription`) → 꿈틀 AI(`/ai/classify`, 갈래 background — 서버 변경 없음)에 **한 줄(head, 50자) + 요점 4~5줄(lines, 각 100자, 수치·이름·결론 등 구체적으로 — 사용자 "상세 내용을 좀 더 자세하게")** JSON으로 → 저장. 본문은 앞 4,000자.
- **저장:** 스키마 변경 없음 — 링크 항목은 할 일 제안을 쓰지 않으므로 같은 칸 `notes.suggestion` JSON에 `{"linkSummary":{"head":…,"lines":[…5],"from":"page"|"youtube","at":ISO,"url":…}}`(주소가 바뀌면 다시 요약)(할 일 제안 칸과 겹치지 않게 키를 나눔). 못 읽음·너무 짧음(본문 120자 미만) = `{"linkSummary":{"none":"empty"|"blocked","at":…}}`.
- **한도:** 자동은 이 기기에서 **하루 20개**(넘으면 그날은 멈춤, 상세 `요약하기`로 하나씩). `⋯ › 자동 분류`를 끄면 자동 요약도 끈다(상세 단추는 됨).
- **보이기(데스크톱 볼 것):** 행 = 제목 / **한 줄 요약(2차 글자, 한 줄 말줄임)** / 도메인·날짜. 상세 = 제목 아래 `요약` 구역: 한 줄(굵게) + 요점 점 4~5줄 + 3차 `페이지 기준 · 꿈틀 AI` 또는 `영상 설명 기준 · 꿈틀 AI`(화면에 "Mac mini"는 쓰지 않는다 — 사용자 2026-10-10). 요약이 없으면 `요약하기`(누르면 회전 → 결과), 못 읽었으면 `요약할 내용을 찾지 못했어요` + `다시 시도`.
- **개인정보:** 페이지는 이 기기가 직접 읽고, 요약은 꿈틀 서버의 AI가 만든다(외부 AI 아님). 페이지 원문은 저장하지 않고 요약 3줄만 동기화.
- **완료 기준:** 블로그·뉴스 링크를 넣으면 몇십 초 안에 목록 둘째 줄에 요약이 생긴다 · 유튜브 링크는 설명 기준 표시 · 로그인 필요한 페이지는 "찾지 못했어요" · 하루 21번째부터 자동이 멈추고 단추는 된다 · 휴대폰 볼 것에도 같은 요약.
