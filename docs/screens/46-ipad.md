## 0. 한 줄 원칙
**틱틱 iPad = 데스크톱 배치 + 손가락 크기.** 꿈틀도 넓은 창에서는 데스크톱(01)의 정보 구조(레일 · 사이드바 · 본문 · 상세)를 그대로 쓰고, 좁은 창에서는 **지금 iPhone 화면을 그대로** 쓴다. 새 화면을 만들지 않고 **이미 있는 휴대폰 화면을 칸(pane)에 나눠 담는다.** 배치는 기기·방향이 아니라 **앱 창의 폭**으로 고른다(iPadOS 26은 창을 아무 폭으로나 늘인다 — research 38 §2).

- 경계값은 [임시] — Apple의 가로 크기 등급(compact/regular)과 거의 겹치게 골랐다(11″ 가로 1/2 = compact, 13″ 가로 1/2 = regular). 실기기에서 창을 끌며 다시 본다.
- **크기가 바뀌어도 상태는 그대로**: 고른 할 일 · 스크롤 위치 · 입력 중인 글 · 열린 화면. 예: 넓음에서 상세를 보다가 1/2로 줄이면 C의 상세 시트로 열린 채 바뀌고, 다시 넓히면 상세 칸으로 돌아온다(틱틱 "상황에 따라 열 ↔ 팝업"). 사이드바 겹침·시트는 등급이 바뀌면 닫는다.
- 바뀔 때 움직임: 칸 폭은 220ms `--k-ease`로 따라가고(모션 감소면 바로), 등급이 바뀌는 순간은 페이드 120ms. 회전도 같다.
- 홈 표시줄 위 아래 안전 영역 20, 위 상태 막대 24. **창 모드(나눠 보기·Stage Manager)에서는 왼쪽 위 창 버튼(● ● ●)이 앱 위에 겹친다** → 레일 위쪽 여백을 14 → 30으로(맥 신호등과 같은 처리, 01 §창), C에서는 머리 줄을 18 내린다.
- 지원 방향: **iPad는 네 방향 모두**, iPhone은 지금처럼 세로만(§7.5).

## 5. 인터랙션
### 5.1 누르기 · 고르기
- 행 누름 = 고르기(R3·R2 상세 칸이 바뀜 / R1 시트 / C 21 상세 반 시트). 체크 누름 = 완료(행 고르기 아님).
- 사이드바·프로젝트 칸 행 누름 = 본문 바꿈(겹침 상태면 닫힘).
- 상세 ✕ · Esc = 고름 해제(01 §2.1).
- **여러 개 고르기**: ⌘ + 누름 · ⇧ + 누름(포인터·키보드)과 두 손가락 끌어 고르기(iPadOS 관례) → 데스크톱 02 §10 일괄 편집 칸 [다음 — 1.1 이후].

### 5.2 길게 누르기 · 두 손가락 클릭 메뉴
- 손가락 길게 누름(0.5초)과 트랙패드 두 손가락 클릭·마우스 오른쪽 버튼이 **같은 메뉴**(§4). 메뉴가 뜬 뒤 그대로 끌면 끌기로 바뀐다(research 37 §2 iPhone 동작과 같음).

## 7. 구현 방법 (React Native · Expo — 1.1)
### 7.1 크기 등급 훅
- `src/ui/layout/useSizeClass.ts`: `useWindowDimensions().width`(창 폭 — 나눠 보기·Stage Manager에서 실제 창 폭이 들어온다)로 `'R3' | 'R2' | 'R1' | 'C'`. iPhone은 늘 `C`(가로 고정이 아니어도 폭 < 600). 경계값은 한 곳 상수. 값이 바뀔 때만 다시 그리게 `useMemo` + 등급 문자열 비교.
- `useIsTablet()` = `Platform.isPad`(설정 iPad 묶음·방향 처리용). 배치 판단에는 쓰지 않는다(폭만 본다).

### 7.2 껍데기: 같은 경로, 다른 탭 막대
- `app/(tabs)/_layout.tsx`의 `Tabs`(React Navigation bottom-tabs v7)를 그대로 두고 `tabBar`만 바꾼다: `C` = 지금 `FloatingTabBar`, 나머지 = 새 `Rail`(세로 66, `tabBarPosition: 'left'`). 레일에만 있는 칸(AI 비서 · 일기 · 작업 지도)은 탭 경로 `assistant` · `diary` · `map`을 더하고 `C`에서는 `href: null`로 알약에서 숨긴다(휴대폰은 지금처럼 더보기 → 루트 스택 경로). 화면 본체는 같은 컴포넌트를 다시 내보낸다.
- `src/ui/layout/SplitLayout.tsx`: `<SplitLayout side={<Sidebar/>} detail={<TaskDetailPane id/>} detailWidth={360}>{목록}</SplitLayout>` — 등급에 따라 칸 배치 / 겹침(Reanimated 220ms) / `C`면 `children`만. 사이드바 겹침 = 왼쪽 서랍(지금 `Drawer.tsx` 재사용).
- **휴대폰 화면을 칸에 담기**: 지금 경로 화면(`app/task/[id].tsx` 상세 formSheet, 서랍 리스트, `app/(tabs)/growth.tsx`·`app/growth/decorate.tsx`, `app/diary/index.tsx`, `app/assistant`)에서 **본체를 `src/screens/*Pane.tsx`로 떼어** 경로 화면과 칸이 같이 쓴다(머리의 ‹/✕만 칸용 prop). 
- 열기 도우미 `openTask(id)`: `C` → `router.push('/task/'+id)`(지금 그대로), `R1` → 같은 경로를 가운데 formSheet로(`presentation: 'formSheet'` + `sheetAllowedDetents` 대신 iPad formSheet), `R2·R3` → 화면 상태 `selected=id`(경로 인자 `?task=`로 두어 딥 링크·복원). 알림·위젯 딥 링크(`sprout://task/<id>`)도 이 도우미로.
- 시트 규칙(20 §3.2 ✕·끌어 닫기)은 그대로. iPad formSheet는 아래로 끌어 닫기 + 바깥 누르기.

### 7.3 입력
- **키보드 단축키**: RN에는 하드웨어 키 명령 API가 없다 → 작은 Expo 모듈 `modules/key-commands`(Swift, Expo Modules API): `UIKeyCommand` 등록 + `buildMenu(with:)`로 메뉴 막대(iPadOS 26)·⌘ 판에 이름 표시, 눌림을 JS 이벤트로. 화면마다 `useKeyCommands([...])`로 등록·해제. [위험 — 구현 첫날 확인: 새 아키텍처에서 첫 응답자(first responder)·글 입력 중 동작]
- **포인터 올림**: `Pressable`의 `onHoverIn/onHoverOut`(iPadOS 포인터) [구현 때 RN 0.86에서 확인]. 안 되면 행 올림 면만 빼고 나머지는 시스템 포인터 효과.
- **두 손가락 클릭 메뉴**: 지금 `LongPressMenu`(JS)는 오른쪽 클릭을 받지 못한다 → 네이티브 `UIContextMenuInteraction`(`@expo/ui`의 ContextMenu 또는 같은 모듈에 추가)로 바꾸거나, 포인터 이벤트 `button === 2`로 같은 메뉴를 연다 [구현 때 둘 중 확인].
- **끌기**: 지금 `DragReorder`·`DayDrag`(react-native-gesture-handler + Reanimated)를 칸 사이로 넓힌다 — 놓을 곳(사이드바 리스트·캘린더 칸)을 `measure`로 등록하는 작은 레지스트리. 다른 앱 끌기는 [다음].

```jsonc
"orientation": "default",              // 지금 "portrait"
"ios": {
  "supportsTablet": true,              // 지금 false
  "requireFullScreen": false,          // 나눠 보기·Slide Over·Stage Manager 허용(결정 ②)
  "infoPlist": {
    "UISupportedInterfaceOrientations": ["UIInterfaceOrientationPortrait"],            // iPhone은 세로만

```
- `orientation`과 `infoPlist` 방향 키가 겹치므로 **`npx expo prebuild` 뒤 `ios/*/Info.plist`에서 두 키가 위대로 나오는지 확인**한다(Expo가 `orientation`으로 덮어쓰면 config plugin으로 고친다).

- Android 태블릿: 같은 폭 규칙이라 자동으로 넓은 배치가 된다. 1.1 확인 범위는 iPad만, Android 태블릿 확인은 [다음].

## 10. 완료 기준 (틱틱 iPad와 나란히 — 실기기 iPad(11″ 이상) + 시뮬레이터 13″, 라이트·다크)
- [ ] 11″ 가로 전체: 레일 · 사이드바 · 목록 · 상세 4칸이 보이고, 행을 누르면 상세가 바뀐다(틱틱 S1 "Reminder" 스크린샷과 같은 배치).
- [ ] 세로 · 2/3 · 13″ 1/2 · 1/2 · 1/3 · Slide Over로 창을 바꿔도 고른 할 일·입력 중인 글이 그대로이고, §2 등급대로 칸이 접힌다(상세 열 ↔ 시트 ↔ 휴대폰 상세).
- [ ] 1/2(11″) 이하에서는 지금 iPhone 화면과 **픽셀 단위로 같은 부품**(탭 알약 · + 버튼 · 시트)이다 — 따로 만든 화면이 없다.
- [ ] 회전해도 깜빡임·잘림이 없다(220ms 따라감, 모션 감소면 바로).
- [ ] 캘린더 월·주가 전체 폭이고, 날짜 없는 할 일을 칸으로 끌어 날짜·시각이 잡힌다(되돌리기 토스트).
- [ ] 작업 지도 타임라인 막대를 끌어 날짜·기간이 바뀐다(데스크톱 31과 같은 결과).
- [ ] 성장 무대와 옷장이 나란히 있고, 옷을 누르면 무대 캐릭터가 바로 바뀐다(깡충).
- [ ] 일기: 대화에 답할 때마다 오른쪽 엮은 글이 채워지고, 저장·다듬어 줘 규칙은 28 §8 그대로(AI 호출 횟수 같음).
- [ ] 하드웨어 키보드: §5.4 표의 키가 모두 동작하고, 메뉴 막대(iPadOS 26)·⌘ 판(iPadOS 18)에 이름이 보인다. 글 입력 중 단일 글쇠가 먹지 않는다.
- [ ] 트랙패드: 올림 면 · 레일 툴팁 · 두 손가락 클릭 메뉴(길게 누름과 같은 항목) · 두 손가락 쓸기로 기간 넘기기.
- [ ] Pencil Scribble로 할 일 추가 줄에 `내일 3시 치과`를 쓰면 글자 + 날짜 인식이 된다.
- [ ] 창 모드에서 왼쪽 위 창 버튼(● ● ●)이 레일·머리 버튼을 가리지 않는다.
- [ ] iPhone 앱은 그대로 세로 고정이고 배치가 바뀌지 않았다(회귀 없음).
- [ ] `expo prebuild` 결과 Info.plist: `UIDeviceFamily` 1·2, iPad 네 방향, iPhone 세로, `UIRequiresFullScreen` 없음. App Store 13″ 스크린샷 8장.
