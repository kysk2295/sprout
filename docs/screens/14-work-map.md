## 0. 그래프 보기 (기본) — 2026-10-04 사용자 결정
사용자 말: "작업 지도는 그래프 노드화 — 연결이 되어서 랭그래프처럼 보여주는 것". 틱틱에 없는 화면 → [sprout]. 모양은 시안 ③의 부품(열 머리 글자, 칸반 카드)을 노드로 그대로 쓴다.

| 항목 | 내용 |
|---|---|
| 머리 | 제목 옆 세그먼트 `그래프 · 보드`(06 캘린더 보기 전환과 같은 모양). 오른쪽 아이콘은 §2와 같다(✦ · 거름틀 · `⋯`) |
| 배치 | **위 → 아래 층**(LangGraph 그림 방향): 1층 뿌리 알약 `나의 할 일` → 2층 영역 노드 → 3층 세부 주제 노드 → 4층 할 일 노드. 자동 배치(dagre 계열), 층 간격 46~72, 노드 간격 24. 같은 주제의 할 일은 가로로 펼치지 않고 **세로로 쌓아 왼쪽 줄기선으로 잇는다**(넓게 퍼지지 않게) |
| 뿌리 노드 | 알약(높이 28, 모서리 999), 배경 `--color-bg-selected`, 글자 12/600 |
| 영역 노드 | 폭 180·높이 40, 배경 `--color-bg-card`, 테두리 1px, 모서리 8, 왼쪽에 영역 색 점 · `학교` · 개수(3차) · 접기 단추(`−`/`+N`) |
| 주제 노드 | 폭 160·높이 34, 같은 모양 한 단계 작게(12.5/600) |
| 할 일 노드 | 시안 ③ 칸반 카드 그대로(폭 200, 40/56): 체크박스 · 제목 · 강조색 날짜 |
| 메모 노드 | 문서 아이콘 + 메모 첫 줄(11 메모함과 같은 행 모양), 폭 180 — 할 일로 전환된 메모만 그 할 일 옆에 |
| 선 | 실선 1.5px `--color-text-quaternary` 곡선 + 끝 화살표 = 포함(영역→주제→할 일). **점선** = 관련: 메모→전환된 할 일, AI가 제안한 주제↔주제 관련(겹치는 할 일이 있을 때) [다음] |
| 선택 | 노드를 누르면 그 노드에서 뿌리까지의 길과 바로 아래 노드들이 강조색, 나머지는 40% 흐리게. 할 일 노드는 상세 패널(336)도 열림 |
| 접기 | 영역·주제 노드의 `−`로 아래를 접으면 노드에 `+N` 표시. 처음엔 할 일이 8개 넘는 주제는 접혀 있다 [임시] |
| 화면 이동 | 빈 곳 끌기 = 이동, 트랙패드 핀치·⌘휠·⌘+/− = 확대/축소(25~200%), 왼쪽 아래 조절 버튼 `+ − ⤢(전체 맞춤)`, 오른쪽 아래 미니맵(160×100) |
| 끌어서 옮기기 | 할 일 노드를 다른 주제·영역 노드 위로 끌어 놓으면 그쪽으로 이동(📌 직접 옮김) — §4 규칙과 같다 |
| 우클릭 | 영역·주제 노드 = §3의 열 `⋯` 메뉴, 할 일 노드 = 02 태스크 메뉴 + `영역 옮기기 ›` |
| 키보드 | ↑↓←→ 노드 사이 이동, Enter 상세/펼치기, Space 완료, `0` 전체 맞춤 [임시] |
| 성능 | 할 일 노드 300개까지 부드럽게. 넘으면 주제를 자동으로 접는다 |
| 구현 | `@xyflow/react`(React Flow, MIT) + `@dagrejs/dagre`(MIT) — 새 의존성. 노드는 우리 컴포넌트로 그린다 |
| 보기 기억 | 고른 보기(그래프/보드)·확대 배율·접은 노드는 기기에 기억 (`sprout.map.view` 등) |

## 3. 구성 요소와 상태
| 요소 | 상태 |
|---|---|
| 카드 | 기본 · 호버(배경 한 단계 밝게) · 선택(강조색 1px 테두리) · 끄는 중(살짝 기울고 그림자, 원래 자리에 점선 자리 표시) · 완료(체크 후 0.4초 뒤 사라짐, 보기 옵션에서 `완료 보이기`면 남고 흐리게) |
| 직접 옮긴 카드 | 호버 시 제목 옆 📌(3차 글자) + 툴팁 `직접 옮긴 항목 — AI가 다시 정리해도 그대로예요` |
| 최근 정리로 바뀐 카드 | 제목 끝 강조색 점(5px). `바뀐 것 보기`를 누르면 그 카드들만 2초간 강조 테두리. 다음에 화면을 열면 점 사라짐 |
| 열 `⋯` | `이름 바꾸기` · `다른 영역과 합치기 ›`(영역 목록) · `세부 주제 추가` · 구분선 · `영역 삭제` (할 일은 미분류로 — 할 일 자체는 지우지 않음, 확인 대화 상자) |
| 세부 주제 머리 `⋯`(호버) | `이름 바꾸기` · `다른 주제와 합치기 ›` · `주제 삭제`(카드는 영역 바로 아래로) |
| 이름 바꾸기 | 그 자리에서 입력칸. Enter 저장 · Esc 취소 · 빈칸/20자 넘음 거부 |
| 열 머리 `+` | 열 맨 위에 입력 카드. Enter = 기본함에 할 일 생성 + 이 영역에 직접 배치(📌). 날짜 인식은 02와 같다 |
| ✦ AI로 다시 정리 | 누르면 아이콘이 돌고 알림 띠 자리에 `할 일 32개를 정리하는 중… ■ 멈추기`. 끝나면 알림 띠 |
| AI 쓸 수 없음 | ✦ 비활성 + 툴팁 `지금은 AI를 쓸 수 없어요. 직접 영역을 만들어 정리할 수 있어요.` 화면은 그대로 쓸 수 있다 |
| 처음(분류 없음) | 보드 가운데: 지도 아이콘 + `할 일을 영역별로 한눈에 보여 드려요` + `학교·회사·개인처럼 AI가 나눠 드리고, 직접 고칠 수도 있어요` + [AI로 정리하기](주 버튼) · [직접 영역 만들기] |
| 할 일 없음 | `정리할 할 일이 없어요` + [할 일 목록 열기] |
| 보기 옵션(거름틀) | 팝오버: `완료한 항목 보이기`(끔) · `날짜 없는 항목 보이기`(켬) · `범위: 모든 리스트 / 고른 리스트 ›` |
| 머리 `⋯` | `AI 분류 모두 지우기`(직접 옮긴 것은 남김) · `직접 옮긴 것도 AI에 맡기기` · 구분선 · `작업 지도 도움말` |

## 4. 인터랙션
| 동작 | 결과 |
|---|---|
| 카드 끌기 → 다른 열·주제 | 그 영역·주제로 이동, 📌(직접 옮김). 열 머리에 놓으면 주제 없이 영역 바로 아래 |
| 카드 끌기 → 같은 주제 안 | 순서만 바뀐다(이 화면 안의 순서, 리스트 순서와 별개) [임시] |
| 열 머리 끌기 | 열 순서 바꾸기 [임시 — 틱틱 칸반 열 끌기 미확인] |
| 카드 클릭 / 체크박스 | 상세 열기 / 완료(02 완료 동작 · XP 포함) |
| 카드 우클릭 | 02의 태스크 메뉴 + 맨 위 `영역 옮기기 ›` |
| AI 정리 | 미완료 할 일·일정 중 **직접 옮기지 않은 것**만 대상. 사용자가 만든·이름 바꾼 영역은 이름을 바꾸지 않는다 |
| 되돌리기 | 방금 정리 전 상태로(정리 뒤 사용자가 옮긴 카드는 그대로) |
| 자동 정리 | 화면을 열 때 미분류 새 할 일이 5개 이상이고 마지막 정리가 1시간 넘었으면 자동 실행 [임시] — 서버 상한 안에서 |
| 키보드 | ←→ 열 이동, ↑↓ 카드 이동, Enter 상세, Space 완료 [임시] |

## 5. 데이터
| 테이블(새로) | 칸 | 설명 |
|---|---|---|
| `map_areas` | common + `name`, `parent_id`(null = 영역, 값 = 그 영역의 세부 주제), `sort_order`, `source`(`ai`/`user`) | 이름을 사용자가 바꾸면 `source=user` → AI가 이름을 바꾸지 않는다 |
| `task_areas` | common + `task_id`, `area_id`(영역 또는 세부 주제), `source`(`ai`/`user`), `run_id` | 할 일 1개당 1행(id = task_id로 결정적). `source=user`면 AI가 덮어쓰지 않는다 |
- 읽기: `tasks`(삭제·취소 제외, 보기 옵션 조건) LEFT JOIN `task_areas`, `map_areas`.
- AI 입력: 할 일 **제목**·리스트 이름·날짜 유무 + 현재 영역·주제 이름(성장과 같은 범위: 제목까지). 출력은 앱이 검증: 존재하는 task_id만, 영역 ≤ 8 · 영역당 주제 ≤ 8 · 이름 ≤ 20자, 나머지는 미분류.
- 되돌리기: 정리 직전 `task_areas`/`map_areas` 스냅숏을 기기에 보관(마지막 1회) [임시].
- 모델 호출: `POST /ai/classify`(JWT) → Mac mini Ollama. 서버가 사용자당 상한을 건다(PRD AI 원칙). **[다음]** API 프록시가 생기기 전까지는 AI 없이 수동 영역만 동작한다.
- ⚠️ 새 테이블 2개 → 서버 스키마·`server/db/migrations`·동기화 규칙 변경이 필요하다. 구현 전에 따로 설명하고 진행한다.

## 6. 완료 기준
- [ ] 그래프: 뿌리→영역→주제→할 일이 위→아래로 이어지고, 이동·확대·전체 맞춤·접기·노드 선택 강조·끌어서 옮기기가 된다.
- [ ] 보드: 틱틱 칸반과 나란히: 열 폭 258, 열 머리 모양, `+ 새로운 영역` 위치, 카드 높이 40/56·간격 8·색이 같다.
- [ ] AI 없이: 영역 만들기 → 카드 끌어 넣기 → 이름 바꾸기 → 합치기 → 삭제(할 일은 미분류로) 전부 동작하고 동기화된다.
- [ ] AI 정리 후 직접 옮긴 카드와 사용자가 이름 지은 영역은 바뀌지 않는다. 되돌리기가 정리 전으로 돌린다.
- [ ] 카드 체크 = 완료 + XP, 카드 클릭 = 상세.
- [ ] AI를 끈 상태·할 일 0개·처음 상태 화면이 시안대로.
- [ ] 라이트·다크·좁은 창(보드 가로 스크롤).
