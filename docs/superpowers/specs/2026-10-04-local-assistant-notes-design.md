# 로컬 AI 비서 · 메모함 · 주제 위키

상태: 대화에서 합의한 제품 방향을 정리한 설계안. 아래 세부 동작은 구현 전 문서 검토 대상이다.

## 목적과 기존 기획의 변경

사용자가 생각나는 내용을 빠르게 기록하고, 기존 리스트·태그로 정리하고, 자연어로 일정을 등록하며, 자신의 일정과 완료 기록을 조회할 수 있게 한다.

기존 PRD의 할 일·캘린더·성장 기능에 이 기능을 추가한다. 기존의 서버 전용 AI 및 주 2회 제한은 KPI/주간 리포트의 기존 정책이다. 이번에 합의한 로컬 비서에는 그 제한을 적용하지 않는다. 로컬 모델 장애 시 클라우드로 자동 전송하지 않는다.

기존 카카오톡 기록을 가져오는 연동은 범위에 포함하지 않는다. ‘나에게 보내기’처럼 빠르게 기록하는 앱 내부 경험을 만든다.

## 합의한 범위

- 새 할 일을 기존 리스트·태그로 자동 분류한다. 긴 메모를 자동으로 여러 할 일로 분해하지 않는다.
- 자연어로 날짜·시간·기간·반복이 있는 할 일을 등록한다.
- AI는 질문할 때 최신 할 일과 일정을 조회한다.
- 타이머 없이 완료된 일정의 길이와 완료 태스크 수를 집계한다.
- 성장 메뉴 바로 아래에 AI 비서 메뉴를 추가하고, 화면 오른쪽 하단 FAB에서 작은 채팅창을 연다. 같은 대화 기록을 공유한다.
- 별도 메모함 메뉴에서 텍스트·링크를 빠르게 저장한다.
- 주제별 위키는 사용자가 ‘AI로 정리하기’를 누를 때 생성·갱신한다. 원본 메모는 유지한다.

## 비교한 접근과 선택

1. 최신순 메모 카드만 제공: 입력은 간단하지만 관련 정보를 재구성하기 어렵다.
2. 모든 기록을 자동 위키화: 정리는 강력하지만 짧은 메모에도 구조를 강요하고 갱신 오류가 눈에 잘 띄지 않는다.
3. 빠른 메모함 + 주제별 요청형 위키: 선택한 방향. 입력을 방해하지 않고 필요할 때 관련 기록을 정리한다.

## 화면과 동작

### AI 비서

전용 화면은 대화 이력, 메시지 입력, 응답 및 결과 카드로 구성한다. FAB는 같은 대화를 작은 오버레이로 열며 현재 캘린더·리스트의 선택과 스크롤을 유지한다. 작은 창에서 전용 화면으로 확장할 수 있다. 모달·날짜 팝업을 가리지 않도록 겹친 입력 UI에서는 FAB를 숨긴다.

전송 중에는 중복 전송을 막고 중단할 수 있다. 실패한 입력은 보존한다. 모델 연결 불가 상태에서는 연결 상태와 재시도를 표시하고 일반 할 일·메모 기능은 정상 동작한다.

응답 종류:
- 등록 결과: 생성한 할 일/일정 링크, 해석한 날짜·분류, 실행 취소.
- 조회 결과: 실제 항목으로 이동할 수 있는 카드.
- 집계 결과: 기간, 집계 기준, 수치, 근거 항목.
- 정보 부족: 필요한 날짜·시간 등 한 가지 질문으로 이어지는 대화.

명확한 생성 요청은 즉시 등록한다. 시간이 지정되지 않은 일반 할 일은 시간 없이 생성할 수 있다. ‘오후에 회의’처럼 정확한 시간이 필요한 일정 요청은 시각을 묻는다. 겹치는 일정이 있으면 충돌을 알려 주며 기존 일정을 임의로 이동하지 않는다. 기존 항목의 수정·삭제를 광범위하게 자동 실행하는 기능은 첫 범위에서 제외한다.

### 자동 분류

입력은 즉시 저장하고 AI 분류는 비동기로 실행한다. 사용자가 지정한 리스트·태그를 우선하며 모델은 유효한 기존 ID만 선택할 수 있다. 새 카테고리를 임의로 생성하지 않는다. 불명확하거나 실패하면 기본함에 유지한다.

분류 결과와 되돌리기를 간단히 표시한다. 분류 요청 후 사용자가 직접 수정했다면 늦게 도착한 결과가 덮어쓰지 않는다. 수정 사례는 다음 분류의 참고 자료로 사용할 수 있으며 모델 재학습은 첫 범위에서 제외한다. 자동 적용 기준은 한국어 평가셋에서 검증하며 모델의 자기 보고 확률만으로 정확성을 보장하지 않는다.

### 메모함

최신순 카드와 하단 입력창이 기본이다. 제목·폴더 입력 없이 저장한다. 검색과 주제 필터를 제공한다. 주제 묶음은 원본 메모를 이동하거나 덮어쓰지 않는 별도 연결이다. 사용자가 주제 연결을 고칠 수 있다.

메모 상세에는 ‘할 일로 만들기’, ‘일정으로 만들기’가 있다. 누르면 제목·날짜·분류를 채운 등록 초안을 보여주고 사용자가 확정한다. 이는 대화에서 명시적으로 등록을 요청하는 흐름과 구분한다. 원문은 설명으로 보존하고 생성 항목과 연결한다. 이미 전환된 메모에는 연결 항목을 보여주며 같은 요청의 재시도는 중복 생성하지 않는다.

### 주제 위키

주제를 열고 ‘AI로 정리하기’를 누르면 그 주제에 연결된 메모를 바탕으로 정리한다. 내용은 개요, 아이디어, 결정 사항, 열린 질문, 연결된 할 일·일정으로 구성하되 근거가 없는 구역은 비워 둔다.

- 각 요약 항목은 출처 메모로 연결한다.
- 명시적인 결정 근거 없이 아이디어를 결정으로 바꾸지 않는다. 상충하는 기록은 함께 표시한다.
- 처음 생성한 결과는 출처와 함께 보여준다. 기존 페이지 갱신은 변경 초안을 보여주고 적용한다.
- 사용자가 직접 수정한 구역은 자동 덮어쓰기에서 보호한다. 보호된 구역의 수정안은 별도 제안으로 표시한다.
- 버전 이력을 보관하여 이전 정리로 돌아갈 수 있다.
- 생성 도중 원본이 바뀌면 ‘원본 변경됨’을 표시하고 재정리를 제공한다.
- 원본 삭제·연결 해제 후에도 과거 출처가 현재 유효한 것처럼 보이지 않도록 출처 상태를 표시한다.

## 완료 기록 집계 기준

시간은 앱에서 계산하고 모델은 결과를 설명한다. ‘실제 측정 시간’이라고 표현하지 않는다.

- 기본 기간은 사용자 시간대와 주 시작 설정을 따른다.
- ‘이번 주 완료한 것’은 completed_at이 기간 안에 있는 완료 태스크를 대상으로 한다.
- 유효한 시작·끝 시각이 모두 있는 완료 태스크만 기간 길이를 합산한다.
- 날짜만 있거나 단일 시각만 있는 항목은 건수로 표시한다. 종일 일정을 24시간으로 환산하지 않는다.
- 기간을 가진 상위 태스크와 하위 태스크의 합계 중복을 피하기 위해 시간 합계는 상위 기간을 우선하고 근거에 포함 항목을 표시한다.
- 서로 겹치는 별도 완료 일정은 각각 합산하며 ‘완료 일정 길이 합계, 겹친 시간 포함’이라고 명시한다.
- 태그별 값은 중복 태그가 있으므로 서로 합쳐 총시간이라고 표시하지 않는다.
- 삭제 항목·하지 않음 상태는 제외한다. 반복 일정은 실제 완료된 회차만 집계하고 가상 미래 회차는 제외한다.
- 미완료 일정의 예정 시간은 별도로 조회한다.

예: ‘완료한 공부 일정은 6시간이고, 시간이 없는 완료 태스크는 3개예요.’

## 구현 경계와 데이터

Electron 메인 프로세스가 로컬 추론 제공자에 연결한다. 렌더러는 제한된 IPC API를 사용한다. 모델에 SQL이나 임의 셸 실행 권한을 주지 않는다. 검색·집계·생성은 앱에서 검증한 도구를 통해 수행하고, 원문 메모 속 지시는 사용자 명령이 아닌 조회 자료로 취급한다.

책임을 분리한다:
- 로컬 추론 어댑터: 연결 상태, 모델 목록, 구조화 결과, 스트리밍, 취소.
- 분류 서비스: 기존 분류 후보, 사용자 수정 사례, 최신 상태 검사.
- 비서 도구: 할 일 검색, 일정 조회, 완료 집계, 검증된 일정 생성.
- 메모 서비스: 원본 저장·검색·주제 연결·전환.
- 위키 서비스: 출처 수집, 생성 초안, 보호 구역, 버전 관리.

기존 tasks/lists/tags/task_tags를 재사용한다. 추가 엔터티는 notes, note_topics, note_topic_links, note_task_links, wiki_pages, wiki_versions, wiki_sources, assistant_threads, assistant_messages, assistant_actions, classification_feedback로 나눈다. owner_id와 생성/수정 시각은 기존 스키마 규칙을 따른다. 위키 출처는 메모 ID와 생성 당시의 수정 시각을 보관한다. 생성 요청 ID로 재시도 중복을 막고 실행 취소는 이후 사용자 수정과 충돌하는지 확인한다.

데이터 스키마 변경 시 로컬 DB뿐 아니라 서버 생성 SQL·업로드 허용 테이블·동기화 규칙·미리보기 DB도 함께 반영한다. 모델 파일과 기기별 연결 설정은 동기화하지 않는다.

## 모델 선정

Jev 계열 판단 모델은 분류 후보, 생성형 모델은 대화·위키 후보로 평가한다. 처음부터 두 모델을 필수로 두지 않는다. 제공자 인터페이스를 분리해 한 모델로 시작하고 성능 근거가 있을 때 분리한다.

정확한 모델·런타임은 실행 기기 메모리, 한국어 평가, 라이선스, 추론 속도 확인 후 선정한다. 아직 선정되거나 설치된 것으로 간주하지 않는다. 이는 제품 동작 설계와 분리된 구현 전 평가 단계다.

## 단계와 검증

1. 메모함 저장·검색·수동 전환·원본 연결을 먼저 구현한다.
2. 로컬 모델을 평가하고 분류 및 자연어 등록을 연결한다.
3. AI 메뉴·FAB와 조회·집계를 연결한다.
4. 주제 위키 생성·출처·갱신 비교·보호 구역을 연결한다.

각 단계는 별도 화면 명세와 구현 계획을 갖는다. 기존 캘린더 UX의 미해결 차이를 AI 기능 완료로 숨기지 않는다.

완료 기준:
- 모델이 꺼져도 메모·일정 입력 및 조회가 동작한다.
- 사용자 지정 분류와 생성 후 수정을 늦은 AI 결과가 덮어쓰지 않는다.
- 상대 날짜·반복·누락 시각·충돌·재시도·실행 취소를 검증한다.
- 시간 없는 태스크, 종일, 반복 완료, 중복 태그, 주 경계를 포함한 집계 결과를 검증한다.
- 대화 전용 화면과 FAB의 메시지 및 결과가 일치한다.
- 메모 전환 후 원본과 일정이 연결되며 재시도해도 중복되지 않는다.
- 위키 요약의 출처를 열 수 있고 사용자 수정은 갱신 후에도 보존된다.
- 메모 내용이 AI에게 도구 실행을 지시하더라도 실행 명령으로 채택하지 않는다.

## 추가 합의: 외부 AI 계정의 구독 한도

AI 비서 자체의 토큰 집계와 별개로 GPT·Claude·Grok·Gemini의 여러 계정 사용 한도를 모아 보는 독립 탭을 추가한다. 상세 조사와 지원 범위는 [계정 한도 대시보드 설계](2026-10-04-account-usage-dashboard.md)를 따른다. 일반 채팅과 코딩 도구의 한도를 혼동하지 않으며 API 토큰·비용은 첫 범위에 포함하지 않는다.
