# 완료가 다른 기기에 안 보이는 문제 조사 (2026-10-25 밤)

사용자 보고: "할 일/일정을 분명히 완료 표시했는데, 동기화를 눌러도 다른 기기에 완료로 안 되어 있다."
조사 범위: 이 Mac 설치본 데스크톱(Kkumteul.app 1.0.1, 10-12 빌드) · 실기기 아이폰 14 Pro(꿈틀 1.0.0(1), 10-21 빌드, Wi-Fi 페어링으로 앱 폴더 **읽기 복사**) · Mac mini 서버 로그(읽기만) · 업로드 경로 코드 · QA 계정 두 클라이언트 재현.
개인 내용(할 일 제목 등)은 적지 않았다. 개수·시각·표·칸 이름·오류 코드만 적는다.

## 1. 결론

**원인(확정): 아이폰 앱이 10-14부터 서버에 한 번도 붙지 못하고 있다.** 아이폰에서 한 완료는 기기 안 업로드 대기열(ps_crud)에만 쌓이고, 다른 기기 변경도 받지 못한다.

- 아이폰 리프레시 토큰이 죽어 있다. 10-21 전 서버는 토큰을 쓸 때마다 새로 주고 옛 토큰을 죽였는데, 아이폰이 새 토큰을 저장하지 못했다(10-21 커밋 f2a197d에 적힌 원인). 그래서 토큰을 새로 받으려 할 때마다 영영 401이 난다.
- 아이폰에 깔린 10-21 빌드는 401을 받으면 `expireLocal()`이 **토큰을 기다리는 동기화 연결이 끊기기를 기다리다 멈춘다**(교착). 그래서 로그인 화면으로 가지 않고 "로그인된 채 동기화만 죽은" 좀비 상태가 된다. 이 상태에서는 당겨서 새로 고침(syncNow)이 8초 동안 기다리기만 하고 아무 오류도 보여 주지 않는다. 이 교착은 오늘 20:25 커밋 88135c0에서 고쳤지만, 고친 빌드가 아이폰에는 아직 깔리지 않았다.
- 사용자가 누른 "동기화"가 아무 일도 하지 않은 것과 "완료했는데 다른 기기엔 안 됨"이 이것으로 설명된다.

**업로드 경로 자체(완료·완료 취소·반복 완료·오프라인 뒤 다시 붙기)는 정상이다.** QA 계정 재현에서 8/8 통과했고 대부분 1초 안에 도착했다(§3.4). 데스크톱 설치본도 대기열 0건이고 최신 체크포인트까지 받아 두었다.

## 3. 코드 점검

### 3.1 업로드 (데스크톱 `apps/desktop/src/main/sync.ts` · 휴대폰 `apps/mobile/src/data/auth.ts` uploadData · 서버 `server/api/src/upload.ts`, `server.ts` POST /sync/upload)
- 서버가 400을 주는 경우는 `bad id`(빈 id, 200자 초과), batch가 배열이 아닌 경우, 모르는 op뿐이다. 완료는 `PATCH tasks {status, completed_at, modified_at}`(반복이면 + `PUT tasks rec:…` + `PATCH due_at`, + `PUT xp_events`)라서 **400이 나지 않는다.** 따라서 "400이면 버리고 진행" 규칙 때문에 완료가 조용히 사라지는 경로는 없다(확정).
- 모르는 표·칸은 409다. 앱은 버리지 않고 다시 시도한다.
- **Postgres 형식 오류는 500이다**(재현: 정수 칸에 글자 → `HTTP 500 server error`). 앱은 400이 아닌 오류를 계속 다시 시도한다. 그래서 형식이 깨진 연산이 하나라도 생기면 **그 기기 대기열 전체가 영영 막히고 내려받기도 같이 멈춘다**(§2.4). 지금은 실제로 일어난 적이 없지만 잠재 위험이다.
- **서버에 없는 행에 PATCH를 보내면 `200 {applied:1}`이 돌아오고 아무것도 바뀌지 않는다**(재현). 다른 기기에서 영구 삭제(휴지통 비우기)한 할 일을 오프라인 기기가 완료하면 완료는 조용히 사라진다. 드문 경우다.

### 3.2 충돌 규칙
- PATCH는 바뀐 칸만 보낸다. 그래서 다른 칸을 동시에 고치면 둘 다 남는다(재현 통과). 같은 칸이면 **서버에 늦게 도착한 쪽이 이긴다(고친 시각이 아니라 도착 순서).** 재현에서 오프라인으로 완료한 A가 나중에 붙자, B가 그사이 해 둔 완료 취소를 덮어썼다.
- 이 때문에 아이폰의 47건이 이제 올라가면 그 뒤에 데스크톱에서 고친 값을 옛 값으로 덮는다. 지금 겹치는 것은 **할 일 3건**이다: 마감 PATCH 1(10-22 값), 휴지통으로 보내기 PATCH 1(10-23), 완료 PATCH 1(10-25 14:06). 세 할 일 모두 데스크톱에서 오늘 22:55에 마감을 내일로 옮긴 것이다. 올라가면 마감 1건은 옛 날짜로 돌아가고, 1건은 휴지통으로 가고, 1건은 완료된다. 일정·메모는 겹치지 않는다. 알림 1건은 서버에 있다(PUT이라 덮어씀).

### 3.3 만료 자동 정리(48)와의 충돌
- 서버는 열린 할 일만 휴지통으로 보낸다(`deleted_at`). 오프라인 기기가 그 할 일을 완료해서 올리면 `status=1`이면서 `deleted_at`도 있는 상태가 된다. 재현 결과 `status=1, 휴지통=1`이었다. 다른 기기에서는 "완료"가 아니라 휴지통에서만 보인다. 이번 아이폰 완료 5건 중 서버에서 휴지통에 있는 것은 0건이었다.

### 3.4 재현 (QA 계정, 운영 서버, PowerSync node 클라이언트 두 대 · 앱과 같은 `taskCore` 경로 · 끝나고 시험 행 지움(남은 것 0))
| 경우 | 결과 |
|---|---|
| 완료 A → B (status·completed_at) | PASS 1.0s |
| 완료 XP 행 A → B | PASS |
| 완료 취소 B → A | PASS 0.2s |
| 반복 완료: 완료 기록 행(status 1) | PASS 1.0s |
| 반복 완료: 원래 할 일 다음 회차 | PASS |
| 오프라인 완료 → 다시 붙으면 B에 완료 | PASS 0.2s |
| 오프라인 동안 B 제목 + A 완료 둘 다 남음 | PASS |
| 같은 칸 충돌: 늦게 도착한 A 완료가 이김 | PASS(규칙대로) |
| 휴지통 동안 오프라인 완료 | status=1 · 휴지통=1 (§3.3) |
| 정수 칸에 글자 PATCH | HTTP 500 (§3.1) |
| 서버에 없는 행 PATCH | HTTP 200 applied 1, 실제 변경 없음 (§3.1) |

재현 스크립트는 저장소에 넣지 않았다(스크래치 `complete-e2e.ts`).

### 3.5 동기화 규칙 · 동기화 버튼
- `server/powersync/sync-config.yaml`은 `SELECT * FROM tasks WHERE owner_id = auth.user_id()`로 모든 칸을 내려보낸다. Mac mini 배포본과 저장소 파일이 같다(diff 없음). API 컨테이너의 스키마 md5도 저장소와 같다.
- 데스크톱 `syncNow`(레일 ⟳·⌘S): 다시 연결하고 최대 12초 기다린 뒤 `offline`·`error`·`timeout`·`pending N`을 돌려준다.
- **휴대폰 `syncNow`**: 끊겨 있으면 `connect`만 부르고 최대 8초 기다린 뒤 **결과 없이 끝난다.** 토큰이 죽었거나 대기열이 막혀 있어도 사용자에게 아무것도 보이지 않는다. 이번 보고의 "눌러도 그대로"가 이것이다.

## 4. 고칠 방안

**지금 사용자에게 (코드 수정 없이)**
1. **아이폰에서 로그아웃하지 말 것.** 로그아웃하면 대기열 47건(완료 5건 포함)이 지워진다. 지금 빌드에서 로그아웃한 뒤 다시 로그인해도 지워진다. 교착 때문에 "만료된 같은 계정" 기록(stale)이 저장되지 않아서, 다시 로그인하면 `adopt → disconnectAndClear`로 간다.
2. 고친 빌드(88135c0 이후)를 아이폰에 **덮어 설치**한다(지우고 다시 깔면 안 된다). 앱을 켜면 401 → stale 기록 → 로그인 화면이 나온다. **같은 계정**으로 로그인하면 지우지 않고 47건을 올린다. 그 전에 §3.2의 할 일 3건을 어떻게 할지 사용자에게 확인한다(옛 값으로 덮여도 되는지).
3. Windows도 10-19부터 붙지 않았다. 같은 상태일 수 있으니 켜서 확인한다(데스크톱 1.0.2부터는 같은 계정으로 다시 로그인하면 지우지 않는다). 설치본 Mac 데스크톱(1.0.1)도 1.0.2 이상으로 올린다.

**코드 (명세·사용자 확인 뒤)**

④ **휴대폰 로그인 시 데이터 지키기:** `adopt()`에서 stale 기록이 없더라도, 기기 대기열(ps_crud)이 남아 있고 그 행들의 owner가 로그인한 사용자와 같으면 지우지 않는다. 로그아웃할 때 올리지 못한 변경이 N개 있으면 "올리지 못한 변경 N개가 사라져요"라고 묻는다. 데스크톱 `adopt`도 같게 한다.

⑤ **동기화가 죽으면 보이게:** 휴대폰 `syncNow`가 데스크톱처럼 `offline/error/timeout/pending`을 돌려주고 토스트를 띄운다. 토큰 401이면 바로 로그인 화면으로 간다(88135c0). 서버는 `/sync/upload` 4xx도 사용자 id 앞자리·표·코드만 한 줄로 로그를 남긴다(지금은 400·409가 안 보인다).

⑥ **서버 500으로 대기열이 영영 막히지 않게:** Postgres 형식·제약 오류(22xxx·23514 등)는 400으로 돌려서 앱의 "한 건씩 → 깨진 것만 건너뜀" 경로를 타게 한다. 버리는 연산은 서버 전용 표(예: `upload_rejects`)에 남겨서 나중에 되살릴 수 있게 한다. 이때 서버 스키마 변경이 들어가므로 계획을 먼저 설명하고 승인받는다.

⑦ **조용한 무시 줄이기:** PATCH·DELETE가 0행이면 응답에 `missing: [id…]`를 넣고 로그를 남긴다. 오프라인 완료가 휴지통에 들어간 할 일에 닿았을 때(§3.3) 완료를 휴지통에서 꺼낼지는 명세(48)에서 정한다.

⑧ (선택) 같은 칸 충돌을 "도착 순서"가 아니라 `modified_at`이 더 늦은 쪽이 이기게 하려면 서버 PATCH에 `WHERE modified_at <= $new` 같은 조건이 필요하다. 오래 오프라인이던 기기가 옛 값을 덮는 문제(§3.2)를 막는다. 동기화 규칙 변경이라 결정이 필요하다.
