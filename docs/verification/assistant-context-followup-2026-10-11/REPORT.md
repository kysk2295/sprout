## 비교 방법과 평가 도구 수정

`cases.json`: 합성 초기 대화 + 4종류 대화 × 2턴. 기준 모델과 후보에 같은 사용자 입력을 넣고 각 버전의 답변으로 후속 대화를 구성했다. 사용자 계정·DB와 분리한 임시 API/합성 DB를 사용하고, 실제 Mac mini MLX 게이트웨이로 추론했다.

초기 검사 도구에 초기 history 배열을 두 버전이 공유하는 오류가 있었다. 해당 16턴은 `invalid-shared-history.jsonl`에 보관하고 평가에서 제외했다. 초기 배열을 버전별 복제하도록 고친 뒤 전체 비교를 다시 실행했다. 이름/종도 양쪽에 동일하게 전달한다.

유효 결과: `results.jsonl` 기준 8 + 후보 v1 8턴. 관점 보강 후 `final-candidate.jsonl` 8턴을 추가했다. 총 유효 24턴이며 서로 다른 후보를 하나의 성능 수치로 합치지 않는다.

## 남은 과제
