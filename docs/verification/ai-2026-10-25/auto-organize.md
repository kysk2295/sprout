> 범위: 조사와 제안만 했다. 코드·git·데스크톱 DB는 바꾸지 않았다(데스크톱 렌더러 DB는 CDP 9231로 SELECT만 했다).
> 대상: QA 계정 `qa-20261025-mggu`, 데스크톱 개발 앱 `SPROUT_PROFILE=qa-sync`.
> 재현: 운영 서버 `macmini.tail425c97.ts.net`, 새 시험 계정 `qa-autotag-0sbz6y@example.com`(`~/.config/sprout/e2e-accounts.jsonl`에 `qa:true`로 적어 둠). 앱과 같은 지시문·본문·검증 코드를 썼다. 원문 답은 [auto-organize-raw.jsonl](auto-organize-raw.jsonl)에 있다.

## 0. 요약

- **리스트 이동은 모두 `useListSuggester`(30 §B.3 ② "새 할 일 자동 분류")가 했다.** 두 갈래가 있다.
  - **AI 갈래(용도 `map`)**: 12:14:00의 6개(`S1 묶음 2/8/10/11/19` → 공부, `R1 아이폰에서 만듦` → 포트폴리오 사이트). 모델(Qwen3.5-9B)은 확신 점수를 **95 아니면 0으로만** 낸다. 그래서 "85 이상이면 바로 옮김"이라는 문턱이 아무것도 거르지 못한다. 공부 리스트 예시에 `S1b 시간 재기`가 있으니 `S1 묶음 N`도 95로 공부에 넣는다. 재현에서 5번 중 5번 그랬다.
  - **낱말 검사 갈래(AI 없음)**: 12:14:33·12:17:50의 `S12_offline_1`×2, `S12_once_check`. 앞에서 옮겨진 `S1 묶음` 5개가 공부의 "최근 할 일"이 됐고, `s12`가 `s1`과 앞글자 일치(`sameWord`)로 5표를 얻어 문턱 3을 넘었다. **AI의 첫 실수를 낱말 검사가 증거로 삼아 키운 연쇄**다.
- **태그는 모두 `useAutoTagger` → `tagTasks` → `/ai/tag`(33 §7)가 붙였다.** 행이 `source='ai'`, `confidence=90`, `run_id=null`(새 할 일 경로)로 남아 있다. 태그가 `중요·5분·업무` 셋뿐인데, 모델은 업무·공부 비슷한 제목이면 `업무 95 + 중요 85~90`을 함께 붙인다. 85가 문턱과 똑같아서 그대로 통과한다. `중요`·`5분`은 주제가 아니라 속성 태그인데 막는 규칙이 없다.
- **"말없이"인 이유**: 리스트 이동은 **2초 토스트** 하나만 띄운다(`Toast.tsx`: 되돌리기가 있는 토스트 = 2000ms). 알림 패널(notices)에는 아무것도 남지 않는다. 할 일을 만든 기기가 휴대폰(iPhone·Android)이어도 옮기는 쪽은 데스크톱이라, 만든 사람의 화면에는 토스트조차 뜨지 않는다. 태그는 알림 패널에 `AI가 태그 15개 붙였어요 · 되돌리기` 한 줄이 남는다.
- **명세와 비교하면** 코드는 명세(30 §B.0-2 "확실하면 자동 이동 + 토스트", 33 §7 "묻지 않고 조용히")대로 움직였다. 문제는 명세가 깔고 있는 전제가 깨졌다는 점이다. 10-05 실측(26건, 잘못 옮김 0)이 가정한 "점수가 눈금대로 나온다"는 전제가 지금 모델에서는 맞지 않는다. 틱틱에는 자동 이동도 자동 태그도 없다(새 할 일은 기본함이나 사용자가 정한 기본 리스트에 남는다).

## 2. 재현 결과 (운영 서버, Qwen3.5-9B, 앱과 같은 지시문)

문맥은 QA 계정과 같게 잡았다. 태그 `업무·중요·5분`, 리스트 `업무·포트폴리오 사이트·공부·생활`과 12:14 직전의 리스트별 최근 할 일 예시. 제목 20개(일상 5 · 업무 3 · 공부 3 · 영문 3 · 의미 없는 시험 문자열 6)를 넣었다. 20개 묶음 2회, 실제 사건 묶음 2회, 한 개씩 8개. 호출은 `tag` 13회, `map` 12회. 지연은 한 개 12~33초, 20개 묶음 52~60초.

### 2.1 리스트 분류 `/ai/map`

| | 20개 묶음 #1 | #2 |
|---|---|---|
| 점수 분포 | **95: 17개 · 0: 3개**(그 밖의 값 없음) | 똑같음 |
| 의미 있는 제목 14개 | 14개 모두 `MOVE`. 리스트 자체는 그럴듯함(물·우유·빨래·전화·치과·Buy groceries → 생활 / 보고서·메일·회의·Fix login bug → 업무 / 토익·과제·강의·Read chapter 3 → 공부) | 같음 |
| 의미 없는 제목 6개 | **3개 잘못 MOVE**: `S1 묶음 2`→공부, `S12_offline_1`→공부, `R1 아이폰에서 만듦`→포트폴리오 사이트. `test123`·`asdf`·`ㅁㄴㅇㄹ`는 0점(맞음) | 같음 |
| 사건 묶음 6개(S1×5 + R1) | S1 5개 모두 공부 95 MOVE, R1 생활 65 칩 | 같음 |
| 한 개씩 | `S1 묶음 2`→공부 95 MOVE, R1·asdf 0, 의미 있는 제목 5개 모두 95 MOVE | — |

- **잘못된 자동 이동: 의미 없는 제목 6개 중 3개(50%), 묶음에서는 몇 번을 돌려도 같다**(온도 0이라 같은 입력이면 같은 답).
- 점수가 95·0 두 값뿐이다. "60~89 = 아마도"라는 눈금은 한 번도 나오지 않았다(6개 묶음의 R1 65 한 건만 예외). 그래서 `autoScore 85`·`chipScore 50`이 사실상 "AI가 무언가를 골랐는가"만 가른다.
- `guardSure`가 못 막는 이유: `isVague`는 `keywords()`가 0개일 때만 참이다. 그런데 `s1`·`r1`·`s12`처럼 영문+숫자 2~3글자 조각도 "뚜렷한 낱말"로 센다.

### 2.2 자동 태그 `/ai/tag`

| | 결과 |
|---|---|
| 20개 묶음 #1·#2(같음) | 태그가 붙은 할 일 5개, 붙은 태그 10개 중 **틀림 7개(정밀도 30%)**: 업무 제목 3개에 `업무 95`(맞음) + `중요 85`(틀림). 공부 제목 `기업경제학 과제 제출`·`운영체제 강의 복습`에 `업무 95 + 중요 85`(둘 다 틀림). 나머지 15개(일상·영문·시험 문자열)는 없음(맞음) |
| 한 개씩 8개 | `주간 보고서 작성` → `업무 95 + 중요 90`(중요 틀림), `토익 단어 외우기` → `업무 85`(틀림), 나머지 6개 없음. 틀린 할 일 2/8 |
| 사건 묶음 재생(물 한 잔 + S1 6개, 공부 리스트 이름 포함) 2회 | 아무 태그도 없음 — **사건(7개 모두 중요+업무 90)은 빈 계정에서는 재현되지 않았다.** 같은 모델이라도 묶음 구성·문맥(그때 대기열에 함께 있던 할 일)에 따라 "모두에 같은 태그 두 개"로 무너지는 일이 있다. 사건 쪽 증거(`source=ai`·90·같은 `created_at`)는 확정이다 |

- 모델이 고르는 점수는 85·90·95 세 값뿐이고, **문턱 85와 같은 85가 자주 나온다**(`c < 85`만 버리므로 통과).
- `중요`는 "이 할 일이 중요하다"는 사람의 판단이다. 제목만 보고 알 수 없는 속성인데, 지시문은 `0-59: a guess`라고만 하고 이를 막지 않는다. `업무`는 같은 이름의 리스트가 있는데도 기본함 할 일에는 막히지 않는다(`allowed`는 **그 할 일의 리스트** 이름만 비교).
- 지시문의 `max_per_item: 2`와 "pick at most 2"가 두 칸을 채우는 쪽으로 미는 것으로 보인다(붙을 때는 거의 늘 2개).

## 4. 고칠 방안 (우선순위)

### P0 — 잘못된 이동·태그를 바로 멈춘다

1. **리스트 자동 이동을 "제안 칩 + 확인"으로 낮춘다(명세 30 §B.0-2를 사용자와 다시 정함).**
   - `data/listSuggest.ts shouldAutoMove`: AI 갈래(`keywordSure`가 아닌 것)는 자동 이동 대신 칩으로(`sure:false`). 모델 점수가 95/0뿐이라 85 문턱이 아무것도 거르지 못하기 때문이다.
   - 자동 이동을 남긴다면 조건은 **AI 점수 + 낱말 근거 둘 다**로 한다. 고른 리스트의 `keywordVotes ≥ 1`(코드 조각이 아닌 진짜 낱말) 또는 리스트 이름이 제목에 있을 때만.
   - 틱틱 기준과도 이쪽이 맞다(새 할 일은 놓은 자리에).
2. **의미 없는 제목을 건너뛴다.** `packages/schema/src/keywords.ts`:
   - `keywords()`에서 영문·숫자 코드 조각(`/^[a-z]{1,3}\d+[a-z]?$/`, `/^[a-z]+\d+$/` — `s1`·`r1`·`s12`·`test123`)과 한글 자모만 있는 조각(`ㅁㄴㅇㄹ`)을 뺀다. 그러면 `isVague`가 참이 되어 AI가 골라도 칩조차 안 된다.
   - `sameWord`의 앞글자 일치는 짧은 쪽이 **3글자 이상**일 때만 허용한다(`s12`≠`s1`).
   - 공용 함수라 휴대폰 정리 모드(`keywordPick`)도 같이 좋아진다.
   - 자동 태그 `askTagAi`에도 같은 `isVague` 거르기를 건다(제목이 막연하면 AI에 묻지 않는다).
3. **자동 태그에서 속성 태그·리스트 이름 태그를 뺀다.** `packages/schema/src/autoTag.ts`:
   - `validateTagAnswer`/`allowed`: AI(`source ai`)는 ⓐ 이름이 **어느 리스트·폴더와도 같은** 태그(`placeNameKeys`, 지금은 그 할 일의 리스트만 봄) ⓑ 속성 태그(이름이 `중요·긴급·나중에·N분·N시간` 같은 우선순위·길이 낱말 — `STOP_WORDS`와 비슷한 `ATTR_WORDS`) ⓒ 사용자가 직접 붙인 할 일이 3개 미만인 태그(무엇을 뜻하는지 증거가 없음)를 붙이지 못하게 한다. 이 태그들은 사전 검사(제목에 이름이 그대로 있을 때)로만 붙는다.
   - 문턱 `AUTO_TAG.autoScore` 85 → 90, 그리고 "85 = 같음"도 버린다(모델이 85를 "애매"로 쓴다).
   - `buildTagPayload`의 `max_per_item: 2` → 1, `TAG_SYSTEM`의 "pick at most 2" → "usually none; at most 1 unless the title names both". 태그마다 사용자가 붙인 예시 제목 3개를 보낸다(지금은 프로젝트만).
   - 태그가 5개 미만이고 사용자가 붙인 연결이 10개 미만이면 AI 갈래를 쉰다(`tagTasks`에서 `ask=[]`). 사전 검사만 돈다.

### P1 — "말없이"를 없앤다

4. **옮긴 기록을 알림 패널에 남긴다.** `useListSuggester`에서 이동 뒤 `addNotice({ kind: 'listmove', key: 'listmove:<day>', title: '새 할 일 N개를 리스트로 옮겼어요', body: '물 한 잔 마시기 → 🏠생활 …', undo: [...] })`(autotag처럼 하루 한 줄로 합친다). 토스트는 `toast.show(msg, undo, { ms: 6000 })`으로 늘리고, 여러 개일 때 리스트 이름도 보인다. `shared/notices`에 kind를 하나 더 둔다. 명세 01 §3.3·30 §B.2를 먼저 고친다.
5. **이 기기에서 만든 할 일만 자동 이동한다.** 다른 기기에서 동기화로 들어온 기본함 할 일은 칩으로만 둔다. 스키마 변경 없이 하려면 `mutations.ts`의 할 일 만들기가 렌더러 메모리(또는 `sprout.listSuggest.v1.local`)에 id를 적고, `shouldAutoMove`가 그 집합에 든 것만 통과시킨다. 휴대폰에서 만든 할 일이 그 화면에서 말없이 사라지는 문제가 없어진다.
6. **연쇄를 끊는다.** `readSuggestContext`의 `recent`(낱말 검사·AI 예시)에서 **자동 이동된 할 일을 뺀다.** 사람이 놓은 할 일만 증거로 쓴다. 자동 이동 id는 `suggestStore`에 `auto: Record<id, at>`로 남기고(되돌리기에도 쓴다), 사용자가 그 할 일을 직접 옮기거나 고치면 지운다. S12가 S1을 따라간 연쇄가 이것으로 막힌다.

### P2 — 측정 고정

7. 이 문서의 20개 제목(+ 의미 없는 6개)을 `scripts/`의 평가 묶음으로 둔다. 기준은 "의미 없는 제목 잘못 이동 0 · 태그 정밀도 ≥90%". 모델·지시문이 바뀔 때마다 돌린다. 30 §B.3 실측 표는 "점수 95/0 두 값뿐"이라는 오늘 관찰로 바꾼다.
8. 이미 잘못 붙은 QA 데이터는 알림 패널 `AI가 태그 15개 붙였어요 · 되돌리기`로 태그를 되돌릴 수 있다. 리스트 이동은 되돌리기 기록이 사라졌으므로 손으로 옮겨야 한다(이 조사에서는 손대지 않았다).
