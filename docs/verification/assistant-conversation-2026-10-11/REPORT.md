# 대화 맥락·캐릭터 정체성 개선 (2026-10-11)

## 변경

별도 워크트리 `jev-runtime-release`, 브랜치 `kysk2295/assistant-conversation-quality`, 기반 `0debea4`. Jev v7 Q6 + Qwen3.5 9B MLX 4bit 동시 상주 구조와 모델 가중치는 그대로다. 재학습하지 않았다.

- 승인된 분류 요청의 모델 오류·잘못된 응답·타임아웃은 Qwen의 도구 없는 대화로 전환한다. 인증·상한·대기열·취소 오류는 숨기지 않는다.
- 낮은 분류 확신은 고정 “어떤 일을 어떻게…” 대신 자연스러운 확인 대화로 보낸다. 조회·변경 도구를 열지 않는다.
- 일반 대화 프롬프트에 역할 구분, 앞선 취향/조건, 짧은 후속 질문, 주제 전환, 잘못된 답 정정을 명시했다. 건강·경제 일반 설명과 개인별 판단을 구분한다.
- 캐릭터 자신을 가리키는 질문은 실제 별명으로 판별한다. ‘어머니’ 안의 ‘니’를 캐릭터 대명사로 오인하지 않는다.
- 새 `assistantPersona.ts`에 달팽이·꿀벌·애벌레·개구리의 성격·말투·취미를 정의했다. 공통 규칙 + 서버 소유 정체성으로 조립한다. 데스크톱/모바일은 매 턴 DB의 선택된 종을 전송한다. 이름 변경과 성격 변경을 분리하고, 구종 ID와 미선택 새싹을 지원한다.
- 첫 비교에서 드러난 최근 대화 사실의 불필요한 조회에는 `conversation_context` 보호 규칙을 추가했다. 명시적 앱 조회/변경은 제외한다. 최근 2턴의 사용자 발화만 근거로 삼는다. 이 규칙과 자기소개 보호 규칙은 학습 모델의 성능으로 계산하면 안 된다.

## 실모델 비교: 첫 수정안 60턴

`results.jsonl`: 기존 30턴 + 첫 수정안 30턴. 같은 6개 사용자 대화를 5턴씩 순서대로 실행했다. 각 버전이 생성한 답변을 그 버전의 다음 턴에 넣었다. 즉 사용자 질문은 같지만 후속 assistant history는 서로 다르다. 임시 API와 합성 DB/인증/사용량으로 격리했고 모델은 Mac mini의 운영 MLX 게이트웨이를 사용했다. 실제 앱의 전체 UI 지연 측정은 아니다.

| 측정 | 기존 | 첫 수정안 |
|---|---:|---:|
| 턴 | 30 | 30 |
| 요청 오류 | 0 | 0 |
| 평균 | 8.76초 | 10.30초 |
| 중앙값 | 7.85초 | 7.71초 |
| 도구가 실행된 턴 | 2 | 5 |

첫 수정안은 평균 속도가 개선되지 않았다. 어머니 이름/취향 대화에서 Jev가 read로 분류해 여러 모델 호출과 조회가 발생했다. 저신뢰 취미 질문의 고정 확인 문장은 사라졌고, 쉬는 조건/주제 전환/단리·복리 설명은 개선된 사례가 있었다. 그러나 존댓말 섞임, 없는 화면 모드 이름 생성, 단순 동의를 반복하는 문제가 남았다. HTTP 성공을 대화 품질 성공으로 집계하지 않았다.

이 60턴은 **캐릭터 정체성과 conversation_context 보완 전 버전**이다. 최종 코드 전체의 벤치마크로 인용하면 안 된다. 최종 변경은 아래 별도 검사를 참조한다. 케이스는 공개된 회귀 데이터이며 미노출 평가셋이 아니다.

## 코드 검증

API 전체 테스트, 분류 API의 인증·상한·오류 fallback·도구 차단·실제 이름·종별 시스템 프롬프트·잘못된 종 입력 거절 테스트, 공용 Decision/DecisionDual/Target/Agent 테스트, 데스크톱 타입 검사·빌드 통과. 캐릭터를 연속 전환해도 요청별 종을 전달하는 공용 코어 테스트를 추가했다.

모바일은 소스 연결만 했다. 로컬에 Expo/React Native 의존성이 없어 타입 검사 실패(모듈 누락과 JSX 설정 연쇄 오류); 모바일 빌드·기기 설치 검증은 완료하지 않았다. `graphify update .`는 실행기가 참조하는 Python 3.12가 없어 실패했다. 관련 로그는 함께 보관한다.

## 남은 한계

프롬프트 수정만으로 모든 맥락·말투·사실 정확성을 보장하지 않는다. 최근 대화 보호 규칙은 제한된 인물/명시적 회상 표현에만 적용하며 장기 기억 기능이 아니다. 캐릭터 자기소개 보호 경로는 이전의 잘못된 캐릭터 답변이 재주입되지 않도록 과거 메시지를 모델 입력에서 제외하는 기존 동작을 유지한다. 상세한 과거 설정을 다시 묻는 경우 추가 개선 여지가 있다. 모델 처리 시간은 동시 사용자/운영 부하에 영향을 받는다.

## 최종 보완 검사

- `personas.jsonl`: 같은 별명 ‘모모’, 같은 4개 질문 × 4종 = 16턴. 요청 오류 0, 도구 실행 0, 평균 7.92초. 4종 모두 자신에게 설정한 취미를 소개하고 후속 설명/회상에서도 유지했다. 반말도 유지했다. 달팽이의 공감 답변에 가벼운 쉬기 제안이 남아 있어 ‘해결책 없이 듣기’는 엄격한 만점으로 보지 않는다.
- `memory-v2.jsonl`: 최근 대화 이름·취향 5턴 재검사. ‘지연’과 무서운 영화 기피를 정확히 이어 받았으며 도구 실행 0, 평균 7.88초. 존댓말과 불필요한 되묻기는 남았다. 이 검사는 종 미지정 새싹 기본 경로이며 종별 검사와 구분한다.
- 총 81턴의 합성 실모델 요청(첫 비교 60 + 캐릭터 16 + 기억 재검사 5). 전체를 동일 버전 정확도·속도 수치로 합치지 않는다.

앱 시작 직후 다른 structured AI 작업이 먼저 처리되면서 대기가 있었다. 그중 JSONDecodeError 한 건도 로그에 나타났다. 모델 재로딩은 아니며, 이번 캐릭터 프롬프트 변경으로 모든 앱 시작 지연이나 다른 AI 기능의 JSON 생성을 해결한 것은 아니다. 초기 자동 입력 도구가 한글을 누락해 공백/물음표를 보낸 턴은 정식 질문 결과에서 제외했다. 이후 붙여넣은 한글 입력을 화면에서 확인한 뒤 전송했다.
