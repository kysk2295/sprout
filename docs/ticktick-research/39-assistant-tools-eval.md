# 실측: Mac mini qwen3.5:9b 도구 호출 — AI 비서 B안 가능성 (2026-10-09)

- 목적: [47 AI 비서 B안](../screens/47-assistant-free-chat.md)(자유 대화 + 앱 도구)을 **지금 모델 그대로** 할 수 있는지, 어디서 틀리는지, 얼마나 걸리는지. 틱틱 조사가 아니라 꿈틀 자체 실측이라 이 폴더 번호만 이어 쓴다.
- 결론 한 줄: **된다, 단 "모델 혼자"는 안 된다.** 읽기 질문은 도구를 잘 고르고(인자 정확 86%), 날짜표·label·재촉 한 번을 더하면 데이터 질문 8/8. 하지만 **쓰기 도구(`propose_*`)는 15번 중 한 번도 부르지 않았다** → 쓰기·확인·상대 날짜는 앱 길잡이가 먼저 푼다(47 §2.2). 한 턴 지연은 도구 없는 답 중앙 약 10–12초, 도구 한 번 쓰는 답 중앙 약 26–30초(부하 있는 Mac mini).

## 5. 길잡이(정해진 규칙) 따로 실측 — 빠른 입력 인식기 재사용
`packages/schema/src/recognition.ts`의 `recognize()`(빠른 입력 날짜 인식)를 그대로 써서 쓰기 말을 풀어 봤다(모델 없음, 0초).
| 말 | 그대로 | `시에`·`시로` 조사 걷은 뒤 |
|---|---|---|
| 내일 3시에 교수님 면담 잡아줘 | 제목 "3시에 교수님 면담", 10/10 날짜만 | 제목 "교수님 면담", **10/10 03:00** ← 오전으로 읽음 |
| 다음 주 토요일 오후 2시로 미용실 예약 잡아줘 | 제목에 "오후 2시로" 남음, 10/17 | "미용실 예약" 10/17 14:00 ✓ |
| 내일 오후 3시 기획 회의 한 시간 등록해 줘 | "기획 회의 한 시간" 10/10 15:00 (길이 못 읽음) | 같음 |

- 그래서 길잡이 = `recognize()` + ① 끝 말(`잡아줘·넣어줘·추가해줘·등록해줘`) 떼기 ② 시각 뒤 조사(`에·로·부터`) 걷기 ③ **오전/오후 없는 1–7시는 오후**로(확인 카드 `언제` 줄에 그대로 보여 고칠 수 있음) ④ `M월 D일` 절대 날짜 ⑤ `한 시간·30분·~까지` 길이. 그래도 못 풀면 13의 의도 JSON(create) 한 번 호출 → 확인 카드(13 검증 그대로). 5개 다 2단계 시험 대상.

## 6. 47에 반영한 것
1. 쓰기는 모델 도구 호출에 기대지 않는다 — 길잡이 → (못 풀면) 13 의도 JSON → **확인 카드**(47 §2.2·§6, 결정 ④).
2. 지시문 = v2(날짜표·label·글자 그대로·반말·이모지 금지), 데이터 질문에 도구가 없으면 재촉 한 번(v3).
3. 근거 검사 6가지(날짜·따옴표 제목·숫자·저장 말·도구 없이 없다고 함·별칭 id/한자)(47 §8.2).
4. 도구 결과에 앱이 날짜 label·정렬(`urgent`)·간격 평균을 넣어 모델이 계산하지 않게(47 §3.3).
5. `num_ctx` 6144, 턴 단위 상한·이어 받기 줄 맨 앞(47 §9) — 도구 턴은 호출 2–3번이라 호출마다 세면 하루 100이 30턴 안팎.
6. 지연 목표: 길잡이로 푼 질문(호출 1번) 중앙 ≤ 15초, 일반 질문 ≤ 12초, 도구 턴 p90 ≤ 40초 — 지금 Mac mini 부하에서의 실측 그대로(47 §16). 줄이려면 지시문·도구 설명을 더 짧게(2.2k → 1.5k 목표) [다음].

## 7. 남은 것
- 서버 프록시 경로(`/ai/assistant` + 대기열)를 지나서 다시 재기(지금은 Ollama 직접). 워커 방식(Railway → Mac mini)이면 호출마다 왕복이 더해진다.
- 2명 이상 동시에 쓸 때(대기열 + 턴 이어 받기) 지연.
- 같은 문항을 길잡이 + 근거 검사까지 붙인 앱 경로로 다시 — 47 §16 "20/22 이상" 기준.
- 더 작은 지시문(도구 설명 영어로 줄이기 등)과 `num_ctx 6144`의 메모리·속도.
