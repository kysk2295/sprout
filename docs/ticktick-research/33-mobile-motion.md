# 틱틱 조사: 모바일 움직임 · 작은 반응 (iOS 우선, Android 차이)

- 조사일: 2026-10-05. [research 20](20-mobile.md)(기능) · [24](24-mobile-ui.md)(모양)에 이어 **움직임(애니메이션)·흔들림(햅틱)·제스처 세부**를 모았다. 명세는 [39 모바일 움직임](../screens/39-mobile-motion.md).
- 계기: 사용자 "모바일은 데탑이랑 다르게 UI/UX 디테일이 부족해. 애니메이션도 자연스럽지 않아."
- 표기
  - **[확인]** 틱틱 공식 도움말·블로그·캡처에서 직접 봄
  - **[추정]** 2차 출처(리뷰·검색 요약)나 일반 사용 관찰, 또는 앞선 조사의 [추정]
  - **[iOS 기본]** 틱틱 수치를 알 수 없어 iOS(UIKit·SwiftUI·HIG) 기본 동작으로 채운 값. 틱틱 iOS는 대부분 시스템 부품(시트·새로 고침·메뉴)을 쓰는 것으로 보여 이 값이 가장 가깝다 [추정]
  - **[미확인]** 근거를 찾지 못함 → 실기기(사용자 휴대폰, `sprout UI 조사` 리스트만) 화면 녹화로 확인
- **수치(ms)는 틱틱 것이 하나도 공개되어 있지 않다.** 아래 숫자는 모두 [iOS 기본] 또는 [추정]이다.

## 2. 행 스와이프
| 항목 | 내용 | 표기 |
|---|---|---|
| 기본값 | 오른쪽으로 밀기 = 완료(초록)·고정(노랑), 왼쪽으로 밀기 = 이동(파랑)·삭제(빨강)·날짜(주황). 칸은 아이콘만 | [확인] research 20 §3 · 24 §4 |
| 짧게 / 길게 | 짧게 오른쪽 · 길게 오른쪽 · 짧게 왼쪽 · 길게 왼쪽 4칸에 동작(없음·완료·마감일·우선순위·이동·삭제)을 고른다 → **"길게 밀기 = 놓으면 바로 실행"**이 있다는 뜻 | [확인] 블로그 2016 |
| 칸 드러남 | 행이 손가락을 따라 움직이고 뒤의 칸이 드러남. 칸 폭 약 60 | 따라감 [iOS 기본] · 폭 [임시] research 24 §14 |
| 짧게 → 열림 | 칸 폭의 절반 남짓 넘기고 놓으면 열린 채 멈춤, 아니면 닫힘. **빠르게 튕기면(속도) 짧게 밀어도 열림** | [iOS 기본] UITableView 스와이프 동작 |
| 길게(끝까지) | 행 폭의 약 절반~60%를 넘기면 첫 칸이 행 전체로 늘어나며(색이 꽉 참) "놓으면 실행" 상태. 넘는 순간 한 번 흔들림, 되돌아가면 다시 한 번 | [iOS 기본] UIKit `performsFirstActionWithFullSwipe` · 비율 [추정] |
| 실행 뒤 | 완료 = 행이 화면 밖으로 밀려 나간 뒤 접힘. 삭제 = 같은 방식 + 되돌리기 토스트 | [iOS 기본] · 틱틱 [미확인] |
| 다른 행 | 한 번에 한 행만 열림. 스크롤하거나 다른 곳을 누르면 닫힘 | [iOS 기본] |
| 반복 할 일 | 왼쪽 밀기 날짜 칸 → 날짜 창에 "이번 회차 건너뛰기" | [확인] FAQ |
| 서랍 리스트·태그 행 | 왼쪽으로 밀면 고정·편집·삭제 칸 3개 | [확인] 도움말 Lists·Tags |

## 9. 흔들림(햅틱) 지도
틱틱은 흔들림을 문서에 적지 않는다. 아래는 **iOS 시스템 부품이 스스로 내는 흔들림**(틱틱이 시스템 부품을 쓰면 그대로 나는 것)과 HIG 권장이다.
| 순간 | iOS 종류 | 근거 |
|---|---|---|
| 휠·세그먼트·피커 값 바뀜 | 선택(selection) | [iOS 기본] UIPickerView·UISegmentedControl |
| 길게 눌러 메뉴/끌기 시작 | 중간 충격(impact medium)에 가까운 한 번 | [iOS 기본] UIContextMenu |
| 끌기 중 자리 넘어감 | 선택 | [iOS 기본] |
| 끌기 놓음 | 가벼운 충격(light) 또는 단단한 충격(rigid) | [iOS 기본] |
| 스와이프 끝까지 넘김 / 되돌림 | 가벼운 충격 | [iOS 기본] UITableView 전체 스와이프 |
| 당겨서 새로 고침 기준 넘김 | 가벼운 충격 | [iOS 기본] UIRefreshControl |
| 할 일 완료 | 가벼운 충격 | [미확인] 틱틱 · iOS 관례 |
| 성공(저장·레벨업) | 알림 성공(notification success) | [iOS 기본] HIG |
| 지울 수 없는 동작 확인 | 알림 경고(warning) | [iOS 기본] HIG |
| 규칙: 같은 동작엔 같은 흔들림, 모든 누름에 넣지 않음, 눈에 보이는 변화와 같은 순간에 | | [iOS 기본] HIG |
- Android: `HapticFeedbackConstants`(CONFIRM · REJECT · LONG_PRESS · SEGMENT_TICK · GESTURE_THRESHOLD_ACTIVATE)가 같은 자리. expo-haptics가 Android에서 진동기로 흉내 낸다 — 세기가 다르므로 실기기에서 조절 [추정].

## 11. sprout에 주는 영향 (명세 39로 넘김)
1. 완료: 체크 채움(약 200ms) → 잠깐 머묾 → 행 접힘 + 아래 행 미끄러짐. 머무는 시간은 [미확인] → 39 결정 필요.
2. 스와이프: 속도로 열기, 끝까지 넘김 = 첫 칸이 행 전체로 늘어남 + 가벼운 충격, 실행 뒤 행이 밀려 나간 채 접힘.
3. 길게 누르기: 그대로 떼면 메뉴, 움직이면 끌기(순서·하위). 잡을 때 중간 충격.
4. 시트: 덮개는 옅어지고 판만 올라온다(덮개가 같이 밀려 올라오면 안 됨). 튕김 없는 스프링.
5. 서랍: 목록 어디서나 오른쪽으로 밀면 손가락을 따라 열림.
6. 캘린더: 월은 위아래·좌우, 주는 손가락을 따라가는 넘김(빠르면 한 주, 천천히 끌면 날짜 단위).
7. 흔들림: §9 지도를 한 곳(공용 함수)에서만 부른다.
