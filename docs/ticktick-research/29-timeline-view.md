## 1. 어디서 켜나 [확인]
- 데스크톱: 일반 리스트·폴더·필터에서 오른쪽 위 `⋯` → `보기` → `타임라인`. 모바일도 같은 자리.
- 스마트 리스트(오늘·내일·다음 7일)는 타임라인을 **지원하지 않는다**.
- 목록 추가 창에도 보기 유형(목록/칸반/타임라인)이 있다 [관찰 — live-2026-10-03 README].
- 목록 `⋯` 메뉴 보기 아이콘 3칸(목록 · 칸반 · 타임라인) [관찰 — 18 §2, 02 명세 §목록 메뉴].
- 모바일은 V6.4 이상, 가로 화면도 된다.

## 2. 무엇을 보여 주나 [확인]
- 할 일을 **가로 시간축** 위의 막대로 놓는다. 막대 **길이 = 기간**, **위치 = 시작·끝 시각**.
- **날짜가 있는 할 일만** 축에 놓인다. 날짜 없는 할 일은 오른쪽 **"Arrange Tasks(할일 정렬)" 칸**에 모이고, 거기서 축으로 끌어 날짜를 준다(캘린더 할일 정렬 패널과 같은 이름·같은 동작 — 06 §9).
- 반복 할 일의 **모든 회차는 보이지 않는다**(지금 회차만).
- 막대 색: `⋯` → 보기 옵션에서 **리스트 · 태그 · 우선순위** 색 중 고른다(캘린더 보기 옵션과 같다).
- 줄(행) 묶기: 도움말의 쓰임새 예시가 "프로젝트 리스트 안에 팀마다 **섹션**을 만들고 타임라인을 켜면 팀별 진행이 보인다", "월·일 할 일을 다른 섹션에 두면…"이라고 한다 → **리스트 안에서는 섹션별로 줄이 묶인다**고 읽힌다. 폴더·필터에서 무엇으로 묶이는지(리스트별?)와 그룹 메뉴(그룹·정렬 08)가 타임라인에도 있는지는 **[미확인]**.
- 하위 태스크도 축 위에서 자유롭게 끌 수 있다(Multilevel Tasks FAQ). 부모-자식이 줄로 묶이는지·들여쓰기되는지는 **[미확인]**.
- **의존(선행) 화살표는 없다.** 도움말 어디에도 dependency·화살표·선행 개념이 없다(전 문서 검색, 2026-10-05). "간트보다 가볍다"고 스스로 소개한다 → 우리 `map_links` 순서 화살표는 **[sprout]** 추가.
- 오늘 표시선·주말 음영·완료 막대 모양: **[미확인]**.

## 3. 보는 조작 [확인]
| 동작 | 데스크톱 | 모바일 |
|---|---|---|
| 축 옮기기 | 마우스를 누른 채 좌우로 끌기(빈 곳) | 좌우로 밀기 |
| 배율 | 오른쪽 위 `일 · 주 · 월` | 같은 버튼 + 두 손가락 오므리기·벌리기 |
| 범위 | 몇 주~몇 달을 이어서 본다 | 같다 |
- 캘린더 쪽 타임라인은 ⌘/Ctrl + 휠로 확대, ⇧ + 휠로 가로 이동을 지원한다(Desktop Interaction Tips). **리스트 타임라인에도 같은지는 [미확인]** — 같게 두는 것을 [임시]로 제안.
- `오늘` 버튼 여부 **[미확인]**(캘린더에는 있다).

## 4. 고치는 조작 [확인]
| 동작 | 결과 |
|---|---|
| 빈 곳 클릭(모바일: 길게 누르기) | 그 날짜로 새 할 일. 예: 4월 2일 칸을 누르면 4월 2일 할 일 |
| 막대 가장자리 끌기(모바일: 길게 누른 뒤 가장자리) | 기간(시작 또는 끝) 바꾸기 — "선택 → 시간 설정 → 끝 시각 → 날짜 → 저장" 다섯 단계를 두 단계로 줄였다고 소개 |
| 막대 잡고 끌기 | 시작·끝을 함께 옮긴다. 놓은 자리에 맞춰 **시각까지** 맞춰진다 |
| 할일 정렬 칸 → 축으로 끌기 | 날짜(·시각) 주기 |
- 막대 클릭·우클릭·더블클릭·키보드 조작은 도움말에 없다 **[미확인]** → 다른 보기(02 목록·06 캘린더)와 같게 두는 것을 [임시]로 제안(클릭 = 상세, 우클릭 = 02 §9 태스크 메뉴).

## 5. 쓰임새 (도움말이 권하는 것)
- 개인 업무: 폴더 "업무" 아래 리스트를 나누고, 월간·일간 일을 섹션으로 나눠 타임라인으로 본다.
- 복잡한 프로젝트: 팀마다 섹션 → 팀별 진행 보기.
- 생활 계획: 한 달 계획, 결혼·이사 준비 등 몇 주~몇 달짜리.

## 6. 참고: 틱틱 AI 비서의 "큰 일 쪼개기" [확인 — AI Assistant 도움말]
- 틱틱 AI 비서(맥·웹)는 "목표를 세우고 → 실행할 할 일로 쪼개고 → 일정을 잡고 → 돌아보기"를 돕는다고 소개한다.
- 예시 프롬프트들이 공통으로 **"먼저 결과와 제안을 보여 주고, 내가 확인하기 전에는 바꾸지 마라"**로 끝난다 → 미리 보기 → 승인 흐름은 틱틱 방식과 같다.
- 목표 쪼개기 예시: 전체 목표 정의 → 단계 몇 개로 나누고 단계별 초점 설명 → 첫 단계를 구체 할 일·주간 계획으로 → 할 일·습관을 알맞은 시각에 배치.
- 별도 "쪼개기 버튼"이나 미리 보기 화면은 도움말에 없다(대화로만) → 우리 쪼개기 창은 **[sprout]** 설계.

## 7. sprout에 주는 결론
1. 타임라인 = 같은 할 일 데이터의 **세 번째 보기**. 새 데이터 없이 `tasks.start_at`·`due_at`·`is_all_day`로 그린다(스키마 이미 있음).
2. 꼭 같아야 할 것: `일·주·월` 배율, 빈 곳 클릭 = 그 날짜로 추가, 가장자리 = 기간, 몸통 = 옮기기(시각까지), 날짜 없는 할 일 = 오른쪽 할일 정렬 칸, 보기 옵션의 막대 색(리스트·태그·우선순위), 반복은 지금 회차만.
3. 틱틱에 없는 것(= [sprout]): 순서 화살표(`map_links`), 지금 할 수 있는 일 강조, 목표로 묶기.
4. 실측이 필요한 것(사용자 틱틱 `sprout UI 조사` 리스트에서만, 끝나면 보기 원래대로): 열 폭·막대 높이·줄 머리 폭, 오늘선, 완료 막대 모양, 폴더에서의 줄 묶기, 하위 태스크 표시, 막대 우클릭 메뉴, 키보드.
